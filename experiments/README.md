# 실험 실행 기록

## M1 파일럿: 기능 연결과 실패 탐색

재현 명령:

```powershell
uv run python scripts/prepare_pilot.py
uv run python scripts/validate_splits.py data/manifests/kubernetes-pilot.json data/evaluation/pilot-smoke.jsonl
uv run python -m scripts.evaluate_pilot --output experiments/results/my-new-run.json
```

평가 결과 파일은 덮어쓰지 않는다. `prepare_pilot`은 고정 원문 SHA-256을 확인하고, 평가 실행기는 실제 가공 입력이 그 원문을 현재 정제기로 처리한 결과와 같은지 다시 검사한다. 보고서에는 코드·질문·manifest·실제 가공 본문·서버에 적재된 본문의 해시를 넣는다. 서비스 모델 API 호출은 없다.

기준 실행은 [m1-bm25-verified.json](results/m1-bm25-verified.json)이다. 실행 코드 커밋은 `357be1a`이며, 당시 결과·설명 문서를 정리 중이어서 `git_dirty=true`다. 코드와 데이터의 실제 해시를 보고서에서 확인할 수 있다. [초기 진단 실행](results/m1-bm25-smoke.json)은 평가 입력 검증을 보강하기 전 개발 과정의 결과다. 초기 보고서에는 실제 가공 입력 해시가 빠져 있으므로 기준 비교에 사용하지 않는다.

기준 실행에 기록된 모든 코드·manifest·질문 해시가 `357be1a`의 Git blob과 일치함을 추가 확인했다. 이후 Git 텍스트 파일의 줄바꿈을 LF로 통일했으므로 과거 실행의 바이트 단위 재현은 보고서에 기록된 해당 커밋을 기준으로 한다. 결과를 좋게 보이게 하려고 과거 수치를 덮어쓰지 않는다.

| 항목 | 실제 관찰 | 해석 범위 |
| --- | --- | --- |
| 공개 문서 | 8개, 4개 주제의 한·영 쌍 | 작고 번역 중복이 많은 smoke corpus |
| 질문 | AI 작성 12개, 사용자 검수 0개 | 최종 평가셋 아님 |
| 답이 있는 질문의 문서 Hit@5 / MRR@10 | 1.0 / 1.0 | top-10 청크에서 문서를 중복 제거한 순위, 10문항 |
| 주석으로 지정한 근거 Hit@5 | 10/10 | top-5 청크가 해당 근거 문자열을 포함하는지 검사 |
| 원문 오프셋 일치 | 반환된 모든 구절 일치 | 의미상 정답이라는 판단과 다름 |

정답이 있는 문서 4주제를 명시적으로 묻는 작은 질문들에서 잘 찾는 것은 기능 연결 확인에 가깝다. 실제 검색 정확도 100%, 사람 검수 완료, 생성 답변 정확도, 미세조정 성과로 표현하지 않는다.

## 확인한 실패와 개선 순서

1. **없어야 할 답의 검색 결과:** 회사 휴가 정책·식대 질문은 코퍼스에 근거가 없지만 일부 어휘가 겹쳐 결과를 반환했다. BM25 양수 점수는 답변 가능성의 증거가 아니다. 이 결과를 숨기지 않으며, 생성 단계에서 별도 근거 충분성·보류 평가가 필요하다.
2. **정제 시 의미 손실:** v1은 Hugo 툴팁 태그 안의 표시 문구까지 삭제했다. v2에서 표시 문구를 보존하고 회귀 테스트를 추가했다. 외부 포함 정의는 아직 완전히 복원하지 못해 manifest 파생 정보에 남긴다.
3. **평가 입력 드리프트:** 가공 파일을 임의로 수정해도 같은 corpus로 소개할 수 있던 결함을 원문 체크섬·재정제 결과 비교로 막았다. 손상 입력 거부 테스트를 추가했다.
4. **근거의 분할 누락:** 정답 문서 ID 외에 근거 annotation의 문서 ID도 분할 검증에 넣었다. 이 검증이 통과해도 의미상 유사 문서를 자동으로 찾아 그룹화했다는 뜻은 아니다.

M1 이후 데이터 품질·분할·질문 검수를 확대하는 M2를 아래와 같이 수행했다. 임베딩·하이브리드·리랭킹·학습의 결과는 아직 없다.

### 실제 결과

기준선은 1,000 codepoint 청크·150 겹침, ASCII 단어+한국어 bigram, BM25 k1=1.5/b=0.75이다. 313문서에서 3,588청크를 만들었다. 양성 59질문을 문서/근거 지표의 분모로 쓴다. 전체 79개에는 근거 없음 12개와 조건 불명확 8개도 포함된다.

| 지표 | 실측 | 해석 |
|---|---:|---|
| 문서 Hit@5 within top-10 chunks | 35/59 (59.32%) | 10청크에서 중복 제거한 첫 5문서에 직접 근거 문서 하나 이상 |
| 문서 Recall@5 within top-10 chunks | 45.48% | 알려진 관련 문서 집합 회수 평균; 정답 번역 대안 수에 영향받음 |
| 문서 reciprocal rank within top-10 chunks | 0.5353 | 전체 문서 순위의 MRR@10이 아님 |
| 근거 하나 이상 @5 chunks | 32/59 (54.24%) | 필수 사실 그룹 하나 이상 |
| 모든 필수 근거 @5 chunks | 30/59 (50.85%) | 각 그룹의 대체 span 중 하나가 한 청크에 완전 포함 |
| 단일 문서 / 다중 문서의 모든 근거 | 29/52 / 1/7 | 다중 문서 소표본; 답변 생성 정확도 아님 |
| 한국어 / 영어 양성의 모든 근거 | 14/39 / 16/20 | 언어별 주제·난이도가 같지 않아 언어의 인과 효과로 해석하지 않음 |
| 주석상 교차 언어만 가능한 질문 | 1/23 (4.35%) | 근거 annotation 언어 기준; 번역 동등성 전수 확인 아님 |
| 근거 없음 후보의 빈 결과 | 0/12 | 모두 어휘 일치 결과 반환; 보류 정확도 아님 |
| 원문 오프셋 일치 | 검사 결과 모두 일치 | 문자열 무결성; 의미적 정답을 보증하지 않음 |

M1 10양성 질문의 높은 점수와 직접 비교하지 않는다. 문서와 질문이 달라진 것이며 모델 개선/퇴보의 실험이 아니다. 관련 문서를 완전히 라벨하지 않았기 때문에 미라벨 결과가 실제로 충분할 가능성도 남아 있다.

### 지연·비용·실패

오프라인 순위 계산 79건의 p50/p95는 **211.628/223.042ms**였다. 토큰화는 포함하지만 HTTP·SQL·권한 검사를 포함하지 않는다.

실제 loopback HTTP에서는 별도 임시 SQLite에 인증된 업로드 313건(총 6,220.137ms)을 수행했다. 카테고리·언어별 ID 순 첫 2질문씩 총 16개, 워밍업 2회 후 각 2회, **동시성 1·32요청**을 측정했다. 32성공/0실패, HTTP p50/p95는 **255.991/385.146ms**, 서버 검색 구간은 **244.050/371.030ms**였다. 순위 계산 함수와 반환 순위가 일치했고 원문 오프셋도 일치했다. DB 본체 12,283,904 bytes, WAL 32,992 bytes, SHM 32,768 bytes였다. 원문 질문·비밀번호가 서버 운영 로그에 없는 것을 해당 실행 입력으로 검사했다.

서버 검색 구간은 인증 의존성 시간을 포함하지 않는다. HTTP는 인증·SQL·직렬화·로컬 왕복을 포함하나 화면 렌더링·인터넷·TLS는 제외한다. OS 캐시·전원·백그라운드 부하는 통제하지 않았다. 최고 메모리 사용량은 미측정이며 32건 p95는 소수의 느린 요청에 민감하다. 부하 시험·운영 SLO 충족이라고 쓰지 않는다.

첫 HTTP 실행은 검색 이후 임시 DB 삭제에서 Windows WinError 32가 났다. 프로세스 종료 후 잠금 주체를 확인하지 못했고 해당 성능 보고서는 남지 않았다. 임시 경로 경계 확인·PermissionError 제한 재시도와 영구 오류 테스트를 추가해 재실행했다. 성공 수치만 남기기 위해 실패 이력을 삭제하지 않았다.

서비스의 외부 모델 API 요청 **0건 / $0**다. 로컬 전력·장비 감가·개발 AI 구독 비용 배분은 미측정이므로 총비용 0원이라고 하지 않는다.

### 실패 진단과 다음 비교

진단은 알려진 주석과 현재 청크로 관찰한 상태이며 원인을 개입 실험으로 증명한 분류가 아니다. 우선순위 분류이므로 다른 실패가 동시에 있을 수 있다.

| 분류 | 질문 수 | 다음 확인 |
|---|---:|---|
| 모든 주석 근거 찾음 | 30 | 사람이 근거 충분성 확인 |
| 필수 근거 문서가 top-10 청크에 없음 | 24 | 다국어 임베딩·혼합의 후보 회수 비교 |
| 후보 문서는 있지만 top-5에 필요한 span 없음 | 2 | m2-dev-003, 040; 청크 순위·후보 수 확인 |
| 필수 span을 온전히 담을 현재 청크가 없음 | 3 | m2-dev-011, 030, 032; 별도 청크 설정 실험 |
| 답변 불가 후보에 대한 검색 결과 | 20 | 검색 결과 유무와 보류 판단을 분리 |

`m2-dev-011`은 영어 정답 문서가 후보에 없으면서 span 경계 문제도 있다. `m2-dev-040`은 `/metrics` RBAC 문서를 찾았으나 필요한 규칙 구간을 놓쳤다. `m2-dev-060`은 여러 문서의 모든 필수 근거를 찾은 사례다. 질문과 기준선은 보존하고 변경은 별도 설정·새 보고서로 남긴다. M3의 첫 비교에서는 코퍼스·질문·청크를 고정해 임베딩 효과를 보고, 청크 실험은 별도로 진행한다. 이후 라벨 변경이 필요하면 이전 버전의 결과도 보존한다.

### 재현 명령

먼저 [데이터 실행법](../data/README.md)의 수집·질문 컴파일·리비전·검사를 수행한다. 아래 출력은 예시 새 파일명이며 기존 파일을 덮어쓰지 않는다. 평가기는 `--split test`를 거부한다.

```powershell
uv run python -m scripts.evaluate_dataset --manifest data/manifests/kubernetes-v1.json --questions data/evaluation/m2-dev-v1.1.jsonl --output experiments/results/my-m2-bm25-dev.json
uv run python -m scripts.analyze_failures --manifest data/manifests/kubernetes-v1.json --questions data/evaluation/m2-dev-v1.1.jsonl --report experiments/results/my-m2-bm25-dev.json --output experiments/results/my-m2-failures.json
uv run python -m scripts.benchmark_api --manifest data/manifests/kubernetes-v1.json --questions data/evaluation/m2-dev-v1.1.jsonl --output experiments/results/my-m2-http.json
```

고정 입력·검색 순위 지표는 재현 대상으로 삼지만 지연시간은 실행 환경에 따라 달라진다. 현재 소스에 분석 도구가 추가되었으므로 새 실행의 전체 코드 해시는 과거 보고서와 다를 수 있다. 과거 코드 바이트 재현은 보고서의 실행 커밋을 사용한다.

임베딩·혼합 검색은 이 설정에서 개선되지 않았다. 리랭커까지 적용하면 BM25 대비 7질문 개선·1질문 퇴보(순증6, +10.17%p)했다. 같은 H50의 단순 RRF 대비로는 9질문 개선·0퇴보다. 이것은 알려진 AI 주석을 회수한 결과이며 검증된 답변 정확도나 통계적 일반화 주장이 아니다. 다중 문서는 BM25/E5/리랭커 모두 1/7, 기본 RRF는0/7로 여전히 약했다.

단계 시간은 따로 측정한 값의 합계이며 실제 상주 서비스 요청 시간이나 HTTP가 아니다. 문서 임베딩 준비45.08초, E5 로드8.84초, 리랭커 로드5.50초는 질의 시간에서 제외했다. CUDA 동기화·batch·단일 순회·warmup과 실제 수치를 보고서에 남겼다. 캐시·전원·배경 부하가 달라 M2 HTTP나 이전 오프라인 시간과 직접 비교하지 않는다.

GPU allocator allocated/reserved peak는 E5 문서 준비794/1,808MiB, 리랭커 질의1,123/1,138MiB였다. CPU RSS의50ms 샘플 peak는 리랭커 로드 단계4,353MiB였다. 전체 GPU나 동시에 두 모델을 띄운 서비스의 최대 사용량이 아니다. RTX4050 6GB에서 순차 실행을 실제 완료했고 OOM·CPU/BM25 fallback은 없었다.

E5 문서38/3,588(1.06%), BGE query-passage803/3,950(20.33%)가512토큰 한도를 넘어 잘렸다. 질문 자체는 잘리지 않았다. 해당 입력 ID·길이를 보존했지만 잘린 뒤 모델에 보인 정확한 근거 span coverage는 측정하지 않았다. 현재 근거 점수는 반환된 전체 원문 청크 기준이다. 근거 없음 후보12개는 모든 방법에서 결과가 있었고 답변 보류는 구현하지 않았다.

다음 판단: BM25 기본 경로는 유지한다. 모델을 추가한 방식의 선택 기능·실제 HTTP·권한·문서 변경·벡터 캐시를 연결한 뒤 M3 서비스 통합 완료를 판단한다. 후보에 없는 근거, RRF 후보 축소로 잃은 근거, 최종top5의 중복 사실, 토큰 잘림을 나눠 후속 실험을 정한다. 리랭커 학습만으로 모든 실패가 해결된다고 가정하지 않는다.

외부 모델 API 요청0·유료 GPU 임대0이며 전력·장비·개발 보조 사용료는 미측정이다. 로컬129테스트·Ruff·프런트엔드 타입 검사/build를 통과했지만 테스트 통과를 모델 품질 증거로 대체하지 않는다. 기본 CI의2개 선택적 tensor/NumPy 검사 skip과 실제 로컬 GPU 실행을 구분한다.
