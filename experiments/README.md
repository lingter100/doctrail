# 실험 실행 기록

## M1 파일럿: 기능 연결과 실패 탐색

재현 명령:

```powershell
uv run python scripts/prepare_pilot.py
uv run python scripts/validate_splits.py data/manifests/kubernetes-pilot.json data/evaluation/pilot-smoke.jsonl
uv run python -m scripts.evaluate_pilot --output experiments/results/my-new-run.json
```

평가 결과 파일은 덮어쓰지 않는다. `prepare_pilot`은 고정 원문 SHA-256을 확인하고, 평가 실행기는 실제 가공 입력이 그 원문을 현재 정제기로 처리한 결과와 같은지 다시 검사한다. 보고서에는 코드·질문·manifest·실제 가공 본문·서버에 적재된 본문의 해시를 넣는다. 서비스 모델 API 호출은 없다.

기준 실행은 [m1-bm25-verified.json](results/m1-bm25-verified.json)이다. 실행 코드 커밋은 `357be1a`이며, 당시 결과·설명 문서를 정리 중이어서 `git_dirty=true`다. 코드와 데이터의 실제 해시를 보고서에서 확인할 수 있다. [초기 진단 실행](results/m1-bm25-smoke.json)은 평가 입력 검증을 보강하기 전 개발 과정의 결과다. 초기 보고서에는 실제 가공 입력 해시가 빠져 있으므로 기준 비교에 사용하지 않는다.

기준 실행에 기록된 모든 코드·manifest·질문 해시가 `357be1a`의 Git blob과 일치함을 추가 확인했다. 이후 Git 텍스트 파일의 줄바꿈을 LF로 통일했으므로 과거 실행의 바이트 단위 재현은 보고서에 기록된 해당 커밋을 기준으로 한다. 결과를 좋게 보이게 하려고 과거 수치를 덮어쓰지 않는다.

| 항목 | 실제 관찰 | 해석 범위 |
| --- | --- | --- |
| 공개 문서 | 8개, 4개 주제의 한·영 쌍 | 작고 번역 중복이 많은 smoke corpus |
| 질문 | AI 작성 12개, 사용자 검수 0개 | 최종 평가셋 아님 |
| 답이 있는 질문의 문서 Hit@5 / MRR@10 | 1.0 / 1.0 | top-10 청크에서 문서를 중복 제거한 순위, 10문항 |
| 주석으로 지정한 근거 Hit@5 | 10/10 | top-5 청크가 해당 근거 문자열을 포함하는지 검사 |
| 원문 오프셋 일치 | 반환된 모든 구절 일치 | 의미상 정답이라는 판단과 다름 |
| 근거 없는 질문의 빈 결과 비율 | 0/2 | 두 질문 모두 관련 없는 어휘 일치 결과 반환 |
| 서버 검색 구간 p50 / p95 | 20.60ms / 22.77ms | 12건, 단일 로컬 직렬 실행. 인증 의존성·네트워크·부하 제외 |
| 외부 모델 API 요청·요금 | 0건 / $0 | 로컬 전력·장비 비용 미측정 |

정답이 있는 문서 4주제를 명시적으로 묻는 작은 질문들에서 잘 찾는 것은 기능 연결 확인에 가깝다. 실제 검색 정확도 100%, 사람 검수 완료, 생성 답변 정확도, 미세조정 성과로 표현하지 않는다.

## 확인한 실패와 개선 순서

1. **없어야 할 답의 검색 결과:** 회사 휴가 정책·식대 질문은 코퍼스에 근거가 없지만 일부 어휘가 겹쳐 결과를 반환했다. BM25 양수 점수는 답변 가능성의 증거가 아니다. 이 결과를 숨기지 않으며, 생성 단계에서 별도 근거 충분성·보류 평가가 필요하다.
2. **정제 시 의미 손실:** v1은 Hugo 툴팁 태그 안의 표시 문구까지 삭제했다. v2에서 표시 문구를 보존하고 회귀 테스트를 추가했다. 외부 포함 정의는 아직 완전히 복원하지 못해 manifest 파생 정보에 남긴다.
3. **평가 입력 드리프트:** 가공 파일을 임의로 수정해도 같은 corpus로 소개할 수 있던 결함을 원문 체크섬·재정제 결과 비교로 막았다. 손상 입력 거부 테스트를 추가했다.
4. **근거의 분할 누락:** 정답 문서 ID 외에 근거 annotation의 문서 ID도 분할 검증에 넣었다. 이 검증이 통과해도 의미상 유사 문서를 자동으로 찾아 그룹화했다는 뜻은 아니다.

다음은 데이터 품질·분할·질문 검수를 확대하는 M2다. 임베딩·하이브리드·리랭킹·학습의 결과는 아직 없다. 새로운 모델은 같은 검수된 데이터에서 비교하며 실패 질문도 함께 남긴다.
