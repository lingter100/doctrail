# C2-P0 신규 자료 비교 계획

작성일: 2026-10-14. 상태: **비교 설계와 출처 계열 메타데이터 등록만 완료. 비교 실행기·신규 질문·oracle·품질 호출·채택은 아직 없음**.

줄 단위 인용 ID를 쓰는 예산 일치 기준 `L0`와 문단·구조 블록 ID를 쓰는 `C2-P0`를 새로운 calibration 8문항에서 비교한다. C2-P0가 모든 필수 기준을 통과하고 완전 정답 개선이 관측될 때만 격리된 신규 validation 12문항으로 진행한다. 후보는 하나이며, 실패 뒤 같은 자료로 정책을 고쳐 재시도하지 않는다.

## 현재 증거와 비교의 가설

[후속 구조 제안](MEETINGS-C1-FAILURE-FOLLOWUP.md)은 정확한 인용 문자열과 주장 전체의 지지를 구분했다. C0/C1의 질문, oracle, 원본 품질 응답, 미실행 항목과 검증 pool은 이 비교에 재사용하지 않는다. 과거 D0 측정값도 새 L0 대조 결과로 계산하지 않는다.

[중립 자원 계획](MEETINGS-C2-NEUTRAL-PLAN.md)에 따른 C2 실행 결과는 부모가 `662965d`에서 확인했다고 전달했다. normal은 입력474/output27/EOS/약3.079초, stress는 입력3881/output384/length/약31.953초이며 실제 native 호출은 2회다. 해당 raw 보고서의 전달받은 SHA256은 `eb138abc5e6af97df68026b3e68c771c7e9d6c4dc974aa58865e894956b4a4d6`이다. 이 설계자는 raw 보고서를 열거나 재실행하지 않았다. 정리된 결과는 [자원 결과 문서](MEETINGS-C2-RESOURCES.md)를 따른다.

강제 stress 출력의 `length` 종료는 자원 프로토콜의 조건일 뿐 정상 답변·인용·보류 성공이 아니다. 강제 timeout은 실제 발생하지 않았으므로 확인된 것은 정상 종료와 metadata 재시작이다. timeout 뒤 생성 복구, 자연어 최대 지연, Java·React 운영 복구가 증명됐다고 하지 않는다. **자원 준비 통과는 의미 품질 게이트 통과가 아니다.**

검토할 가설은 같은 입력·모델·예산에서 문단 내부의 조건과 서술부를 한 근거 단위로 보존하면, 여러 줄 ID를 고르다가 필수 부분을 빠뜨리는 실패를 줄일 수 있다는 것이다. 넓어진 인용 자체, 자기검토, 새 모델, 검색 개선의 효과를 주장하지 않는다. 문단 간 의존과 잘못된 주장 생성은 그대로 남는 위험이다.

## 두 역할의 고정 비교 계약

| 항목 | L0 | C2-P0 |
|---|---|---|
| 근거 단위 | 기존 줄 단위 규칙: `splitlines(keepends=True)`, 긴 줄은 기존480 code point 규칙 | 동결된 `meeting_answer_blocks.py`의 문단·목록·표·코드 등 구조 블록 |
| 구조 단위 상한 | 기존 줄 분할 규칙 유지 | 단위1,024 code points, 초과 시 분할·요약 없이 사전 오류 |
| 생성 | 답변 1회 | 답변 1회 |
| 입력/출력 | 최대4,096/384 tokens | 최대4,096/384 tokens |
| 시간 | 준비·단일 생성·응답 처리 공통90초 | 준비·단일 생성·응답 처리 공통90초 |
| 출력 계약 | `answered|abstained`, 최대6개 주장, 주장당1~4개 ID | 동일 |
| 모델·runtime | 무료 로컬 Qwen3.5-9B Q5_K_M, 동일 weights/runtime hash | 동일 |
| 실행 설정 | 24 GPU layers, context6144, batch512/ubatch128, fit off, nonthinking, greedy/seed0, cache off, warmup0 | 동일 |
| 추가 호출·예시 | 자기검토·재작성·추가 예시·retry 없음 | 동일 |

L0는 새 예산 어댑터 `src/doctrail/meeting_answer_lines_bounded.py`를 이용하는 별도 비교 역할이다. 부모는 자원 결과와 이 비교 역할을 `ddae7bb`에 commit했고 Python 전체1,335개와 Ruff가 통과했다고 전달했다. 이 설계자는 해당 검사를 재실행하지 않았다. **비교 실행기는 아직 구현되지 않았으며**, 실행기 구현·관련 검사와 아래 등록 절차를 마치기 전에는 자료 작성·품질 호출로 넘어가지 않는다. 과거 동결 어댑터나 계획을 고쳐 L0를 만들지 않는다.

양쪽에는 동일한 질문과 동일한 `contexts`의 문자열·문서 ID·리비전·순서·offset·제목·회의일을 전달한다. ID 개수와 직렬화 길이는 구조 차이 때문에 달라질 수 있으며 그 차이는 측정한다. 토큰 수를 맞추려고 내용을 버리거나 채움 문장을 추가하지 않는다. prompt 차이는 단위·경계 표시를 설명하는 최소 계약 문구로 한정하고, 비교 실행 전에 정확한 diff를 등록한다. 두 역할의 근거·보류·언어 지시가 달라지면 단위 구조만의 비교라고 부를 수 없다.

같은 모델 프로세스에서 요청마다 cache를 끄고 동시성1로 실행한다. 항목 순서는 입력 전에 고정하고, 홀수 항목은 L0→C2, 짝수 항목은 C2→L0로 순서를 상쇄한다. 프로세스 시작·추가 warmup·prefill cache 차이를 숨기지 않는다. 자동 모델 fallback이나 다른 프로세스의 종료는 금지한다.

90초를 넘기거나 오류가 나면 이 실행이 소유한 native 프로세스만 정리한다. 별도의 종료 확인5초와 호출 시작부터 정리 완료까지120초 안전 경계를 유지하되, 90초 초과 응답이 성공으로 되살아나는 유예시간으로 쓰지 않는다. Java 전체 요청120초는 여전히 별도 운영 가정이다.

## 원문과 보안 경계

현재 C2 모듈의 docstring/계약은 원문을 손실 없이 보존하는 보수적 Markdown 부분집합이며 의미 완결성 판별기가 아니다. 청크 경계 flag는 전달된 context의 경계에 닿는다는 뜻이고, 문장이나 의미가 완결됐다는 증거가 아니다.

근거 단위는 **권한·리비전 검사된 단일 context 안**에만 속한다. 같은 문서라도 서로 다른 청크 좌표를 한 인용으로 합치거나 context 밖 원문을 가져와 확장하지 않는다. 모델은 ID를 고르고 어댑터는 원문과 code point 위치를 복사한다. Java의 ACL·리비전·청크 범위·원문 일치 검사를 우회하지 않는다. 새 평가가 Python 어댑터에서 통과해도 Java 서비스 성능이나 운영 정확도로 이름을 바꾸지 않는다.

응답 뒤에 근거를 넓히거나 잘못된 주장을 고치지 않는다. 다른 주장이나 context에 있는 사실을 현재 주장의 인용 지지로 빌려오지 않는다. 운영 로그에는 원문·질문을 넣지 않으며, 평가 산출물에 포함할 공개·합성 텍스트와 안전한 운영 메타데이터를 구분한다.

## 질문보다 앞서는 등록과 동결

순서의 증거는 작성일 표기만으로 대체하지 않고 commit, SHA256, 담당 역할과 생성 시각을 남긴다.

1. **출처 계열 등록:** [family registry](../data/evaluation/meetings-c2-family-registry-v1.json)를 먼저 commit한다. 최초 파일 SHA256은 `0fe710907f10dfc407997970ed176c0a657aa6d1e24a0ca95f4da07f8dd9c76c`이다. 이 파일은 메타데이터이며 질문·oracle·context가 아니다.
2. **비교 소스 동결:** C2와 L0, 새 실행기, parser·문법·prompt·오류 계약, 메트릭/스코어 schema, 실제 모델·tokenizer·runtime 식별, 본 계획과 registry를 **새 비교 계획**에 바인딩한다. 기존 자원 계획의 source28이나 C0/C1 계획에 새 파일을 소급 추가하지 않는다. 관련 Python 검사, 두 역할의 예산·원문 보존·모델 없는 토큰 준비를 통과시킨다.
3. **출처 채택:** 각 자료 작성자가 자신에게 허용된 split의 고정 source만 확인한다. 라이선스·NOTICE·출처 적합성을 검토하고 raw bytes/processed text의 SHA256, 처리 규칙, document/revision/coordinate 체계를 별도 manifest로 고정한다. validation 본문은 격리 작성자/custodian에게만 공개한다.
4. **새 문항 작성:** 두 역할의 응답을 보기 전에 질문, 고정 context 순서, 필수 사실·조건·대상·시점, 허용 대체 인용, 근거 부족 시 요구 상태, 금지 추론을 만든다. AI 작성과 자기 검토, 독립 사전 검토, 인간 검수를 각각 기록한다. 이 단계의 담당자는 기존 질문이나 model output을 복제하지 않는다.
5. **실행 전 입력 동결:** 새 calibration8과 validation12의 registry·manifest·질문·oracle·처리본 hash를 봉인한다. 양쪽 동일 입력과 공통 상한을 모델 없이 확인하고 실행 순서·익명화 seed·소유 프로세스·새 출력 경로·중단 규칙을 등록한다. 부모에게 validation의 본문이나 oracle를 보여주지 않는다.

코드 결함이나 source 적합성 문제가 문항 작성 전에 발견되면 원인을 남기고 별도 버전으로 다시 등록할 수 있다. 이미 작성된 문항을 보며 구조·source·oracle를 바꾸는 경로를 정상 준비로 포장하지 않는다. 준비 실패 항목을 빼고 분모를 줄이거나 다른 질문으로 조용히 교체하지 않는다.

## 새 출처 계열과 구성

두 split은 문단·파일 단위가 아니라 프로젝트 또는 합성 조직 단위로 분리한다. 다른 branch, 과거 revision, 번역, 근접한 바꿔쓰기 역시 같은 계열이다. 아래의 파일 경로·license·commit 메타데이터만 확인했으며 본문 적합성이나 실제 정답은 아직 확인하지 않았다.

| split | 계열 | 문항 수 | 언어 | 답변 가능/근거 부족 |
|---|---|---:|---|---:|
| calibration | C2-F01: OpenTelemetry community governance/membership | 4 | 한국어2·영어2 | 3/1 |
| calibration | C2-F02: 새 합성 실내 빙상장 운영 | 4 | 한국어2·영어2 | 3/1 |
| validation | C2-F03: Apache Arrow contributor/review/release 절차 | 6 | 한국어3·영어3 | 4/2 |
| validation | C2-F04: 새 합성 인쇄소 교정 승인·생산 인계 | 6 | 한국어3·영어3 | 4/2 |

공개 calibration source는 `open-telemetry/community`의 `df3343ccbecb84a6e25dcd9610cb9a93ad377a93`, 공개 validation source는 `apache/arrow`의 `7ee15283bc9fac8b4e523b0b4640439b547ef0ff`로 고정한다. 확인한 저장소 라이선스는 각각 [OpenTelemetry Apache-2.0](https://github.com/open-telemetry/community/blob/df3343ccbecb84a6e25dcd9610cb9a93ad377a93/LICENSE), [Arrow Apache-2.0 및 포함 라이선스](https://github.com/apache/arrow/blob/7ee15283bc9fac8b4e523b0b4640439b547ef0ff/LICENSE.txt)다. Arrow의 [NOTICE](https://github.com/apache/arrow/blob/7ee15283bc9fac8b4e523b0b4640439b547ef0ff/NOTICE.txt)도 고정한다. 저장소 SPDX 표기가 개별 파일의 예외를 없애는 것은 아니므로, 채택 전 각 작성자가 해당 파일의 고지와 재배포 조건을 확인한다. **두 공개 계열 모두 source 채택은 HOLD**다. 고정 경로·commit·저장소 license 확인과 개별 파일 사용 가능성·본문 적합성 확인을 구분하며, 후자가 끝나기 전에는 질문을 작성하지 않는다.

registry는 Kubernetes, Jupyter, Rust lang-team, archive digitization, Python PEPs, NumPy NEPs, coastal bird, chess 및 기존 M5-B의12 계열·3 예시 계열을 제외했다. 이를 확인할 때 M5-B의 family ID/topic 메타데이터만 조회했으며 validation 질문·oracle·본문은 열지 않았다. 기존 C0 known4, prepared12, C1의 시도/미시도 자료와 최종 test는 계속 잠근다.

각 계열에는 복수 조건을 함께 답해야 하는 항목, 여러 source가 필요한 항목, 질문의 일부 정보는 있어도 필수 부분이 없어 전체 보류가 필요한 항목을 포함한다. 답변 가능한 항목은 calibration에서 최소4개, validation에서 최소6개가 여러 필수 사실을 요구하도록 등록하고, 복수 source가 필요한 항목은 각각 최소2개·4개로 한다. 조건·주체·시점·제안/확정/완료 구분은 실제 source가 지지하는 범위에서 다룬다. 수를 채우려고 source에 없는 사건이나 정답을 만들지 않는다.

이 구성은 목적에 맞춰 고른 작은 공개/합성 자료이며 무작위 benchmark가 아니다. 공개 family 두 개가 서로 다른 프로젝트여도 모두 절차 문서라는 편향이 남는다. 공개 문서의 모델 사전학습 가능성, AI 작성·평가의 공통 편향, 합성 조직의 비현실성을 기록한다.

문장 줄바꿈을 인위적으로 끊거나 늘려 L0를 불리하게 만들지 않는다. 후보의 구간 크기를 알고 거기에 딱 맞는 source만 고르는 것도 금지한다. source 처리와 context 선택 규칙을 사전 등록하고 양쪽에 같은 원문을 제공한다. 블록 길이·ID 수·token 상한을 못 맞춘 입력은 준비 실패로 남기며, 내용을 잘라 조용히 통과시키지 않는다.

## 정확한 인용과 의미 지지의 별도 측정

문자 수는 Unicode code points, 위치는 문서의 반열린 구간 `[start, end)`를 사용한다. 고유 길이는 `(document_id, revision)`별 좌표 합집합이고 발생 길이는 반복·청크 중복·주장 간 재인용을 포함한다. 서로 다른 revision의 좌표는 합치지 않는다. 현재 C2 `citation_metrics` 계약의 이 구분을 L0에도 동일하게 적용한다.

| 지표 | 고정 정의 | 해석 경계 |
|---|---|---|
| exact-span | 인용이 지정 context 안에 있고 ID/원문/Unicode 위치가 정확히 일치하는 개수 / 실제 반환 인용 개수 | 원문 검색으로 다른 위치를 대신 찾아 맞추지 않음. 의미 지지와 별개 |
| 모든 주장 지지 | 답변의 각 주장에 포함된 **모든 사실**이 그 주장에 연결된 인용들의 합으로 지지되는지 | 선택하지 않은 앞뒤 문장, 다른 주장 인용, 외부 지식으로 보충하지 않음 |
| 주장별 사실 지지율 | 인용으로 지지된 최소 사실 단위 / 필수·부가 사실 전체 | 분모는 optional 예시·이유·비교도 포함. 높은 평균으로 하나의 실패를 덮지 않음 |
| 인용 정밀도 | 해당 주장에 필요한 사실/조건/해석 근거를 실제 제공하는 `주장-인용` 연결 수 / 전체 연결 수 | 한 인용이 여러 문장을 포함해도 연결 하나. 단순 주제 일치는 관련 근거로 계산하지 않음 |
| 질문 완전성 | 고정 oracle의 필수 사실·조건·관계가 모두 답변에 포함됐는지 | 글에 사실이 있다는 것과 그 인용이 지지한다는 것을 따로 보고 |
| 상태·언어·시간·대상·조건 | 고정 oracle 및 전체 제공 문맥과 일치하는지 각각 판정 | 문서일→사건일, 제안→완료, 일부 조건→무조건 적용을 허용하지 않음 |
| 근거 부족 보류 | 필수 부분이 없을 때 `abstained/insufficient_evidence`를 반환했는지 | 유용한 부분 답변도 `answered`면 실패. `error`는 보류가 아님 |

각 인용은 단독으로 주장 전체를 증명할 필요는 없다. 같은 주장에 연결된 여러 정확한 구간이 함께 주장을 지지할 수 있으며, 그중 조건이나 주체를 제공하는 구간도 필요한 기여로 인정한다. 다만 필요한 결론이 어느 선택 인용에도 없으면 실패다. oracle에 명시된 대체 근거는 인정하고, 인용 경계가 oracle 발췌 경계와 똑같아야 한다는 불필요한 요구는 하지 않는다.

넓은 단위가 주는 착시를 막기 위해 검토자는 선택 인용 안에서 실제 지지 부분의 위치를 기록한다. 인용 정밀도와 함께 source 발생/고유 길이, quote 발생/고유 길이, 주장별 quote 길이, source 대비 고유 quote 비율, 불필요 인용과 중복, 실제 지지 부분 대비 인용 폭을 보고한다. 짧은 줄 조각도 단독으로 의미가 없을 수 있으므로 원문 길이만으로 우열을 정하지 않는다. 지지 폭 수치는 주석 기준의 불확실성이 있는 보조 계측이며, 출력 확인 뒤 임의의 수치 경계로 합격 기준을 바꾸지 않는다.

완전 적합에는 정확한 모든 인용, 모든 사실의 주장 지지, 불필요한 인용 연결0, 모든 필수 항목, 요청 언어, 시간·대상·조건, 올바른 상태가 모두 필요하다. 넓어진 quote 안에서 사실을 직접 확인할 수 있어야 하며, 상반된 조건이나 취소 문장은 무시할 수 없다. 증거 단위를 크게 했다는 이유로 기존 의미 기준을 느슨하게 하지 않는다.

정상 보류에는 인용이 없을 수 있다. 이때 인용 rate는 N/A로 보고하고 올바른 보류 여부로 판단한다. 오류·미반환·잘림의 빈 인용 배열을 100% exact 또는 100% 지지로 계산하지 않는다. 오류는 전체 실패로 남기고 평가 불가 차원은 별도 표시한다.

## 익명 독립 판정과 역할 대응표

1. scorer는 구현·prompt·구조 설계·질문/oracle 작성에 참여하지 않은 새 역할이어야 한다. 작성자의 AI 자기 검토는 독립 사전 검토나 사후 독립 의미 검토로 계산하지 않는다.
2. calibration16 응답은 원래 순서와 역할 이름을 숨긴 익명 sample로 섞는다. 실제 질문, 제공 context 전체, 고정 oracle, 실제 반환 주장·선택 인용·오류는 그대로 제공한다. 모델명·L0/C2 label·원시 실행 로그·후보별 집계·이전 판정·대응표는 scorer에게 주지 않는다.
3. scorer는 각 sample의8 품질 boolean, 전체 적합, 주장별 지지/누락, 인용 정밀도와 이유를 기록한다. 집계를 보며 기준을 바꾸지 않고 **판정 파일 SHA를 먼저 잠근다**. 그 다음에만 custodian이 대응표 hash를 제공해 항목별 개선/퇴보를 연결한다.
4. 인용 길이·구조, 반복된 답변이나 오류 모양으로 역할을 추측할 수 있다. 예상한 역할과 자신감 또는 추측하지 않았음을 잠금 전에 기록하고, 완전한 blind였다고 주장하지 않는다.
5. validation은 별도의 격리 custodian이 관리한다. 부모·prompt 작성자·구조 설계자는 본문·oracle·항목별 설명을 읽지 않고 hash·완료 수·전체 게이트·추상 실패 범주만 받는다. 검토자가 custodian과 같은 역할이라면 그 한계를 명시한다.

현재 문서/registry 작성자는 C0와 C1 부분 calibration을 과거 검토했고 C2 구조·평가 설계에도 참여했다. **후속 독립 scorer 및 격리 validation 작성자로 사용할 수 없다.** 공개 validation의 프로젝트명·경로·라이선스 metadata를 이미 보았다는 사실도 남긴다.

## 호출 상한, 선택 규칙과 중단

이미 완료된 자원 normal/stress2는 재실행하지 않는다. 새 품질 실행 상한은 calibration8×2역할=16회와 선택된 C2 validation12회, 합계 **28회**다. 기존 자원2를 포함한 C2-P0 전체 등록 흐름의 상한은30회이며, 새 자원 호출·추가 자기검토·hidden warmup·retry를 더하지 않는다. 호출 전 dispatch 영수증을 저장하고, 이미 시작했거나 완료된 실행 경로를 재사용하지 않는다.

calibration 선택은 다음을 모두 만족할 때만 통과한다.

- 계획된8 문항의 두 역할16 결과와 독립 판정이 모두 존재한다. 부분 결과로 선택하지 않는다.
- C2의 완전 적합이 **8/8**이다.
- 같은 문항에서 `L0 실패→C2 성공`이 **1개 이상**, `L0 성공→C2 실패`가 **0개**다.
- 호출마다 입력≤4,096/output≤384, 실제 어댑터 처리≤90초, 단일 생성, 고정 설정을 충족한다. EOS로 정상 종료해야 하며 품질 실행의 `length`는 실패다. 중립 stress의 특별 종료 규칙을 가져오지 않는다.
- source·모델·설정·입력 hash와 비교의 동일 조건이 유지되고, source/문항 누락·조용한 fallback·출력 수리·형식 보정이 없다.

둘 다8/8이면 품질 개선은 관측되지 않았으므로 이 계획의 구조 선택 게이트를 통과하지 않는다. 작은 지연 차이나 더 넓은 인용을 사후 대체 성공 기준으로 삼지 않는다. C2가 일부 의미 실패를 내도 실행이 정상이라면 등록된 calibration 전체를 마쳐 퇴보와 보류를 함께 평가하되, 선택 게이트 실패는 바뀌지 않는다.

형식 미반환, native 오류·timeout·OOM, 잘림, 설정 불일치, source 변경, 입력 상한 위반 등 실행 무결성 문제가 생기면 중단한다. 이미 완료된 부분은 사후 분석으로 보존하고 선택 게이트는 실패다. 미실행 문항은 미실행으로 남기고, 수정한 후보로 이어 실행하지 않는다. 기준 역할의 구현 결함을 후보의 의미 향상으로 포장하지 않는다.

선택된 C2만 격리 validation12에 각1회 적용한다. **12/12 완전 적합**, 부적절한 보류0, 오류0, 근거 없는 추가 사실0, 동일 자원·무결성 조건을 요구한다. 실패 항목을 제외하거나 oracle를 바꾸지 않으며, 실패 후 같은 pool로 튜닝/재실행하지 않는다. 새 기준 역할의 validation 호출은 이 계획에 없다.

## 산출물과 종료 상태

후속 실행은 새 plan/source binding, source manifest, 입력·oracle 봉인, native dispatch 영수증, 원본 보고서, 익명 review pack, 잠긴 판정, mapping과 사후 집계를 각각 보존해야 한다. report/plan/input/oracle/reviewer/mapping SHA와 실제 호출 수·미실행 수·실패 원인·사용자 검수 수를 연결한다. 기존 자원 계획이나 실패 후보의 기록은 그대로 둔다.

이 문서 작성에서는 비교 계획과 family 메타데이터 두 파일만 추가했다. 질문·oracle·context 생성0, 품질 모델 호출0, native 실행0, 새 모델 다운로드0, 유료 사용0, 인간 검수0이다. 공개 source의 body는 읽지 않았으며 GitHub 저장소·commit·tree·경로·blob/size 및 LICENSE/NOTICE만 확인했다. 라이선스 text는 메타데이터 확인 목적으로 조회했고 질문 근거로 사용하지 않았다.

실제 도구가 수락한 이 설계 역할은 부모가 확인한 `gpt-6-astra / xhigh`다. 부모 채팅 모델과 서비스 추론 모델은 별개다. 신규 작은 품질 pool을 모두 통과하더라도 서비스 채택은 자동이 아니며, 실제 Java/React·세션·ACL·리비전·삭제·취소 회귀가 남는다. Phase1/PR14는 미완료/draft 상태를 유지한다.
