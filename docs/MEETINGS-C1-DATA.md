# C1 자료 등록과 작성 순서

2026-10-13. 현재는 [가족 등록부](../data/evaluation/meetings-c1-calibration-family-registry-v1.json)를 작성한 단계다. 새 calibration 질문·정답·검증 자료는 아직 작성하지 않았다. 질문에 앞서 출처와 구성을 고정하고, C1 코드·정책을 커밋한 뒤 별도 역할이 자료를 만든다.

## 비교 자료

calibration은 8항목이다. 답변 가능 6·근거 부족 2, 한국어 질문 4·영어 질문 4, 공개 원문 4·명시적 합성 원문 4로 구성한다. 각 출처 종류에서 한국어·영어 질문을 2개씩 작성하며 보류 필요 질문은 언어별 1개다. 총 4개 가족에서 최대 2항목씩 사용하므로 독립적인 8개 가족이라고 설명하지 않는다.

공개 자료는 Python PEP 거버넌스(PEP 1/13)와 NumPy 스칼라 설계(NEP 50/51)다. 등록부의 전체 commit ID, raw URL, SHA-256, 바이트 크기를 검증하고 자료를 저장한다. 네 문서의 개별 public-domain 선언을 확인했으며 PEP 1의 CC0 선택지도 구분한다. 저장소 소프트웨어 라이선스를 문서에 일괄 적용하지 않는다. 출처·기여자·문서별 저작권 선언을 원문과 함께 보존한다.

합성 자료는 해안 조류 조사와 체스 대회 판정의 별도 회의·관련 문서다. 실제 회의로 표시하지 않으며 AI 작성과 사용자 검수 상태를 기록한다. 이전 사례의 인명·숫자만 바꾼 자료를 만들지 않는다.

이전 M2~M4 Kubernetes 자료, Jupyter 회의/안내, M5-B 가족 등록부와 알려진 과거 가족의 메타데이터를 대조했다. 잠긴 질문·정답을 읽어 전수 의미 중복 검사를 했다는 주장은 하지 않는다. 현재는 제한된 가족 수준의 대조이며 출처별 세부 근거는 등록부의 `overlap_review`에 남겼다.

## 코드 동결 뒤 할 일

1. 등록된 원문의 고정 바이트를 받아 hash와 문서별 이용 조건을 다시 확인한다. 필요한 완전한 문단과 제목 문맥을 선택하고 raw 원문 위치와 처리 결과를 연결한다.
2. 모든 질문에 대한 필수 사실·허용 대체 인용·금지 추론·답변 가능성·언어를 모델 실행 전에 기록한다. 질문·정답은 모델 호출 입력과 분리한다.
3. 프롬프트 구현에 참여하지 않은 별도 AI 검토자가 명확성·근거·완전성을 사전 검토한다. 수정은 추론 전에만 하며 원문을 정답에 맞게 바꾸지 않는다. AI 작성·AI 검토·사용자 검수 수를 따로 센다.
4. 준비 파일·문항 순서·원문/정답 hash를 고정한 실행 계획을 만든다. 입력 전체와 후속 검토/수정의 추가 공간이 한도에 들어가는지 확인하되 본문을 몰래 줄이지 않는다.
5. 중립 protocol 확인 2개와 calibration 8개를 각각 한 번 실행한다. 정확한 인용과 의미 정답을 별도로 평가한다. 기준 답변은 C1의 첫 D0 출력이며 추가 기준 모델 호출은 없다.

validation 8개는 calibration의 개선·완전성·자원 게이트를 통과한 뒤에만 다른 가족으로 등록·작성한다. 부모/정책 구현자는 그 원문·질문·정답·검토 설명을 읽지 않는다. 현재 validation 작성·추론은 0이다. 기존 노출된 12문항과 M5-B/최종 test는 재사용하지 않는다.

## 검증과 한계

등록은 자료 준비 또는 모델 품질 완료를 뜻하지 않는다. 공개 문서는 제품의 통합 문서 RAG를, 합성 회의는 통제된 결정/조건 관계를 확인하는 소규모 자료다. 실제 조직 사용자 정확도나 일반화 성능으로 확대하지 않는다.

원문/질문/모델 출력은 등록된 공개·합성 실험 결과에만 저장한다. 운영 로그에는 남기지 않는다. 전체 staged diff/공백 검사에서 격리 자료가 화면에 나오지 않도록 검사 출력은 로컬 파일로 보내고 종료 코드와 집계만 확인한다.

가족 등록은 도구가 수락한 `meeting_c1_registry`의 Astra xhigh 역할이 작성했다. 부모는 등록 메타데이터를 확인하고 이 작성 순서를 문서화했다. 사용자 검수 0이며 준비 단계의 세부 상태는 [STATUS](STATUS.md)를 따른다.
