# 회의 AI worker — 실험 운영 경로

이 경로는 Phase 1 회의록/문서 지식 검색을 위한 **실험 모델 통합**이다. 기존 M5-A v1/v2 및 M5-B 동결 입력·평가·계획은 변경하거나 재실행하지 않는다. Qwen3-1.7B의 과거 의미 오류와 보류 실패는 해결됐다고 주장하지 않는다. 모델 기본 채택, 사용자 검수, 생성 품질 평가 통과의 증거가 아니다.

## 실행

Java jar와 프런트엔드 빌드, 기존 로컬 모델 파일, 이미 설치된 retrieval dependency group이 필요하다. 실행기는 의존성을 동기화하거나 모델을 내려받거나 빌드하지 않는다.

```powershell
uv run --no-sync --group retrieval python -m scripts.serve_meetings --port 8000
```

기본은 BM25 + CUDA 생성 worker다. `--retrieval`을 붙이면 기존 E5/BGE worker를 **CPU**에 로드한다. `--no-retrieval`은 기본값을 명시한다. 6GB GPU에 retrieval과 generation을 동시에 올리지 않는다. 시작 전 다른 GPU 모델 작업과 실험 active lock을 확인해야 한다. 기존 실험의 lock을 삭제하거나 진행 중 작업을 강제 중단하지 않는다.

기본 모델 경로는 `models/generation-m5-qwen3-1.7b`이다. 원본 manifest `data/models/m5-generation-v1.json`의 모델 revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`, 전체 파일 집합·크기·SHA256, Torch 2.10.0, Transformers 4.57.6을 검증하는 기존 loader를 읽기 전용으로 재사용한다. `local_files_only=True`, 원격 코드 비허용, offline 환경을 사용한다. 무료/유료 API 호출이나 새로운 다운로드는 없다.

Java는 `DOCTRAIL_GENERATION_URL`과 `DOCTRAIL_GENERATION_TOKEN`으로 worker에 접근한다. 실행기가 매번 무작위 토큰을 자식 환경에만 전달하고 출력하지 않는다. 독립 실행은 32자 이상의 안전한 토큰을 환경에 설정한 뒤 `python -m doctrail.meeting_worker`로 가능하다. HTTP는 `127.0.0.1`에만 바인딩되며 `/health`, `/analyze`, `/answer` 모두 Bearer 인증을 요구한다. 이 내부 인증은 사용자/문서 접근권한을 대신하지 않는다. 세션·권한·저장·job lifecycle·최종 인용 검증은 Java 책임이다.

실행기는 실패나 종료 시 자신이 만든 Java/생성/선택적 검색 프로세스만 종료한다. worker는 프로세스 생존 기간 OS lease로 같은 저장소의 생성 worker 중복 실행을 막는다. 프로세스 종료 시 커널이 lease를 해제하며 lock 파일을 삭제하지 않는다. 다른 종류의 GPU 실험을 이 lease가 대신 조율하지 않으므로 시작 전 active job 확인은 여전히 필요하다. 토큰·질문·원문·모델 원시 출력을 운영 로그에 남기지 않는다. 일반 서버 access log도 끈다. 모델 시간과 worker HTTP 시간은 Java 서비스 응답 시간과 별도다.

## 실제 모델 처리와 한계

새 protocol은 `meeting-classifier-evidence-v4`이다. 최신 답변 개발 prompt의 raw 실행 영수증은 아래 개발 v9에 있다. 회의 추출은 실제 Qwen이 각 원문 단위를 열 개 범주(skip/제목/날짜/참석자/목적/주제/제안/결정/미해결/작업)로 분류한다. 현재 원문 단위와 12개의 AI 작성 가상 형식 예시를 입력하고, 0~9 각각이 단일 token인지 검증한 뒤 실제 모델의 다음 token logits를 이 열 개 선택지로 제한해 argmax를 취한다. 예시는 과거 M5 평가셋을 읽거나 가져오지 않았다. 최대 4개 입력을 한 번에 forward하고 `use_cache=False`, `logits_to_keep=1`을 사용한다. 입력이 768 tokens를 넘으면 해당 batch는 하나씩 처리한다. 이는 실제 LLM 분류이며 정규식으로 분류한 것을 AI 결과로 포장하지 않는다. 라벨 간 상대 점수는 보정된 신뢰도로 표시하지 않는다.

모든 단위를 처리한 후 서버가 작업→결정→미해결→제안→주제 순서와 원문 순서로 최대 4개 요약 구절을 선택한다. 항목은 최대 150개까지 **모두 보존**하며 초과 시 명시적 오류다. 일곱 번째 작업이 조용히 버려지지 않는다. 요약에는 Discourse/Date 헤더, 녹화·게시 안내 같은 한정된 상용구를 제외하는 명시적 표시 규칙을 적용하며 원문/전체 분류 항목은 그대로 둔다. 이 우선순위와 상용구 제외는 결정적 표시 규칙이며 모델의 중요도 평가라고 주장하지 않는다. 서버가 선택된 단위에서 정확한 인용과 Unicode code point 절대 오프셋을 재구성한다. 요약 문구는 이 원문 구절을 연결하는 **발췌 요약**이며 자유로운 요약문 생성으로 표시하지 않는다. 원문 문자열 일치는 의미 판단이 올바르다는 증거가 아니다.

모델 프롬프트는 명시적으로 채택된 해법/합의만 decision으로 분류하도록 요구한다. 모든 AI 항목 상태는 `needs_confirmation`이다. Java가 ID를 발급하고 UI가 사용자 확인을 표시한다. **모델이 분류한 작업 구절의 담당자·기한·우선순위, 메타데이터 구절의 값은 유한 규칙으로 추출**한다. 이 값까지 자유 생성 모델이 추출했다고 주장하지 않는다. 담당자는 명시적 한국어 주어 또는 영어 `Name will` 구문, 작업 기한은 같은 구절의 `까지`/`by`/`due`/`deadline`에 연결된 유일한 ISO 날짜, priority는 `priority:`/`우선순위:` 뒤 low/medium/high 또는 낮음/보통/높음만 허용한다. 과거 사고 날짜를 마감일로 삼지 않는다. 참석자는 명시적 헤더의 쉼표 목록 또는 모델이 분류한 참석자 표 행의 첫 열에서 얻는다. 제목·목적은 명시적 헤더, 회의 날짜는 해당 줄의 유일한 ISO 날짜만 읽는다. 비작업 항목에는 담당자·기한·우선순위를 채우지 않는다. 빈 배열·null은 유효하다. 날짜 자연어 정규화와 불명확한 이름 추론은 하지 않으므로 실제 존재하는 정보를 누락할 수도 있다.

답변은 실제 Qwen이 생성한 짧은 claim과 **서버가 부여한 작은 정수 evidence ID**를 파싱한다. 모델에게 UUID나 원문 quote를 다시 쓰게 하지 않는다. 서버가 요청받은 청크 안의 각 줄을 정확한 원문 span으로 나누고 같은 문서·revision·절대 위치의 중복을 제거한다. 160개 이하의 후보 줄에서 기존 BM25로 최대 12개를 선별한다. 영어 질문의 일반적인 기능어만 순위 계산에서 제외하고 한국어·숫자는 보존한다. 선택된 자료는 문서별로 묶고 0부터 다시 번호를 부여한다. 받은 청크 수·선별 구절 수·문서 수·12개 상한을 telemetry에 남긴다. 이 두 번째 검색 단계는 결정적 선별이며 LLM이 relevance를 판단했다고 주장하지 않는다.

네 개의 별도 AI 작성 가상 답변/보류 예시와 함께 실제 모델이 claim과 evidence 배열을 생성한다. 정수 ID가 참조하는 chunk ID·원문 quote·문서 절대 code point 위치를 그대로 응답으로 연결하고 Java가 현재 revision·원문으로 다시 검증한다. 잘못된 ID·타입·중복 ID는 오류다. 인용 문자열을 유사 매칭하거나 수정하지 않는다. 동일한 문자열이 여러 위치에 있어도 개별 ID가 위치를 구별한다. 원문 span의 정확성은 claim 의미의 지지를 증명하지 않는다. 빈 검색 청크는 모델 호출 없이 `abstained`; 전달된 청크가 있는 요청은 선별 결과가 비어도 실제 모델이 답변/보류한다. 모델이 반환한 보류와 잘못된 JSON/잘린 출력/인용 불일치 실패를 구분한다.

## 유한 입력과 실행 예산

| 항목 | 상한/동작 |
|---|---|
| HTTP 본문 | 512KiB; 인증 후 실제 수신 바이트도 검사 |
| 분석 원문 | 24,000 Unicode code points |
| 분석 분할 | 선택용 분할 기준 prompt 포함 2,200 tokens 이하, 최대 6개; 최대 160개 원문 단위, 전체 단위를 실제 분류 |
| Q&A | 최대 10개 chunk, 160개 구절 후보에서 BM25 최대 12개 선별, 전체 prompt 4,096 tokens; 상한 초과 시 명시적 422 |
| 생성/분류 | 답변 호출당 최대 768 tokens, 실제 greedy 설정 검사; 분류는 10개 라벨 제한 argmax, 양쪽 thinking 비활성 |
| 요청 | 전 분할 합계 120초; 초과 504, 동시 요청은 model_busy 503 |
| GPU | loader의 5,376MiB reserved-memory 상한 재사용 |

분할은 원문 줄과 code point 경계에서 이루어지며 원문을 수정하거나 token decode로 잘라 복구하지 않는다. 빈 줄/주변 공백은 선택 단위에서 제외하지만 본문의 원래 위치는 유지한다. 명시적인 `## Purpose`/`## 목적`과 바로 다음 본문은 하나의 정확한 근거 span으로 묶고 모델 입력만 `Purpose: 본문` 형태로 표현한다. 원문 근거에는 제목·줄바꿈·본문이 그대로 남는다. 아주 긴 한 줄도 유한 분할한다. 모든 분할은 모델 실행 전에 계획되며 6개/160단위 초과는 호출 없이 실패한다. 30개를 넘는 메타데이터 단위는 명시적 오류로 처리한다. 처리 중 하나라도 실패하면 완성된 분석으로 저장하지 않는다. 5MiB 업로드 지원과 모델 분석 가능 용량은 다르다. Q&A의 구절 선별은 위에 선언한 검색 정책이며 prompt token 초과를 숨기기 위해 문자열을 잘라내지 않는다.

deadline은 토큰 생성 사이와 요청 경계에서 검사한다. 정지된 CUDA kernel을 프로세스 내부에서 hard-real-time 중단하는 보장은 없으며 Java HTTP timeout과 실행기 프로세스 종료가 별도 경계다. worker가 살아 있다고 CUDA가 항상 복구 가능하다고 보장하지 않는다. 실패 뒤 자동 재시도는 없다.

## 검증 분리

`tests/test_meeting_worker.py`는 synthetic/fake-generator 계약·인증·본문 제한·오프셋·인용·보류 경로·입력 한도 검사다. 실제 모델 품질 증거가 아니다. 실제 GPU 개발 probe는 이전 M5 평가와 분리해 `.local/meeting-development`에 입력·raw 출력·적용 설정·실패를 기록한다. 이 개발 기록은 prompt 개발용이며 잠금 test나 인간 검토로 계산하지 않는다. 공개 자료 운영 검증과 Java/브라우저 결과는 별도 통합 실행 결과를 따른다.

2026-10-13 개발 결과: 새 worker 단위/HTTP 계약 37개가 통과했고 관련 새 파일의 Ruff 검사도 통과했다. 인간 검수는 0이다. 개발 prompt는 아래의 관찰을 사용해 수정했으므로 아래 수치를 독립 검증 성능으로 해석하지 않는다.

| 개발 영수증 | 실제 실행 | 보존한 결과/실패 |
|---|---|---|
| v1 | 자유 JSON 생성 3회 | 공개 회의 추출은 768 tokens에서 잘림, 한국어 추출은 잘못된 schema, 한국어 근거 답변 1개는 구조·인용 통과 |
| v2 | 압축 JSON few-shot 생성 3회 | 공개 회의는 잘림, 한국어는 허용되지 않은 category/schema, 근거 답변 1개 통과 |
| v3 | 실제 Qwen 라벨 분류 2요청 | 두 요청 구조 통과; 한국어 핵심 항목이 모두 topic인 의미 실패, 공개 요약에 안내문이 포함됨 |
| v4 | 실제 Qwen 라벨 분류 2요청 | 한국어 8단위 범주 구분, 공개 회의 substantive line을 skip으로 놓쳐 empty summary 실패 |
| v5 | 실제 Qwen 라벨 분류 2요청 | 공개 58단위/18 forward batch: 13.08초, 한국어 8단위/2 batch: 1.77초, 최대 reserved 3,938MiB; 두 요청 구조·인용 통과 |

v5 공개 February 회의에서는 참석자 23명·주제 19개·skip 14개·제목·날짜 각 1개로 분류했다. 실제 날짜 `2025-02-19`를 회수했다. 한국어 가상 회의는 제목/날짜/참석자/목적/제안/결정/작업/미해결 각 1개로 분류했고, 작업의 명시적 이름과 기한을 회수했다. 공개 주제에는 여전히 안내문 오분류가 있어 v5 관찰 뒤 **모델 재실행 없이** 요약 표시 전용 상용구 제외 규칙을 추가하고 단위 검증했다. 새 전체 운영 실행은 이 최종 소스와 별도로 비교해야 한다. 위 시간은 Python GPU 개발 측정이며 Java 서비스나 HTTP 응답 시간으로 사용하지 않는다.

## 첫 운영 실패 이후의 교정 기록

최초 Java 운영 실행 `.local/meeting-live-v1/operations.json`은 일반 문서 답변 뒤 공개 두 회의 비교에서 `generation_invalid_evidence`로 실패했다. 원시 응답을 별도 개발 v6에서 재현하자 모델이 인용의 Markdown 표시를 삭제했고, February beta 발표를 June 사건으로 잘못 서술했다. 실패를 덮어쓰지 않고 인용 프로토콜과 답변 prompt를 새 운영 경로에서 교정했다. 운영 프로세스가 소스를 import한 뒤 변경된 파일 hash를 수집하면 실행 소스 증명이 되지 않으므로 통합 실행은 시작 전에 파일을 동결하고 snapshot을 남겨야 한다.

| 개발 영수증 | 실제 실행 | 관찰 |
|---|---|---|
| v6 | 기존 운영 비교 답변 1회 재현 | Markdown quote 불일치 + 잘못된 월 연결, strict 오류 보존 |
