# DocTrail 면접 설명 초안

기준일: 2026-10-29. **사용자 검수·설명 연습 확인 전 초안이며 제출용 확정 답변이 아니다.** 아래는 저장소 근거를 설명하는 문장이다. AI가 구현·실행·검토한 일을 사용자가 직접 했다고 바꾸어 말하지 않는다. 실제로 코드를 읽고 시연한 뒤 본인의 판단과 확인 범위를 덧붙인다. [기여 기록](CONTRIBUTIONS.md), [현재 상태](PROGRESS-OVERVIEW.md).

## 1. 어떤 문제를 해결하려는 프로젝트인가요?

- 답변 초안: 개발 조직의 구성원이 한국어·영어 문서와 회의 기록에서 필요한 내용을 찾고, 현재 열 수 있는 원문으로 근거를 확인하도록 돕는 서비스입니다. 검색 순위뿐 아니라 권한·문서 갱신·원문 이동을 연결했습니다. 실제 조직 도입이나 사용자 조사 성과는 아직 없습니다. [소개](../README.md).
- 꼬리질문: 일반 키워드 검색이나 파일 공유만으로 부족한 상황은 무엇인가요?
- 직접 확인할 점: 본인이 겪은 탐색 문제와 가정한 문제를 구분하고, 접근 가능한 문서 검색에서 원문 확인까지 직접 시연하기.

## 2. Java·React·Python을 왜 나눴나요? Python만 써도 되지 않나요?

- 답변 초안: Java는 세션·권한·문서 상태와 API, React는 검색·편집·근거 확인 화면, Python은 모델과 데이터·학습·평가를 맡습니다. Java 전환은 사용자 요청이었고 세부 분리와 구현은 AI 지원으로 진행됐습니다. Python 단일 서비스라면 경계가 줄지만, 현재 구조는 모델 교체·장애를 서비스 상태와 분리할 수 있습니다. 대신 인증·버전·오류 계약을 관리해야 합니다. [구성](../README.md), [실제 기여](CONTRIBUTIONS.md).
- 꼬리질문: 모델 worker가 죽으면 일반 문서 검색도 중단되나요?
- 직접 확인할 점: 실제 worker 장애 결과에서 선택 모델의 명시적 오류와 기본 BM25 유지가 어떻게 구분되는지 읽고 설명하기. [운영 검사](../experiments/results/m3-model-service-v1.json).

## 3. 권한과 문서 revision은 검색에서 왜 중요한가요?

- 답변 초안: 열 수 없는 문서가 후보나 모델 입력에 들어간 뒤 화면에서만 숨기면 충분하지 않습니다. 수정·삭제된 문서의 예전 근거와 캐시도 다시 쓰면 안 됩니다. 연결 검사에서는 작업공간·비공개 ACL, 수정 후 예전 근거 제거와 오래된 피드백 거부, 같은 본문 재처리의 버전 갱신, 삭제 문서의 캐시 제외를 확인했습니다. 합성 자료의 로컬 검사이며 보안 감사 완료는 아닙니다. [검사 항목](../experiments/results/m3-model-service-v1.json).
- 꼬리질문: 요청 도중 권한이나 문서가 바뀌면 어떤 상태를 다시 확인해야 하나요?
- 직접 확인할 점: 권한 확인과 결과 저장 사이의 경합, 문서 ID와 revision의 차이, 오래된 화면 요청을 거부하는 실제 경로를 코드와 시연으로 확인하기.

## 4. 임베딩과 혼합 검색이 BM25보다 항상 좋았나요?

- 답변 초안: 아닙니다. M3 같은 입력에서 모든 필수 근거 top-5 회수는 BM25 30/59, E5 29/59, 혼합 27/59, 혼합+BGE 재정렬 36/59였습니다. 별도 후보 선택 비교는 36→37/59였지만 회복은 한 질문입니다. 모델을 추가한 사실과 품질 개선을 구분했고, 후보에 없는 근거는 후단 재정렬만으로 회복할 수 없다는 점을 봤습니다. [첫 비교](M3-ANALYSIS.md), [후보 비교](M3-CANDIDATE-ANALYSIS.md).
- 꼬리질문: 후보 생성과 재정렬 중 어느 단계가 문제인지 어떻게 구분하나요?
- 직접 확인할 점: top-50 후보에 필수 근거가 없는 경우와 후보에는 있지만 top-5에 못 올라온 경우를 각각 설명하기. 전체 모델의 일반 우열로 확대하지 않기.

## 5. 실제 학습으로 무엇이 좋아졌고 무엇이 나빠졌나요?

- 답변 초안: E5를 제한적으로 학습한 저장본과 원래 모델을 같은 조건에서 새로 비교했습니다. dev 양성 59질문의 모든 필수 근거 회수는 후보 50개에서 34→47, 상위 5개에서 29→37이었습니다. 하지만 @5 회복 14개와 퇴보 6개가 함께 있었고, 다중 문서 질문은 1→0/7로 나빠졌습니다. 제한된 근거 회수 개선이며 답변 정확도나 기본 서비스 채택은 아닙니다. [결과](../experiments/results/m4-main-dev-v1.json), [해석](M4-MAIN-DEV-ANALYSIS.md).
- 꼬리질문: 37/59면 M3 재정렬과 같은 성능이라고 말할 수 있나요?
- 직접 확인할 점: M4는 같은 tokenizer·FP32·512토큰·dense 50후보의 fresh base 비교임을 설명하기. 서로 다른 실험의 같은 총점과 같은 실패 구성을 혼동하지 않기.

## 6. 평가 데이터와 test 잠금은 어떤 한계가 있나요?

- 답변 초안: 학습용 자료와 별도 dev를 사용했고, M4 dev 79질문 중 주석상 근거가 있는 59개를 주 분모로 삼았습니다. 질문과 라벨은 AI 작성이며 사용자 검수는 0개입니다. 최종 test의 내용을 검토하거나 모델 평가에 사용하지 않았습니다. 이후 중복 방지 준비에서는 본문 의미를 노출하지 않고 고정 질문 필드의 해시만 기계적으로 추출했습니다. 여러 필수 근거를 모두 찾는 조건을 고정했지만 주석에 대체 근거가 빠질 수 있고, 작은 개발 집합의 개선은 일반 성능을 보장하지 않습니다. [비교와 주석 한계](M4-MAIN-DEV-ANALYSIS.md).
- 꼬리질문: 결과를 본 뒤 대체 정답을 발견하면 점수를 고쳐야 하나요?
- 직접 확인할 점: 고정 점수는 보존하고 대체 근거를 별도 검토 기록으로 남긴 이유, dev·test와 사람·AI 검수의 차이를 설명하기. 보지 않은 test 결과를 추측하지 않기.

## 7. 인용이 원문과 정확히 같으면 답변도 맞는 것 아닌가요?

- 답변 초안: 문자열·위치 일치는 근거가 원문에 존재한다는 검사입니다. 그 근거가 문장 전체를 지원하는지, 조건·예외·시점을 보존했는지, 질문의 핵심을 빠뜨리지 않았는지는 별도입니다. 요약 v3에서 인용은 초안 71/71·수정본 70/70 일치했지만, 선택 근거가 충분히 지원한 주장은 각각 10/18이었고 핵심 충분 요약은 둘 다 0/3이었습니다. [독립 AI 판단](../experiments/results/meetings-grounded-summary-review-v3.json).
- 꼬리질문: 정확 인용, 문장 지원, 전체 요약의 충분성을 어떤 순서로 확인하나요?
- 직접 확인할 점: 원문과 인용의 존재 확인만으로 의미 판정을 대체하지 않는 이유를 설명하기. AI 판단도 사용자 검수나 외부 독립 평가로 포장하지 않기.

## 8. 자기검토와 한 번 더 재작성하는 방식은 효과가 있었나요?

- 답변 초안: 이 고정 비교에서는 품질 회복을 확인하지 못했습니다. 재작성 전후 핵심 충분 요약은 0/3으로 같았고, 자기검토는 세 요약 모두 충분하다고 판단했습니다. 추가 재작성 전송 시간은 평균 29.219초 관측됐습니다. 표현 변화나 검토 통과만으로 채택하지 않았습니다. 작은 개발 결과로 모델 내부의 실패 원인이나 모든 자기검토 방식의 한계를 확정할 수는 없습니다. [비교 방식·시간·한계](MEETINGS-SUMMARY-V3-ANALYSIS.md).
- 꼬리질문: 자기검토 결과를 독립 판단 전에 보면 무엇이 달라질 수 있나요?
- 직접 확인할 점: 개별 판단을 잠근 뒤 전후 대응과 자기검토를 공개한 순서, 완전 맹검은 아니었다는 제한을 설명하기. 겹치는 시간 구간을 더해 전체 지연으로 말하지 않기.

## 9. 새 무료 로컬 모델을 쓰면 해결됐나요?

- 답변 초안: 아직 해결됐다고 말할 수 없습니다. 최신3B 개발 비교에서 답변4개는 형식과 EOS를 통과했고 인용10개도 원문과 같았지만, 별도 AI 내용 수용은0/4였습니다. 필수 내용13개 중 충족1·부분4·누락6·오류2였고 요약4개는 형식·출력 조건에서 거부돼 내용 평가를 하지 못했습니다. 같은 지침의 미세변형은 종료했습니다. 새7B 자산은 받았지만 새6개 비교는 아직 실행 전입니다. [최신 실제 결과](MEETINGS-LOCAL-QA-CONTROL-RESULTS.md), [다음 비교의 고정 조건](MEETINGS-FREE-QA-NEXT-DECISION.md).
- 꼬리질문: 출력 상한을 늘리거나 모델 자기검토를 추가하지 않고 모델 비교를 택한 이유는 무엇인가요?
- 직접 확인할 점: v7 답변은 모두 EOS로 끝나256토큰에서 잘린 실패가 아니었다는 점, 모델 크기만의 인과 효과가 아니라 가중치·양자화·tokenizer·template 묶음 비교라는 점, 새 모델 우위를 미리 가정하지 않는 기준을 설명하기. 과거 실패 질문으로 다시 튜닝하지 않기.

## 10. CI 정체 문제는 원인을 찾아 해결한 사례인가요?

- 답변 초안: 원래 원격 Maven 정체의 원인은 확인하지 못했습니다. 같은 소스의 다른 실행은 통과했고 필요한 원본 로그도 확보하지 못했습니다. 후속 변경은 JUnit 120초·fork 300초·Maven step 10분·job 30분 상한과 제한된 진단 보존입니다. 로컬 정상·합성 지연 검사와 Linux 정상 경로의 Java 232검사·진단 업로드는 확인했지만 Linux 강제 지연 종료는 미검증입니다. [CI 설명](CI-JAVA-DIAGNOSTICS.md), [원격 근거](../experiments/results/java-ci-bounded-source-ci-v1.json).
- 꼬리질문: timeout을 추가했다고 같은 결함이 재발하지 않는다고 할 수 있나요?
- 직접 확인할 점: 원인 제거와 실패 대기시간 제한·관측 개선의 차이, 원래 종료코드를 보존하는 이유, raw 로그 대신 허용한 필드만 공개하는 이유 설명하기.

## 11. 지금 어디까지 완료됐고 실제 배포한 서비스인가요?

- 답변 초안: 문서·회의 관리, 검색·근거 이동과 편집 흐름은 구현·로컬 검증돼 있습니다. 실제 Java의 합성 자료 백업·복원 12항목도 통과했습니다. 그러나 실제 모델을 포함한 요약·자연어 답변 전체 수용, 새 환경 운영, 사용자 외관·사용성 검수가 남았습니다. 외부 서비스 배포나 조직 사용 사례는 없고, 합성 화면 검사를 실제 모델 품질로 세지 않습니다. [진행 상태](PROGRESS-OVERVIEW.md), [회의 결과](MEETINGS-RESULTS.md).
- 꼬리질문: 지금 시연하면 무엇을 실제 모델 결과로 보여 줄 수 있나요?
- 직접 확인할 점: 시연 경로와 모델·DB를 먼저 확인하고 합성 응답 여부를 표시하기. 기본 서비스와 별도 4B 실험 경로, 오프라인 3B 후보를 혼동하지 않기. 레이아웃·색상·원문 이동도 직접 확인하기.

## 12. AI가 얼마나 만들었고 본인은 무엇을 했나요?

- 답변 초안: 저장소 기록상 사용자는 개인 포트폴리오 목적, 문서 검색·모델 개선 목표, 한국어·영어 범위, Java 전환과 유료 사용·외부 배포 경계를 정했습니다. 세부 설계·코드·테스트·실행·분석·문서에는 AI가 참여했습니다. 현재 사용자 직접 코드 검토·화면 시연·질문 검수·면접 숙지 기록은 없으므로 전부 직접 구현했다고 말할 수 없습니다. Git 작성자 계정과 실제 작업 주체도 구분합니다. [기여 원본](CONTRIBUTIONS.md).
- 꼬리질문: 지금 AI 없이 설명하거나 수정할 수 있는 부분은 어디인가요?
- 직접 확인할 점: 직접 읽은 코드, 재현한 동작, 발견한 문제와 수정·판단 이유를 날짜와 함께 본인이 기록하기. 확인 전에는 개인 기여 비율이나 AI 덕분의 비용 절감 수치를 만들지 않기.

## 13. 새 평가 질문의 데이터 누출은 어떻게 줄였나요?

- 답변 초안: 기존·예약·거부 출처의 계열과 조상 저장소를 먼저 제외하고, 원본·수정본 질문51개 파일의1,118기록에서516개 고유 해시를 만들었습니다. 새 작성자에게 과거 질문이나 정답을 보여 주지 않고 식별자·해시와 출처 규칙만 전달했습니다. 정확 해시로 변형 복사나 번역 중복 전체를 찾을 수는 없어서 별도 사전 검토자가 출처와 필수 내용의 충분성을 확인해야 합니다. 현재 새6개는 준비 단계이며 아직 성능 결과는 없습니다. [제외 목록의 검증과 한계](MEETINGS-FREE-QA-EXCLUSION-PREPARATION.md).
- 꼬리질문: 파일 해시가 다르면 새로운 자료라고 볼 수 있나요?
- 직접 확인할 점: 파일·정규화 내용·질문 해시의 의미, 같은 계열의 파생 문서를 제외하는 이유, AI 작성·자동 검증·사용자 검수의 차이를 설명하기. 중립 합성 사례와 실제 자료의 품질 평가를 합산하지 않기.
