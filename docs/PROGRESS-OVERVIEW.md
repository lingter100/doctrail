# 사용자가 보는 현재 진행 상황

기준일: 2026-10-22. 핵심 기능은 구현돼 있으며, 무료 로컬 AI의 품질과 전체 운영·화면 흐름을 완성하는 중이다. 1차 회의 지능형 관리와 전체 프로젝트 목표는 진행 중이다. 상세 이력은 [STATUS](STATUS.md), 완료 기준은 [회의 설계](MEETINGS-DESIGN.md)를 따른다.

## 현재 고치고 있는 문제

원문 단독 기준과 실제 추출159개를 비교한 사후 AI 진단에서149개는 우선/허용 집합에 맞았고10개는 명확히 달랐다. 네 요약 모두 첫4개 작업에 치우쳐 핵심 내용이 부족했고, 올바른 제목 라벨 뒤 필드2개가 누락됐다. 확약3개는 작업이 아닌 다른 유형으로 분류됐다. 인용179개가 원문과 일치해도 요약 충분성은 별도 문제다. [추출 진단과 한계](../experiments/results/meetings-analysis-scope-extraction-review-v1.json).

우선 분류 결과를 고정한 채 요약 선택과 제목 변환의 손실을 줄이는 `coverage-v1`을 구현한다. 기존4개 요약 한도 안에서 여러 유형을 순환 선택하고, 제목으로 분류된 원문에서 실제 제목 값을 보존한다. [설계](MEETINGS-EXTRACTION-COVERAGE-PLAN.md)에 대안과 한계를 기록했다. 새 모듈과 서비스·실행기 연결은452개 합성·MockTransport/Node 계약 검사와 독립 코드 검토를 마쳤다. 정확한 source commit의 양쪽 필수 CI도 통과했다. 저장된 동일 분류159개로4회의를 각각 한 번 조립해 요약4개·제목2개가 바뀌었고 나머지 결과가 유지됨을 확인했다. 같은 잠금 기준의 독립 의미 검토에서 주요 결정의 노출은 늘었지만 요약 충분성은0/4로 그대로였다. 제목 빈칸2개는 채웠으나 접두어가 남아 정확한 기대값 일치는2/4로 유지됐다. [비개선 결과](../experiments/results/meetings-extraction-coverage-review-v1.json)를 보존하고 의미관계가 반영되는 별도 후보를 설계한다. 기존 분할기가 만드는 공백 span을 잘못 거부한 문제의 최초 실패와 수정도 보존했다. **같은 분류의 후처리만으로 충분한 요약을 얻지 못했다. 새 모델 실행·새 운영 통과는 아직 검증하지 않았다.**

지식검색의 보류·오류 안내는 근거 충돌/부족과 시간 초과/요청 실패를 구분하도록 수정했다. Java50개·실제 Java/합성 응답 브라우저14개와 좁은 후속 회귀를 통과했고 정확한 수정 커밋의 필수 CI도 통과했다. 검사 반복을 새 고유 검사로 합산하지 않는다. [구현 검증](../experiments/results/knowledge-answer-recovery-messages-v1.json), [CI](../experiments/results/knowledge-answer-recovery-ci-v1.json).

전체 화면 여정에서는 재분석 내부 코드 노출과 키보드 초점 유실을 확인해 고쳤다. 독립 검토가 찾아낸 ‘A 원문을 연 채 B를 업로드한 뒤 닫으면 A로 돌아가는’ 문제도 실제 재현 뒤 수정했다. 첫 수정12개와 최종 영향 범위4개는 겹치는 검사다. 최종 타입·빌드·패키징·독립 읽기 검토와 정확한 수정 커밋의 양쪽 필수 CI를 통과했다. [화면·이미지·재현 방법](MEETINGS-VISUAL-ACCEPTANCE.md), [검증 한계](../experiments/results/meeting-product-walkthrough-v1.json), [CI 결과](../experiments/results/meeting-product-walkthrough-ci-v1.json).

## 실제로 관측한 결과와 한계

- 최근 작은 합성 개발 자료를 실제 로컬 모델로 처리해 문서6개 등록, 회의4개 분석, 질문6개 응답(답변4·보류2), 인용17개, 작업편집4개, 결정연결2개까지 진행했다. 마지막 소유 프로세스 종료 확인이 실패해 전체 실행은 실패로 유지한다. 이후 프로세스 부재 확인으로 원래 결과를 통과 처리하지 않았다. [실제 실행](../experiments/results/meetings-analysis-scope-development-v2.json).
- 해당6건의 독립 사후 AI 답변 검토는 문제 없음5건·불필요한 추가 인용1건이다. 핵심 답변4건과 보류2건은 타당했지만 작은 합성 개발 자료의 결과이며 공식 평가·실제 조직 품질·사용자 검수를 뜻하지 않는다. [답변 검토](../experiments/results/meetings-analysis-scope-answer-review-v1.json).
- 질문6건은 클릭부터 응답JSON 수신까지 평균52.758초(42.973~62.573초), 회의분석4건은 worker 관측 평균29.332초였다. 측정 구간이 다르고, 최종 화면 렌더·운영p95·전체 비용은 미측정이다. [실측 구간](../experiments/results/meetings-analysis-scope-performance-v1.json).
- 검색 dev의 필수 근거 회수는 BM25 30/59, 기존 혼합+리랭커36/59, 후보 선택 개선 후37/59였다. 별도 학습 저장본 비교의 E5 상위5 회수는29/59→37/59였지만 다중 문서 질문은1/7→0/7로 나빠졌다. 최종 test와 사용자 검수는 남아 있다. [M3](M3-ANALYSIS.md), [후보 개선](M3-CANDIDATE-ANALYSIS.md), [M4](M4-MAIN-DEV-ANALYSIS.md).
- 화면에서는 수정한 회의 제목으로 검색되지 않거나 좁은 화면에서 담당자·기한이 숨는 문제를 실제 Java에서 재현하고 수정했다. 해당 시나리오 통과를 전체 외관 검수 완료로 표현하지 않는다. [화면 검증](MEETINGS-VISUAL-ACCEPTANCE.md).

앞선 모델 후보의 의미 오류·시간 초과·입력 조건 실패와 데이터 미채택 이력은 [STATUS](STATUS.md)와 각 원래 결과에 보존한다. 테스트·CI 통과와 실제 AI 품질을 구분한다.

## 남은 순서

1. 새 조립의 구현·검증·동일 분류 비교와 독립 의미 검토를 마쳤다. 핵심 누락이 남아 [압축 주장마다 여러 원문 근거를 연결하는 후보](MEETINGS-GROUNDED-SUMMARY-PLAN.md)의 단독 모듈을 구현하고 신규55개 포함 관련162개 합성 검사와 독립 코드 검토를 마쳤다. Java/화면/실제 서비스 연결이 다음이며 실제 모델의 실행 가능성과 품질은 아직 미검증이다. 기존 결과·기준은 보존한다.
2. 누락과 의미 오류의 남은 원인을 분리해 개선하고, 변경된 실제 서비스 흐름·종료·복구를 검증한다. 공개 실제 자료의 출처·권한·전체 색인을 유지하며 calibration 통과 뒤 격리 validation과 최종 평가 조건을 따른다.
3. 권한 변경·문서 수정/삭제·오류 복구와 전체 화면·외관·새 환경 실행을 확인한다. 공개 배포는 승인과 별도 증거가 필요하다.
4. 시연·기준/개선 비교·실패 분석·면접 설명을 정리하고 AI 작성/검토와 사용자 직접 판단을 구분한다.

## 일정

2026-10-22 사용자에게 1차 기능과 포트폴리오 정리에 **추가2~4주를 임시 계획 범위**로 설명했다. 실제 개발 속도로 계산한 납기나 보장된 완료일이 아니다. 무료 로컬 모델의 품질 실패가 지속되면 늘어날 수 있다. 다음 일정 판단 지점은 새 조립의 실제 비교와 전체 서비스 검증 결과다. 현재 의미 있는 완료율을 산출할 근거도 없다.

검증 도구·실험 계약·실패 보존에 상당한 작업이 들어갔지만, 그것을 사용자 기능 완성이나 모델 품질 개선과 같은 성과로 계산하지 않는다. 준비 작업만 반복하는 것은 완료 증거가 아니다.

녹음·STT·실시간·외부 회의 연동은 2차 범위로 제외한다. 유료 서비스는 사용하지 않으며 공개 서비스 배포는 별도 승인 사항이다.
