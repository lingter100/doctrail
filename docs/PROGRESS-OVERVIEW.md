## 이미 얻은 AI 실험 근거

원래 dev 평가의 필수 근거 회수는 BM25 30/59, 기존 혼합+리랭커 36/59, 후보 선택 개선 후 37/59였다. 별도 학습 저장본 비교에서는 E5 상위5 회수가 29/59에서37/59로 바뀌었지만, 다중 문서 질문은1/7에서0/7로 나빠졌다. 사용자 검수0·최종 test 잠금·개발 평가라는 한계를 유지한다. 숫자는 [M3 분석](M3-ANALYSIS.md), [후보 개선 분석](M3-CANDIDATE-ANALYSIS.md), [M4 분석](M4-MAIN-DEV-ANALYSIS.md)의 저장된 실측이며 이번에 재실행하지 않았다.

실제 자연어 답변은 인용 문자열이 맞아도 내용이 틀리거나 질문 일부를 놓쳤다. C3의 독립 최종 답변 판정은2/6이었고 이후 경로도 시간 또는 입력 조건에서 종료됐다. C7 자료 탐색은 채택 자료와 모델 품질 실행 없이 종료했다. 마지막 제한 탐색은 본문을 보기 전에 예산이 끝났으므로 자료나 모델의 보편적인 불가능성을 뜻하지 않는다. 실패를 성공으로 바꾸거나 자료를 줄여 같은 실험을 구제하지 않는다.

최근 화면 작업에서는 수정한 회의 제목으로 검색되지 않는 문제와 좁은 화면에서 담당자·기한이 숨는 문제를 실제 Java 서비스에서 재현하고 수정했다. 관련 두 시나리오를 각각 검증했으며 전체 외관·서비스 품질 검수 완료는 아니다. [검증 범위와 화면](MEETINGS-VISUAL-ACCEPTANCE.md)을 확인할 수 있다.

## 남은 순서와 일정의 불확실성

1. [실제 서비스 RAG 연결](MEETINGS-SERVICE-RAG.md)의 worker·Java 시간 예산 코드는 구현했고 합성 계약 검사와 새 설정의 실제 화면 검사를 통과했다. 새 Python worker와 실제 native 모델을 모두 거치는 연결·분석 호환성 검증은 남았다.
2. 원문 전체를 등록·색인한 상태에서 권한이 있는 상위 검색 청크로 답변하는 실제 경로를 새 자료로 평가한다. 검색 누락과 생성 오류를 구분하고, 통과하지 못한 품질 기준을 낮춰 완료 처리하지 않는다.
3. 별도 최종 평가, 전체 화면 흐름·권한 변경·문서 갱신·삭제·복구와 새 환경 실행을 검증한다.
4. 최종 시연·실험 비교·실패 분석·면접 설명을 묶고 사용자 검수와 AI 검토를 구분한다. 공개 배포 승인과 실제 배포는 별도 단계다.

전체 완료일이나 의미 있는 완료 퍼센트를 산출할 근거는 아직 없다. 남은 작업은 단순 화면 수정의 양보다 무료 로컬 모델의 품질 관문 통과 여부에 좌우된다. “며칠 후 완료”나 “거의 완료”를 약속하지 않는다. 다음 일정 판단 지점은 실제 업로드→권한 검색→모델 답변→원문 열기의 연결 검증과 첫 새 품질 결과다. 연결의 성공만으로 전체 완료일을 확정하지 않으며, 종료 시한 없이 같은 준비와 실험을 반복하는 것을 진행 성과로 세지 않는다.

지금까지 검증 도구·실험 계약·실패 보존에 상당한 작업이 들어갔다. 이것은 재현성과 정직한 보고에 필요하지만 사용자에게 보이는 기능 완성이나 모델 품질 개선과 같은 성과는 아니다. 기능·품질·운영·발표 준비의 상태를 위 표처럼 따로 보고한다.

녹음·STT·실시간·외부 회의 연동은 2차 범위로 계속 제외한다. 유료 서비스는 사용하지 않으며 공개 서비스 배포는 별도 승인 사항이다.
