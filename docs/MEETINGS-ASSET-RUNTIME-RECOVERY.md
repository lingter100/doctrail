# 자산 준비용 Python 실행 환경 분리

2026-10-28. 기존 프로젝트 Python은 시작 시 Windows 오류448을 반환했다. uv 별칭이 연결 지점(Junction)이며 파일 읽기·폴더 조회도 신뢰되지 않는 탑재 지점 오류로 차단되는 것을 확인했다. 차단이 새로 발생한 계기는 확인하지 못했다. 기존 환경·연결 대상·보안 설정을 변경하지 않았다.

## 선택과 검증

같은 폴더에서 정상 실행되는 기존 번들 Python3.12.14를 사용해 `.local/meeting-qa-python312-v1/venv`를 `venv --copies`로 만들었다. 프로젝트 지원 범위 `>=3.11,<3.13` 안이며, 기본 `.venv`를 대체하지 않는 자산 준비 전용 환경이다. psutil이 기본 번들에 없어서 기존 `uv.lock`의 소형 패키지7개를 정확한 URL·버전·SHA·크기로 확인하고, 받은 휠만으로 격리 설치했다. 다운로드 합계는1,937,015바이트다.

## 실행 범위와 한계

이 PC의 명시적 실행기는 `.local/meeting-qa-python312-v1/venv/Scripts/python.exe`다. 환경 생성·설치·검사 명령과 휠 해시는 해당 폴더의 `venv-action.json`, `requirements-hashed.txt`, `pip-install-action.json`, `runtime-verification-receipt.json`에 저장돼 있다. 다른 PC에서는 신뢰할 수 있는 지원 Python을 별도로 준비하고 같은 잠금 의존성·검사를 확인해야 한다.

이번 결과는 원래 개발 환경의 복구나 전체 서비스 호환성을 입증하지 않는다. 모델 추론·엔진 빌드·Java 검증은 이 환경에서 수행하지 않았다. 실제 모델 파일 취득 결과도 별도 종료·무결성·정리 기록으로 판단한다. 사용자 검수와 유료 사용은0이다.
