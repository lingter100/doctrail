# 지식 검색의 원문 변경·접근 거부 복구

2026-10-16. 실제 Java/React 로컬 검증이며 일반 답변 모델의 의미 품질 평가는 아니다.

통합 지식 검색은 일반 검색과 별도의 질문·필터·결과를 가진다. 공용 원문 패널의 재검색 버튼은 일반 검색 상태만 읽고 있었다. 지식 검색 후 원문 revision이 바뀌면 일반 검색 이력이 없을 때 아무 요청도 보내지 않았고, 이력이 있으면 다른 질문을 일반 검색 API로 보냈다. 소유자가 문서를 비공개로 바꾼 뒤 독자의 원문 조회에서 실제404가 확인돼도 지식 검색의 이전 카드·발췌·건수는 남았다.

원문을 연 검색의 질문·조건·범위·검색 방식·작업을 함께 연결했다. 변경 경고의 명시적 ‘다시 검색’ 또는 ‘다시 질문’이 해당 작업을 다시 실행한다. 질문·필터·모드·화면·작업공간 변경 뒤 도착한 원문 응답이나 이전 callback은 적용하지 않는다. 접근 거부가 확인되면 해당 지식 결과 전체와 연결된 답변을 숨기고 입력 조건은 유지한다. 자동 검색·모델 재호출은 추가하지 않았다. 일반 검색의 복구도 그대로 검증했다.

전역 검색 상태에 지식 결과를 억지로 합치거나 서버 API를 추가하는 대신, 공용 원문 열기에 결과의 출처와 유효성 검사를 전달했다. 현재 하나의 결과 snapshot에서 인용하는 문서의 접근 거부가 확인되면 일부 주장만 남겨 정확한 답변처럼 보이게 하지 않고 전체 snapshot을 무효화한다. 이는 조회 전 실시간 권한 회수나 서버 ACL 우회 방지의 새로운 증명은 아니다.

## 재현과 검증

- 초기 `web-e2e-B2asFq`는 테스트의 select 접근성 이름을 잘못 잡은3건 timeout이다. 실제 결함 증거로 세지 않는다.
- 선택자를 고친 `web-e2e-J2YQS7`에서 수정 전3결함을 실제 재현했다. 재검색 요청 없음, 다른 일반 검색 GET 실행, 실제 reader404 뒤 이전 카드1개 유지가 각각 실패했다.
- 수정 후 새8개와 기존24개, 총32개 브라우저 검사가 통과했다. 실제 Java가 패키지된 React UI를 제공했고 각 서버가 종료됐다. 관련 기존 검사는 일반 검색·요청 경합·지식 오류 복구·모델 설정 경합·회의 근거 열기를 포함한다.
- TypeScript, production build, Java `package -DskipTests`가 통과했다. 이 패키징을 Java 단위 검사 전체 통과로 세지 않는다.
- 답변 인용과503 검사는 합성 전송/오류를 명시적으로 사용했다. 실제 LLM 호출0, 사용자 검수0이며 새 평가 원문은 사용하지 않았다. BM25 흐름을 검증했으며 실제 dense 추론 성능을 측정하지 않았다.

원본 report/log/trace/screenshot은 `.local/knowledge-source-recovery-v1/`에 보존한다. 공개 [검증 영수증](../experiments/results/knowledge-source-recovery-v1.json)은 파일hash·실행별 결과·초기 실패와 한계를 기록한다. 부모 AI는 실제390px 접근 거부 화면과 데스크톱 변경 경고 화면을 확인했다. 입력 조건과 명시적 복구 버튼이 보이고, 숨겨야 할 답변·결과는 남지 않았다. 이는 사용자 사용성 평가가 아니다.

재현 명령은 `cd web` 후 `npm run typecheck`, `npm run build`, 그리고 `DOCTRAIL_E2E_SPEC=tests/knowledge-source-recovery.spec.ts` 환경 변수로 `npm run test:e2e`를 실행하는 방식이다. Windows PowerShell에서는 `$env:DOCTRAIL_E2E_SPEC='tests/knowledge-source-recovery.spec.ts'`로 지정한다. 전체 CI에서는 일반 브라우저 묶음에 새 검사가 자동 포함된다.

다음에는 최종 커밋의 필수 CI를 확인한다. 코드·브라우저 검사 통과만으로 일반 자연어 답변 품질이나 회의1차 전체 완료를 주장하지 않는다.
