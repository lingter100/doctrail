# DocTrail 포트폴리오 설명 초안

기준일: 2026-10-31. **사용자 미검수 초안이며 제출 완성본이 아니다.** 아래 구현·실험은 AI 지원 개발과 자동 실행 기록에 근거한다. 사용자 직접 구현·시연·내용 검수 이력으로 바꾸어 읽지 않는다. 회의 요약·자연어 답변의 최종 품질과 전체 포트폴리오 목표는 미완료다. [현재 범위](PROGRESS-OVERVIEW.md), [기여 기록](CONTRIBUTIONS.md).

## 30~60초 소개

> DocTrail은 개발 조직의 문서와 회의 기록에서 접근 가능한 최신 근거를 찾도록 돕는 개인 프로젝트입니다. Java와 React로 문서 권한·수정·검색·원문 확인 흐름을 만들고, Python으로 검색 모델을 비교하고 제한된 임베딩 학습을 실험했습니다. 같은 조건의 개발 평가에서 필수 근거 top-5 회수는 29/59에서 37/59로 늘었지만, 다중 문서 질문은 1/7에서 0/7로 퇴보했습니다. 회의 요약도 인용이 정확해도 핵심을 놓치는 문제가 남았습니다. 설계·구현·자동 검증은 AI가 주도했습니다.

소개 속 수치는 아래 M4 비교에 한정한다. 사용자 직접 검수와 최종 품질 수용은 완료되지 않았다. 지원자가 직접 설명·시연할 수 있는 범위를 확인한 뒤 문장을 확정한다.

## 해결하려는 사용자 문제

신규 구성원이 한국어·영어 문서에서 필요한 운영 절차를 찾더라도, 열 수 없는 문서이거나 수정 전 내용이면 업무에 쓰기 어렵다. 회의의 결정도 적용 조건·시점·원문 근거를 함께 확인해야 한다. DocTrail은 **접근 권한에 맞는 문서를 검색하고, 현재 원문으로 근거를 확인하는 흐름**을 연결한다. 실제 조직 도입이나 사용자 조사로 입증한 수요라는 뜻은 아니다. [프로젝트 소개와 현재 기능](../README.md).

## 서비스와 모델의 책임

| 구성 | 현재 책임 | 분리 이유와 비용 |
| --- | --- | --- |
| Java 21·Spring Boot | 로그인·작업공간·문서 권한, 저장·갱신, 검색 API와 이력 | 서비스 상태와 접근 규칙을 한곳에서 관리한다. Python 모델 경계를 넘을 때 인증·오류·버전 계약이 필요하다. |
| React·TypeScript | 검색 방식 선택, 회의·작업 편집, 원문 근거 이동과 실패 안내 | 모델 결과를 사용자가 확인·수정할 수 있게 한다. 비동기 요청과 화면 상태가 오래된 결과를 다시 보여 주지 않도록 관리해야 한다. |
| Python | 코퍼스·학습·오프라인 평가, 선택적 검색·회의 분석·답변 추론 | 모델 도구를 서비스와 분리한다. worker 장애와 캐시 갱신을 별도로 다뤄야 한다. |

기술 구성은 [README](../README.md), AI 구현과 사용자 요청의 구분은 [CONTRIBUTIONS](CONTRIBUTIONS.md)를 따른다. Java 전환은 사용자가 직접 요청한 사항이며, 세부 구조·구현·자동 검증은 AI 수행 기록이다.

권한을 결과 화면에서만 숨기면 검색·모델 입력이나 캐시에 접근 불가 내용이 남을 수 있다. 문서 수정·재처리·삭제 뒤에는 같은 문서 ID라도 예전 근거와 피드백을 그대로 받아서는 안 된다. 현재 연결 검사에서는 모든 검색 방식의 작업공간·비공개 권한, 수정 후 예전 근거 제거와 오래된 피드백 거부, 같은 본문의 재처리 시 버전 갱신, 삭제된 캐시 문서 제외를 확인했다. 이는 합성 자료를 이용한 실제 로컬 서비스 검사이며 보안 감사나 실사용자 검증은 아니다. [운영 결과의 checks](../experiments/results/m3-model-service-v1.json).

## 검색 비교와 실제 학습 결과

먼저 M3의 같은 입력 비교에서 필수 근거 top-5 회수는 BM25 **30/59**, E5 **29/59**, 혼합 **27/59**, 혼합+BGE 재정렬 **36/59**였다. 임베딩이나 혼합만으로 자동 개선되지 않았다. 이후 별도 후보 선택 비교는 고정 50후보 구성 변경으로 **36→37/59**, 회복 1개·추가 퇴보 0개였다. 이 비교는 아래 학습 실험과 구분한다. [M3 분석](M3-ANALYSIS.md), [후보 선택 분석](M3-CANDIDATE-ANALYSIS.md).

M4에서는 E5 전체 가중치를 16회 갱신한 저장본과 원래 모델을 **동일한 조건에서 각각 새로 실행**했다. 같은 코퍼스·질문·tokenizer·FP32·512토큰·dense 50후보를 사용했고, BM25나 BGE를 다시 평가한 결과가 아니다. [비교 조건](M4-MAIN-DEV-ANALYSIS.md).

| 지표 | Fresh base | 학습 저장본 | 함께 공개할 결과 |
| --- | ---: | ---: | --- |
| 질문의 모든 필수 근거가 상위 50청크 안에 있음 | 34/59 | 47/59 | 회복 15개·퇴보 2개 |
| 질문의 모든 필수 근거가 상위 5청크 안에 있음 | 29/59 | 37/59 | 회복 14개·퇴보 6개 |
| 다중 문서 질문의 모든 필수 근거 @5 | 1/7 | 0/7 | 이 집단은 퇴보 |

분모 59는 dev 79질문 중 주석상 근거가 있는 질문이다. 여러 필수 근거 중 하나만 찾으면 성공으로 세지 않는다. **AI 작성 라벨·사용자 검수 0개인 dev 결과이며, 최종 test의 내용 검토·모델 평가는 수행하지 않았다.** 학습용 자료와 별도인 dev에서 관측한 예비 개선이지, 답변 정확도·통계적 유의성·새 사용자 질문의 성능을 증명하지 않는다. 기본 검색 모델 채택도 아니다. [고정 공개 결과](../experiments/results/m4-main-dev-v1.json).

M3 재정렬과 M4 학습 저장본이 각각 37/59였다는 이유로 동등한 방법이라고 결론 내리지 않는다. 비교 조건과 실패한 질문이 다르며, M4의 기준은 과거 점수를 가져온 값이 아니라 함께 새로 실행한 base다. 다중 문서 퇴보를 숨기지 않고 후보 회수와 최종 근거 조합을 구분한 점이 핵심 설명 대상이다. [분석과 한계](M4-MAIN-DEV-ANALYSIS.md).

## 회의 기능: 연결한 범위와 남은 품질

회의 텍스트 등록, 로컬 모델 분석, 결정·작업과 원문 근거, 사용자 편집, 명시적인 결정 변경 연결, 일반 문서와의 통합 검색을 구현했다. 자연어 답변 호출·인용 검사·답변 보류·오류 복구 경로도 있지만 **생성형 요약·질의응답의 품질 수용은 완료되지 않았다.** 원문 이동·초점·실패 안내와 좁은 화면 흐름의 기존 검사는 실제 Java/React와 합성 모델 응답을 포함하며, 실제 모델 정확성이나 사용자 외관 검수를 대신하지 않는다. [현재 기능별 상태](PROGRESS-OVERVIEW.md), [회의 결과](MEETINGS-RESULTS.md).

대표적으로 원문 대조 재작성 1회를 추가한 후보에서 인용 위치는 초안 71/71·수정본 70/70으로 일치했지만, 독립 AI 판단의 핵심 충분 요약은 **0/3→0/3**이었다. 선택 근거가 충분히 지원한 주장도 **10/18→10/18**로 같았다. 자기검토는 세 요약 모두 충분하다고 판단했다. 따라서 정확 인용·모델 자기검토·의미적 완전성을 별도로 확인해야 하며, 추가 단계의 품질 개선은 입증하지 못했다. 이 판단도 사람 검수나 완전히 독립적인 외부 평가가 아니다. [공개 판단](../experiments/results/meetings-grounded-summary-review-v3.json), [자기검토 비교와 한계](MEETINGS-SUMMARY-V3-ANALYSIS.md).

최신3B QA 지침 비교에서도 답변4개는 EOS·형식을 통과했지만 별도 AI 내용 수용은 **0/4**, 인용은 **10/10** 원문 일치였다. 필수 내용13개는 충족1·부분4·누락6·오류2였다. 요약4개는 출력·형식 조건을 통과하지 못해 내용 미판정이다. 같은 지침 계열의 미세변형은 종료했고 실패 후보를 서비스에 채택하지 않았다. 이는 반복 개발 자료와 AI 판단의 결과이며 사람 검수·일반 정답률이 아니다. [실제 비교·실패 분석](MEETINGS-LOCAL-QA-CONTROL-RESULTS.md).

현재3B와 새7B를 같은 새6개 자료·질문·입력4,096/출력256토큰·60초 조건으로 실제 비교했다. 형식 유효는3개·4개였지만, 구현·실행과 분리한 AI 판정의 최종 수용은 모두 **0/6**이었다. 입력은 한 사례에서5,134·5,237토큰으로 한도를 초과했고 출력 거절3건은256토큰·stop_type=limit이었다. 형식 유효 출력도 의미 기준에 미달해 모델 크기 변경만의 해결을 주장하지 않는다. 원래 선택 규칙을 유지하며 재실행·같은6개 튜닝 없이 비교를 종료했다. 판정은 모델 대응표 공개 전에 잠갔지만 일부 진행 정보 노출이 있어 완전 블라인드나 사람 검수라고 하지 않는다. [실제 비교와 한계](MEETINGS-FREE-QA-PAIRED-V3-RESULTS.md). 이전 실행 환경 오류·template 수정·정상 중립 실행·CI 성공도 실제 내용 품질과 구분해 보존했다. 새 자료 작성에는 기존 질문516개 고유 해시와 출처 계열 제외 목록을 사용했으며, 해시만으로 의미·번역 중복 전체를 보장하지 않는다. [자료 제외 준비](MEETINGS-FREE-QA-EXCLUSION-PREPARATION.md).

## 운영 근거와 공개 배포의 구분

새 공개 자료를 실제 Java 검색에 연결한 진단에서는 원문 등록·청크·모델 전달의 일치를 확인했지만 필요한 출범 규정이 검색되지 않았다. 모델은 대신 멤버 제명 규정을 인용하고 제안을 확정으로 표현했다. 문서 적중·필수 사실 회수·문장 지원을 구분하고, JSON 형식만 복구해 잘못된 내용을 수용하지 않은 사례다. [실행 결과](../experiments/results/meetings-qa-service-development-v1.json), [원인 분리](../experiments/results/meetings-qa-service-diagnosis-v1.json). 후속 검색 비교는 시작 오류로 아직 결과가 없으므로 개선 성과로 넣지 않는다.

로컬 Java의 합성 자료 백업·복원 12항목은 통과했다. 별도로 CI에서 Maven 장기 정체를 겪어 테스트·fork·step·job의 시간 상한과 제한된 진단 보존을 추가했다. 최신 Linux 정상 경로의 Java 232검사와 진단 업로드는 확인했지만, 원래 정체 원인은 미확정이며 Linux 강제 지연 종료는 미검증이다. [복원 상태](PROGRESS-OVERVIEW.md), [CI 설명](CI-JAVA-DIAGNOSTICS.md), [원격 CI 결과](../experiments/results/java-ci-bounded-source-ci-v1.json).

이 근거는 외부 서비스 배포, 실제 조직 사용, 부하·보안 검증 완료, 비용 절감을 의미하지 않는다. 무료 로컬 조건으로 진행했지만 전력·장비·개발 보조 비용을 측정한 총비용 비교는 없다. 녹음·STT·외부 회의 연동도 현재 완료 범위에 넣지 않는다. [범위와 제한](MEETINGS-RESULTS.md), [현재 진행](PROGRESS-OVERVIEW.md).

[기여 원본](CONTRIBUTIONS.md)을 기준으로, Git 작성자 계정을 사용자가 전 코드를 직접 작성했다는 증거로 삼지 않는다. 제출 전 사용자가 직접 권한 변경·문서 갱신·원문 이동을 시연하고, 위 지표와 실패를 설명하며, 실제로 읽고 판단·수정한 코드와 그 이유를 별도 기록해야 한다. 목표는 요약·답변·권한·화면을 갖춘 서비스의 완성이며, 현재 초안 작성으로 그 목표를 완료 처리하지 않는다.
