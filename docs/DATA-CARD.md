# Kubernetes 문서 검색 데이터 카드 · v1

## 무엇을 재현하는 데이터인가

소규모 개발 조직의 엔지니어가 한·영 기술 문서에서 운영 조건과 명령 사용법을 찾는 상황을 근사한다. 실제 회사 문서, 실제 직원 질문, 사용자 클릭 로그를 수집한 데이터가 아니다. 서비스의 권한·수정·삭제 검사는 별도 합성 시나리오 테스트이며 이 공개 코퍼스의 검색 점수에 포함하지 않는다.

Kubernetes Authors의 [공식 문서 저장소 고정 버전](https://github.com/kubernetes/website/tree/4b10551a8c6f0a3f100356d8fc3c6fb5cfde1448)을 사용했다. 원문은 [저장소 LICENSE](https://github.com/kubernetes/website/blob/4b10551a8c6f0a3f100356d8fc3c6fb5cfde1448/LICENSE)에 따라 CC-BY-4.0으로 표시한다. 코드의 MIT 라이선스를 원문이나 발췌에 적용하지 않는다. 원저작자, 고정 경로, 출처 링크, 정제 변경 사항을 manifest에 보존한다. Kubernetes 프로젝트의 승인·제휴를 뜻하지 않는다.

2026-10-12에 검사 목록을 고정했다. 수집일은 원문 갱신일이 아니다. 원문에서 확인할 수 없는 갱신일은 `null`이다.

약 1,000문서 확보 목표는 미달이다. 2,287개를 검토한 것과 1,000개를 확보한 것은 다르다. 미해결 외부 포함 파일을 삭제한 불완전 본문으로 수량을 채우지 않았다. 제외 원인은 [품질 보고서](../data/manifests/kubernetes-v1-quality.json)에 전부 보존한다. 대표적으로 자동 생성 대형 참조·용어 조각 1,105개, 범위 밖 124개, 짧은 탐색 페이지·조각 111개, 미해결 include 182개, 자동 feature-state 116개가 제외됐다. 문서마다 처음 발견한 제외 사유를 집계하므로 한 문서의 모든 결함 수를 뜻하지 않는다.

선정 주제는 reference 176개, concepts 79개, tasks 56개, tutorials 2개다. 파서가 처리하기 쉬운 참조 문서 쪽으로 편향되어 있다. 짧은 kubectl 명령 참조도 일부 포함되며 공통 설명 때문에 큰 중복 그룹이 생겼다. 최대 연결 그룹은 23개다. 향후 include·버전 참조를 올바르게 해석하는 새 파서와 새 코퍼스 버전으로 절차 문서의 비율을 늘릴 필요가 있다. 기존 v1 분할·평가 결과를 덮어쓰지 않는다.

## 정제와 무결성

`hugo-strict-v1`은 YAML metadata를 본문에서 제거하고 제목을 별도로 유지한다. 주석은 제거하고 Markdown·코드 본문은 보존한다. 허용한 안내 상자·capture wrapper는 안쪽 내용을 유지하고, heading은 해시로 고정한 언어 파일에서 해석한다. 명시된 버전·상태의 feature-state만 텍스트로 풀고 외부 lookup은 제외한다. 내용이 생기는 지원하지 않는 구문은 문서 전체를 격리한다.

원본 Git blob 식별자와 SHA-256, 정제 결과 SHA-256, 정제 재실행 결과를 모두 확인한다. 제목과 문서 정체성도 확인한다. 로더는 중복 연결과 분할을 다시 계산한다. 캐시나 manifest의 분할을 조용히 바꾸면 실패한다. 원문·정제 본문은 Git에서 제외하고 해시와 수집 방법만 공개한다.

같은 canonical 경로의 번역, 정제 결과 완전 중복, 5-token shingle Jaccard 0.85 이상을 먼저 연결한다. 연결 그룹 해시의 60/20/20 구간으로 분할했다. 이는 균등·층화 추출이 아니므로 실제 문서·언어 비율이 목표와 다르다. 입력 순서를 바꾼 재실행에는 안정적이지만 문서를 추가하여 연결 그룹이 바뀌면 분할도 바뀔 수 있다. v1을 동결하고 변경은 새 버전에서 수행한다.

이 검사는 의미가 비슷하지만 표현이 다른 문서, 다른 경로의 번역, 짧은 공통 절을 모두 탐지하지 못한다. 자동 누출 검사 통과를 완전한 의미적 독립성의 증거로 쓰지 않는다. M1에 이미 사용한 4개 계열 중 선정된 ConfigMap 두 번역본은 smoke로 남겨 새 holdout으로 쓰지 않는다.

## 질문·라벨 사용 경계

질문은 문서 분할 고정 후 AI가 실제 본문을 읽고 작성하는 후보다. 작성 지침, 작업별 허용 문서, 모델 설정과 원본 초안을 `data/evaluation/generation/`에 기록한다. 추론 API의 seed·응답을 재실행한 데이터 생성 파이프라인은 아니다. 저장한 초안을 근거 위치가 있는 JSONL로 변환하고 검증하는 과정은 결정적으로 재실행할 수 있다.

최초 dev 80개와 test 후보 160개, 총 240개를 작성했다. 평가 실행 전 AI 의미 검토에서 다중 문서 조건이 불확실한 `m2-dev-055`를 제외한 dev v1.1(79개)을 만들었다. 원본과 제외 이유·입력 해시를 보존했다. 현재 활성 239개는 단일 문서 156개, 다중 문서 23개, 근거 없음 36개, 필수 조건 불명확 24개이며 언어는 KO 159 / EN 80이다. 참고 답안은 AI 라벨링 보조 자료이고 실제 서비스의 답변 생성 기능이 아니다. 근거는 문서 제목·청크 ID가 아닌 정제 본문의 정확한 구간에 연결한다.

하나의 필수 사실에 대한 대체 구절은 OR, 서로 다른 필수 사실은 AND로 평가한다. 번역이라는 이유만으로 대체 정답을 자동 등록하지 않는다. 모든 관련 문서를 완전히 라벨한 것은 아니므로 알려진 정답 근거의 회수 지표로 해석한다. AI가 만든 음성·모호성 판정 역시 잠정적이다.

AI 작성, 정확한 span·분할 자동 검사, 사용자 검수는 각각 별도 상태다. 사용자 검수는 아직 0개다. 검수 HTML은 사람이 실제 결정한 파일만 받아 별도 기록하며, 질문 원본을 승인 상태로 바꿔 과거를 지우지 않는다. M2 평가기는 test 실행을 항상 거부한다. 공개 질문 후보라서 완전한 블라인드 시험이라고 주장하지 않는다.

## 적절하지 않은 해석

- Kubernetes 문서 한 도메인에서 얻은 점수를 사내 문서 전반이나 다른 회사의 실사용 품질로 일반화하지 않는다.
- 문서 적중을 답변 정확도나 근거 충분성으로 바꾸어 표현하지 않는다.
- AI의 구조 검사와 원문 대조를 전문가·사용자 검수라고 쓰지 않는다.
- 문서의 갱신일이 없으므로 이 코퍼스로 최신성 충돌 해결을 검증했다고 하지 않는다.
- 문서 수·청크 수·번역 수·독립 계열 수를 서로 바꾸어 인용하지 않는다.
- 학습용 문서를 예약한 것과 모델을 학습한 것을 구분한다.
