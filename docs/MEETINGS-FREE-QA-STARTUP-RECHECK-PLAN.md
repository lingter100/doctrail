# 수정 후 시작 진단의 분리

후속 결과: 아래 설계의 v2는 실제1회 실행을 완료했고 health·props 검증·정상 종료·전체 보존 확인을 통과했다. [실측](MEETINGS-FREE-QA-STARTUP-V2-RESULTS.md)의 CLI19.906초·생성0은 시작 검증 결과이며 QA 품질 수용은 아니다. 실행 당시에는 Git8846의 이 계획 원문 사본을 고정했고, 이 후속 안내는 종료 후 추가했다.

2026-10-29. template 표현 수정 커밋df87c70의 양쪽 필수 CI를 확인한 뒤 적용하는 다음 설계다. [원래 진단](MEETINGS-FREE-QA-STARTUP-RESULTS.md)은 실패·once 소비 상태로 보존한다. 이 문서는 새 실제 실행 결과나 등록이 아니다.

기존 시작 CLI의 ID만 `meeting-free-qa-startup-v2`로 올려 새 고정 신뢰 경로를 사용한다. 같은 실행기·명령·스키마·모델·제한·공유 실행 잠금을 유지하고 v1 통제 파일을 덮지 않는다. 소스와 기존 시작 테스트2파일에서 v2 경로, v1 거부, v1 파일 보존, v2 자체 once의 반복 거부를 검증한다. 선택 가능한 신뢰 경로나 새 실행 프레임워크는 만들지 않는다.

원래 monitor는 종료 기록을 본 직후 이미 알려진 conhost가 남아 있는 순간에 최종화했다. 새 사본은 종료 후 새 프로세스를 찾지 않고, 이미 기록한 PID/생성 시각만 기존 시작 시각+300초 한도 안에서 부재가 확인될 때까지 관찰한다. 새 300초를 주거나 전역 검색·종료 명령·모델 재시도를 하지 않는다. 조회 불가 오류는 이후 사라져도 오류로 유지한다. 초기30초 대기와 신원 검사는 그대로 두고 가상 시간·프로세스로 지연 종료·계속 잔류·PID 재사용·조회 불가·누락·마감 직전 종료를 검사한다. 기존 wrapper·종료 기록 대조를 재사용한다.

다음 자료 고정 전에는 문서를 포함한 정확한 변경 금지 목록을 모든 담당자에게 제공한다. 가능하면 실행 계획은 변경되지 않는 사본으로 연결하고 원문 commit/path/hash를 남긴다. 살아 있는 문서가 다른 참조에 포함돼 있으면 그 문서도 계속 고정 대상이다. 진행 상태와 CI 설명은 이 목록 밖에만 쓴다. 이전 실패나 보존 목록은 고치지 않는다.

순서는 좁은 구현·모의 검사 → 독립 검토 → 게시 소스 CI → 별도 v2 등록 후보·검토·설치·공식 검증 → 단독 실제 실행 배정이다. 아직 새 신뢰·등록·once·실제 조회·모델 실행은 없다. 준비·설정 조회가 성공해도 토큰화·생성·회의 답변 품질을 통과한 것이 아니다.

설계는 같은 Astra xhigh가 수행했고 부모가 결정 기록2참조와 근거를 확인했다. 원본 영수증 SHA는 `da0d10cd9b1aa44a7a333ac315cf0d094eb3acb1d277e31914d5565112e3f174`다.

## 구현 검증 상태

시작 소스·기존 시작 테스트2파일과 새 로컬 관찰기 사본을 구현했다. 신규 등록 검사5개와 이를 포함한 QA/시작 진단278개(31.39초), 별도 관찰 모의14개와 Ruff가 통과했다. 관찰 모의 검사는 공개 CI에 포함된 검사로 세지 않는다. [검증 기록](../experiments/results/meetings-free-qa-startup-v2-implementation-v1.json)의 독립 검토는 공개 소스2를 차단0·권고0으로 수용했다.

같은 검토에서 로컬 관찰기가 제한 시간 이후 부재를 성공으로 판단하는 경계를 순수3사례로 확인했다. 원래 통과·실패를 보존하고 조회 전후 마감 확인과 오류 유지 기능만 새 사본에서 보완한다. 승인된 공개 소스의 CI와 로컬 관찰기 보완은 병행하되, 최종 검토와 새 CI 모두 완료하기 전에는 실제 등록이나 실행을 진행하지 않는다.
