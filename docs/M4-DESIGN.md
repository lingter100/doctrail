# M4 · Train 데이터와 첫 학습 실험의 경계

기준일: 2026-10-12. **첫 학습 가설은 E5의 후보 회수 개선이다. 먼저 train 계열의 작은 질문 묶음과 음성 후보 검토 경로를 만들고, 품질 조건을 모두 통과한 뒤 한 번의 제한된 학습을 수행한다.** 이 문서는 학습 성공이나 검색 개선 결과가 아니다. 현재 작성 질문은 AI 초안이며 사용자 검수는 0개다.

실행 계약은 [m4-plan-v1.json](../data/training/m4-plan-v1.json), 질문 작성 지침은 [protocol-v1.md](../data/training/generation/protocol-v1.md)다. 계획·지침을 먼저 해시로 고정하고, 문서 목록과 로컬 author pack을 그 계획에 연결한다. 계획의 `training_readiness` 값은 이미 통과한 결과가 아니라 통과해야 하는 조건이다. 실제 상태는 실행 보고서와 [STATUS](STATUS.md)에 기록한다.

## 1. 왜 E5를 먼저 검토하는가

[동결 M3 후속 분석](M3-CANDIDATE-ANALYSIS.md)의 최종 실패 22개 중 21개는 필수 근거가 후보에 부족했고, 1개는 충분한 후보가 있었으나 최종 순위에서 실패했다. 이 집계로 첫 가설을 정한다. 이번 데이터 작성에서는 M2 dev/test 질문·정답 파일을 열거나 새로운 dev 점수를 얻어 학습 질문을 고르지 않는다.

리랭커는 입력 후보 밖의 근거를 새로 가져올 수 없다. 따라서 BGE를 먼저 학습하는 것보다 E5 후보 검색의 도메인 표현과 언어 대응을 검토하는 편이 관찰한 병목에 가깝다. 단, 21개에는 청크 경계로 표현할 수 없는 경우도 포함되므로 전부 임베딩 학습으로 해결된다고 해석하지 않는다. 후보 수·RRF 정책·청크·리랭커를 함께 바꾸지 않는다.

E5 기술 보고서는 대조 학습 후 라벨 데이터와 채굴한 음성 예시를 이용한 미세조정을 설명한다. 이는 검색용 학습 목적을 고르는 근거이며, 현재의 작은 Kubernetes 데이터나 RTX 4050에서 성능이 좋아진다는 증거는 아니다. [Multilingual E5 기술 보고서](https://arxiv.org/html/2402.05672v1)

| 선택 | 이번 판단 | 남는 위험 |
|---|---|---|
| E5 후보 생성 모델 | 첫 제한 실험의 조건부 선택 | 작은 AI 라벨 묶음의 과적합, 학습되지 않은 주제·언어의 회수 저하 |
| BGE 재정렬 모델 | 고정 | 후보 생성 개선 뒤에도 남는 순위 오류를 별도로 평가해야 함 |
| 청크·후보 예산 조정 | 고정 | 현재 경계 실패를 이 학습의 분모에서 지우지 못함 |
| 생성 모델 학습·QA | 보류 | 검색 근거와 데이터 품질을 확인하기 전 범위를 늘리지 않음 |

## 2. 원래 train 안에서 다시 나누기

원래 데이터의 train 180문서·128계열만 질문 작성과 학습 후보로 사용한다. Manifest의 `family_id`는 canonical 경로 하나가 아니라 번역·정확 중복·유사 중복의 연결 그룹이다. 이 그룹을 통째로 유지한다. 기존 검증 로더는 동결 코퍼스 전체의 해시·정제·그룹을 내부적으로 다시 검사하며, 그 직후 train만 남긴다. 이후 author pack·청크·음성 채굴에는 dev/test/smoke 본문이 들어가지 않는다. 이는 평가 질문을 읽는 작업과 구분한다.

분할은 `sha256("doctrail-m4-train-v1:" + family_id)`의 앞 16자리 16진수를 정수로 바꾼 뒤 100으로 나눈 나머지를 쓴다. 0~79는 `fit`, 80~99는 `calibration`이다. 그룹을 특정 칸으로 보내기 위한 seed 탐색이나 수동 이동은 하지 않는다.

| 구분 | 문서 | 연결 그룹 | 기존 방식 청크 | EN / KO 문서 |
|---|---:|---:|---:|---:|
| Fit | 150 | 103 | 1,643 | 111 / 39 |
| Calibration | 30 | 25 | 553 | 24 / 6 |

80/20은 해시 구간 비율이며 문서·언어 비율을 보장하지 않는다. Calibration 문서와 질문은 gradient와 fit 음성 채굴에서 제외한다. 이후 보정 평가의 검색 대상은 원래 train 전체의 고정 청크로 지정해 같은 조건으로 전후를 비교한다. Calibration은 이미 train으로 예약한 공개 자료에서 만든 내부 검증 묶음이며 새로운 비공개 최종 시험이 아니다.

기존 연결 그룹은 의미 중복 전체를 탐지하지 못한다. 질문의 정확 중복·정규화한 문자 trigram Jaccard 0.8 이상은 별도 격리하며, 번역·말바꾸기는 같은 `question_family_id`로 관리한다. 자동 검사만으로 모든 의미 누출이 없다고 주장하지 않는다.

## 3. 수량보다 독립 의도와 실제 근거

첫 목표는 fit 64질문/16계열, calibration 16질문/4계열이며 계열당 최대 4질문이다. 질문 결과를 보기 전에 주제와 길이를 이용한 결정적 문서 선택 목록을 고정한다. `concepts`, `tasks`, `reference`를 포함하고 짧은 명령 참조만으로 채우지 않는다. 전체에서 한국어 질문·영어 근거 16개 이상, 영어 질문 8개 이상을 목표로 한다. 언어가 다른 주석이라는 사실은 다른 언어에서만 답할 수 있다는 완전한 관련성 판정을 뜻하지 않는다.

작성자는 배정한 partition의 local pack만 읽는다. 각 행에는 독립 의도, 질문 언어·유형, 원문 근거, 작성 근거, 참고 답안, pack 해시와 실제 도구가 수락한 모델·reasoning 설정을 보존한다. 원문은 Kubernetes Authors의 실제 공개 자료지만 질문·참고 답안은 AI 작성이다. AI 작성, 구조·원문 자동 검사, 별도 AI 의미 검토, 실제 사용자 검수를 각각 구분한다.

원문 `quote`와 0부터 시작하는 `occurrence`로 정확한 문자 구간을 컴파일한다. 문서 해시와 근거 전체를 담는 기존 청크 ID·본문 해시를 보존하며, 학습 전에 E5의 실제 입력 토큰에 근거가 남아 있는지 따로 검사한다. 첫 compiler는 질문당 한 근거 항목만 지원한다. 계획에 설명한 같은 사실의 대안 OR 표현은 향후 확장 계약이며 이번 pilot에서 다중 항목을 허용한 결과가 아니다. 다중 문서 AND 질문은 범위 밖이다.

보정 초안은 **14질문/4계열(한국어 9, 영어 5)**이다. Kubernetes 라벨, macOS Bash 자동완성, Linux 보안 제약 문서에는 각각 네 개의 독립 질문을 작성했다. Dockershim 문서는 링크 모음이므로 공식 제거 제안과 피드백 창구를 찾는 두 탐색 질문만 작성했다. 링크 대상의 설계·운영 내용을 읽은 것처럼 질문을 만들거나 날짜·제목 암기로 두 칸을 채우지 않았다. 목표 16개보다 2개 부족하며 계획의 통과 조건을 낮추지 않는다. 초안의 14개 인용은 모두 실제 본문에 한 번 존재함을 확인했지만, 이것이 의미 검토나 학습 준비 완료를 뜻하지 않는다.

원문·전체 author pack은 로컬 캐시로 남기고 Git에 올리지 않는다. 공개할 질문의 짧은 인용·출처는 CC-BY-4.0 원문에서 파생된 것으로 표시한다. 코드의 MIT 라이선스로 원문 인용을 재표시하지 않는다. 저장한 초안의 재컴파일은 재현 가능하지만 AI 생성 호출 자체를 같은 결과로 재현할 수 있다는 뜻은 아니다.

## 4. 음성 후보를 곧바로 음성 라벨로 쓰지 않기

첫 채굴은 현재 BM25의 상위 20청크만 사용한다. Fit 질문은 fit 청크에서, calibration 질문은 calibration 청크에서만 채굴한다. BM25 순위를 그대로 남기며 점수 임계값이나 E5/BGE 점수로 의미적 음성 여부를 확정하지 않는다.

후보는 양성 청크·근거와 겹치는 구간, 같은 코퍼스 계열, 동일 본문, 양성 본문과 높은 어휘 유사성을 보이면 격리한다. Compiler가 사용하는 청크 중복 검사는 단어 trigram Jaccard 0.8이다. 이것은 질문의 문자 trigram 중복 검사와 별개다. 필터를 통과한 후보도 기본 라벨은 `unknown`이며 아직 학습 음성이 아니다.

별도 검토자는 질문, 양성 근거의 문맥, 음성 후보의 전체 청크를 함께 읽고 `negative`, `relevant`, `ambiguous`, `unknown`으로 구분한다. `negative`는 **질문이 요청한 구체적 사실을 후보가 지지하지 않는다는 설명**이 있을 때만 부여한다. 같은 주제라는 이유나 양성 목록에 없다는 이유만으로 음성을 만들지 않는다. 대체 답일 가능성, 불충분한 조건, 번역·버전 관계가 의심되면 격리한다. 검토자·판정 이유·질문 및 청크 해시를 별도 영수증에 남긴다.

첫 학습은 각 fit 질문에 검토된 명시적 음성 두 개가 있어야 한다. 미검토·모호한 후보는 loss에 들어가지 않으며, 배치의 다른 질문에 딸린 문서를 자동 음성으로 쓰지 않는다. 자동 구조 검사가 통과한 양성도 독립 AI 의미 검토와 tokenizer 검사가 끝나기 전에는 학습 준비 상태가 아니다. 사람이 확인하지 않은 상태는 계속 `human_review: pending`이다.

## 5. 한 번의 제한된 학습안

데이터 조건이 충족됐을 때 고정 E5-small revision에서 전체 가중치 AdamW 학습을 먼저 시험한다. 기존 잠금의 PyTorch·Transformers로 표현할 수 있는 작은 실험을 택해 M3의 `uv.lock`과 모델 snapshot을 보존한다. Full-weight가 LoRA보다 우수하거나 6GB에 이미 들어갔다는 주장은 하지 않는다.

E5 공식 사용 계약인 `query: ` / `passage: `, attention mask를 반영한 평균 pooling, L2 정규화, 512토큰을 유지한다. 한국어에도 동일한 영어 접두사를 붙인다. [고정 E5 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small/blob/614241f622f53c4eeff9890bdc4f31cfecc418b3/README.md)

첫 목적함수는 질문마다 양성 한 개와 명시적 음성 두 개의 cosine 점수를 temperature 0.01로 나누어 계산하는 InfoNCE다. 한 질문의 분모는 이 세 문서뿐이다. 여러 양성 포함 청크가 있으면 학습 실행기에서 질문별 한 청크를 선택하는 결정적 규칙을 동결해야 하며, 동일 질문을 중복 청크 수만큼 더 자주 학습하지 않는다. 이 단순한 목적함수는 E5 원 학습의 대규모 in-batch negative·교차 인코더 증류를 재현한 것이 아니다.

| 항목 | 고정 제안 |
|---|---|
| Seed / epoch / 상한 | 20261012 / 2 / optimizer 16 step |
| Microbatch / 누적 | 질문 2개 / 4 microstep |
| Optimizer | AdamW, learning rate 1e-5, weight decay 0.01 |
| Warmup / clip | optimizer 1 step / max norm 1.0 |
| Forward / 상태 | FP16 autocast, FP32 parameter·optimizer, GradScaler |
| 메모리 절약 | gradient checkpointing, 동적 padding |
| 비교 시 추론 | 기존 E5와 같은 FP32·고정 tokenizer·청크 |
| Checkpoint 선택 | 마지막 하나만, best epoch 탐색 없음 |

Gradient accumulation은 업데이트에 반영하는 질문 수를 늘려도 공유 in-batch 음성 풀을 자동으로 늘리지 않는다. GradCache는 이를 위한 별도 방법이지만 이번 목적함수·환경에는 넣지 않는다. 중복을 뺀 배치도 알려지지 않은 관련 문서가 음성에 섞이지 않는다고 보장하지 못한다. [Sentence Transformers loss 문서](https://sbert.net/docs/package_reference/sentence_transformer/losses.html)

LoRA는 작은 추가 행렬만 학습하는 대안이며 지원되는 target module을 실제 모델 구조에 맞춰 지정해야 한다. 하지만 학습 파라미터 감소가 forward activation 제거를 뜻하지 않고, 현재 잠금에 PEFT가 없으며, 이 데이터에서의 품질 차이도 모른다. OOM 또는 과적합을 관찰했다면 별도 환경·잠금·새 계획 버전으로 비교할 후보다. 이번 실행 중 몰래 의존성을 추가하거나 full-weight에서 LoRA로 전환하지 않는다. [PEFT LoRA 문서](https://huggingface.co/docs/peft/en/package_reference/lora)

## 6. 로컬 6GB 가능성은 실제 backward로 확인

M3 순전파의 GPU 메모리 기록은 학습 가능성 검증이 아니다. Full-weight AdamW는 모델 가중치 외에 gradient·optimizer moments·활성값을 보유하므로 추론 기록만으로 필요한 VRAM을 확정할 수 없다. 먼저 단일 optimizer step을 실제로 수행하는 자원 probe를 한다. probe도 실제 가중치 업데이트지만 품질 학습 결과와 분리하고, 본 실행 전 원래 checkpoint·optimizer·seed로 다시 시작한다.

FP16·checkpointing·고정 microbatch로 peak allocated 5,376MiB 이하인지, 유한 loss/gradient인지, 실제 trainable parameter와 optimizer가 의도대로 갱신되는지 확인한다. allocated/reserved, 장치 메모리 상태, CPU RSS, elapsed, 실제 precision, 토큰 길이와 OOM을 함께 기록한다. Allocator 상한 통과를 장치 전체 메모리 보장으로 표현하지 않는다.

OOM·비정상 gradient·자원 상한 초과 시 실패를 보존하고 중단한다. CPU·클라우드 전환, 자동 재시도, batch·길이 축소, 유료 GPU 사용을 하지 않는다. 새 설정이 필요하면 계획 버전을 바꾸고 실패 이유를 먼저 기록한다. 기존 모델 서버·다른 학습이 실행 중이면 중복 작업을 시작하지 않는다.

## 7. 평가와 채택을 분리

학습 전 base checkpoint와 학습 후 terminal checkpoint를 동일한 calibration 질문·원래 train 2,196청크로 비교한다. 주 지표는 E5 50후보에서 주석 근거 전체가 포함되는 질문 수다. 근거 @5, MRR@10, 문서 적중, 언어·주석상 교차 언어, 질문별 개선/퇴보, 잘림·메모리·지연을 함께 기록한다. 이들은 AI 라벨에 대한 예비 회수 지표다.

진행 기준은 calibration 후보 회수가 한 질문 이상 증가하고 근거 @5가 감소하지 않는 것이다. 통계적 유의성이나 일반 우위를 보장하는 기준이 아니라 작은 실험을 무한 반복하지 않기 위한 보수적인 내부 선택 규칙이다. Tie·퇴보면 원 모델을 유지하고 불리한 결과도 보존한다. 중간 epoch·seed·음성 점수·질문 삭제로 기준을 맞추지 않는다.

데이터, 코드, 체크포인트, 평가 설정이 고정된 뒤에만 기존 main dev를 한 번 평가한다. 그 결과로 이 실행을 재튜닝하지 않는다. 기존 test 개방 조건과 잠금은 유지한다. 원래 M2/M3의 코퍼스·질문·결과·실행 소스·모델·잠금 파일은 덮어쓰지 않는다.

작은 한 번의 실행은 roadmap의 여러 seed·데이터 양·음성 품질 ablation 전체를 완료하지 못한다. 데이터 준비, 실제 학습 완료, 검색 개선, Java 운영 채택을 각각 보고한다. 채택에는 별도의 서버 세션·ACL·revision/delete·검색/근거/history/feedback·실제 HTTP·브라우저 회귀와 원격 CI 확인이 필요하다. 이 문서의 Python 실험 설계를 Java 서비스 성능으로 소개하지 않는다.

## 8. 이번 묶음이 끝났다고 볼 수 있는 범위

이번에는 동결된 train 내부 분할과 작성 지침, 출처가 있는 질문 초안, 정확한 span·청크 연결, 음성 후보와 격리 사유, 결정적 replay 경로를 산출한다. 보정 질문 수 미달, 의미·음성 검토, tokenizer 검증, 실제 자원 probe가 남으면 `training_ready=false`로 유지한다. 학습 파일 하나를 만들었다는 이유로 가중치를 갱신하지 않는다.

다음 작업은 부족한 독립 보정 질문의 수집을 새 선택 버전으로 기록하고, 양성 및 음성의 독립 의미 검토와 tokenizer 근거 보존 검사를 수행하는 것이다. 부족한 사례를 얻을 수 없다면 목표와 한계를 다시 설계하되 현재 계획의 통과 기록을 소급 변경하지 않는다. 모든 조건이 통과된 후에만 자원 probe와 제한 학습에 들어간다.
