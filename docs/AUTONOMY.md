## 실제 설정

현재 채팅에 `DocTrail 개발 이어가기` 후속 실행을 등록했다. 앱의 자동화 도구가 `ACTIVE` 상태와 ID `doctrail`을 반환했고 로컬 설정에서도 매시간 실행과 이 채팅 연결을 확인했다. 2026-10-12 05:06:57 UTC에 이 ID의 실제 heartbeat 메시지를 받아 첫 예약 실행 시작을 확인했다. 시작 확인과 작업 완료는 구분하며, 해당 실행의 검증 결과는 STATUS에 기록한다. 이름·간격 변경이나 중단은 앱의 예약 작업에서 관리할 수 있다.

이 설정은 사용자 PC의 작업 폴더에서 이어가는 실행이다. PC와 앱이 실행 중이어야 하며 꺼진 PC를 대신하는 클라우드 서버를 만들지 않았다. 앱·계정 사용 한도·네트워크·도구 오류 때문에 예약 실행이 실패할 수 있으므로 무중단 진행을 보장하지 않는다. 근거: [OpenAI 공식 예약 작업 문서](https://learn.chatgpt.com/docs/automations?surface=app).

## 실행마다 할 일

1. AGENTS와 STATUS·DECISIONS·CONTRIBUTIONS, Git 상태·진행 중 프로세스를 읽는다. 이미 진행 중인 실험을 중복 실행하거나 타 작업의 파일을 덮어쓰지 않는다.
2. 다음의 의미 있는 작업 묶음을 구현·검증·문서화한다. 실패한 실험도 보존한다. 같은 대기 상태를 반복 보고하지 않는다.
3. 검증된 범위만 짧은 기능 브랜치·Conventional Commits·PR·필수 CI를 거쳐 사용자 계정으로 main에 통합한다. 검증 중인 변경을 main에 넣지 않는다.
4. 단계 완료, 새로운 실패, 사용자 판단이 필요한 내용만 알린다. 완료할 일이 남았는데 단순히 다음 지시를 기다리지 않는다.
5. 승인된 로드맵이 모두 완료되면 완료 사실을 알리고 후속 실행을 종료한다. 사용자가 중단을 요청하면 따른다.

## 자동으로 대신할 수 없는 것

- 서비스 인터넷 공개는 검토할 결과를 먼저 준비하고 별도 승인을 받는다. 공개 GitHub 소스 생성·푸시는 이미 승인된 범위다. 유료 API·GPU 임대·클라우드는 최신 무료 전용 결정에 따라 보류하며 승인 요청을 반복하지 않는다.
- 사용자 질문 검수·경험·피드백: AI가 사용자로 가장해 체크하거나 승인하지 않는다. 사용자 검수가 없어도 예비 개발 실험은 계속할 수 있으나 최종 평가 개방 조건을 우회하지 않는다.
- 개발 모델 설정: 도구가 수락한 서브에이전트 설정만 기록한다. 부모 채팅의 모델 설정을 바꿨다고 주장하지 않는다.

현재는 M3 첫 오프라인 비교를 마쳤다. 이후 사용자의 Java 전환 요청을 반영해 후속 실행의 프롬프트도 갱신했으며 ACTIVE 상태는 유지했다. 서비스 백엔드는 Java 21 + Spring Boot로 개발하고 Python은 데이터·학습·오프라인 평가에 사용한다. 기존 Python 서비스와 동결 결과를 보존한다.

Java의 계약·실제 HTTP 검증 이후 실패 원인별 후속 비교와 새 검색 모델의 권한·문서 변경 반영, 원인에 맞춘 학습, 근거 기반 답변, 운영·포트폴리오 정리 순서로 진행한다. 실행 결과가 나쁘면 원인을 확인하고 비교를 추가하되, 끝없이 설정을 고쳐 dev에만 맞추지 않는다.

Java 전환과 후보 선택 후속 비교를 마친 뒤 사용자가 React 전환 제안을 승인했다. 이 작업에서는 React + TypeScript + Vite로 기존 화면·API 흐름을 보존하고 실제 Java 브라우저 회귀를 먼저 검증한다. 이후에는 기존 검색 모델 연결 로드맵을 이어가며, 프런트엔드 전환을 이유로 동결 실험을 다시 수행하지 않는다.
