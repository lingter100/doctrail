# C1 실제 실행과 실패 분석

실행 소스 `82b0fff`, 자료·실행 계획 `45810d2`. 현재 상태: **구조 오류로 calibration 중단, 후보 선택 실패**. Phase 1 자연어 답변 완료나 서비스 채택이 아니다.

## 실측

| 구간 | 실제 요청 | native 생성 | 결과 |
|---|---:|---:|---|
| 중립 protocol | 2 | 4 | 답변 1·근거 부족 보류 1, 기본 구조·자원 검사 통과 |
| calibration | 계획 8 중 4 시도 | 8 | 앞의 3건 구조 수용, 4번째 검토 형식 오류로 중단 |
| calibration 나머지 | 0 | 0 | 미실행 4건 |
| validation | 작성 0 | 0 | 선행 게이트 실패로 열지 않음 |

총 native 생성은 12회다. D1/V1 수정 경로는 한 번도 실행되지 않았다. 재시도·분석 호출·warmup·유료 호출은 0이다. 중립의 native 작업 시간은 65.359초, calibration은 402.782초이며 시작·종료 처리도 포함한다. Java HTTP나 동시 서비스 응답 시간이 아니다.

calibration의 요청별 Python 어댑터 경과 시간은 69.094 / 79.328 / 119.032 / 73.266초다. 각 요청은 120초 안에 끝났지만 3번째는 여유가 약 1초뿐이다. 더 비싼 4단계 수정의 실행 가능성을 검증한 것으로 해석하지 않는다.

calibration의 실제 8개 생성은 입력 1,195~2,119 tokens, 출력 99~285 tokens이며 모두 EOS로 종료했다. cache_n은 모두 0이다. native가 반환한 생성 속도는 약 5.01~5.54 token/s, prompt 처리 시간은 6.43~17.44초, 생성 시간은 19.54~53.15초다. 문서 길이뿐 아니라 생성 시간도 병목이라는 관찰이며 다른 실행 설정의 원인 비교는 아직 하지 않았다.

## 실패 원인과 해석

네 번째 초안에는 주장 2개가 있었으나 검토 JSON의 `claim_checks`에는 주장 0만 있었다. 주장 1에 대한 검토가 빠졌다. JSON과 DTO는 유효했지만 모든 주장이 정확히 한 번 검토되어야 한다는 교차 필드 검사가 `generation_invalid_review`로 차단했다. 모델이 빠뜨린 판단을 코드가 대신 채우거나 잘못된 검토를 성공으로 처리하지 않았다.

기존 문법은 항목의 형식과 인덱스 범위는 제한하지만 목록이 모든 인덱스를 포함하도록 강제하지 않았다. 따라서 문법의 구조 제약을 강화하는 후속 구현이 가능하다. 이 수정 자체가 의미상 맞는 판단이나 전체 답변 완전성을 보장하지는 않는다.

완료형 검토 도구를 우회하지 않고 별도의 **사후 부분 실패 분석** 묶음으로 첫 4문항의 초안·최종 상태 8개만 익명화해 독립 의미 검토했다. 남은 4개 질문·정답은 검토 묶음에 넣지 않았다. 이 검토는 중단된 선택 게이트를 통과시키지 못한다.

## 잠근 사후 의미 판정

검토자는 역할 대응표를 보기 전에 [8개 판정](../experiments/results/meetings-c1-calibration-partial-judgments-v1.json)을 고정했다. 그 후 대응표로 집계한 [요약](../experiments/results/meetings-c1-calibration-partial-review-v1.json)은 다음과 같다. 이는 **4문항의 부분 결과**이며 전체 calibration 또는 운영 정확도가 아니다.

| 검사 | D0 초안 | C1 최종 |
|---|---:|---:|
| 완전 적합 | 0/4 | 0/4 |
| 원문 문자열·좌표가 정확한 인용 | 31/31 | 27/27 |
| 모든 주장에 대한 선택 인용의 충분한 지지 | 0/4 | 0/4 |
| 답변 내용에 필수 항목 포함 | 3/4 | 3/4 |
| 오류 응답 | 0 | 1 |

개선은 0이며 정답→오답 퇴행도 0이지만 C1에는 새로운 오류 응답 1개가 있으므로 결과가 완전히 같다고 말하지 않는다. 인용 문자열이 정확해도 필수 조건·문장 후반·결론이 선택 구간 밖에 남거나 추가 열거·비교 사실에 대한 인용이 없었다. 원문의 한정 조건을 넓히는 오류도 있었다. 근거 부족 질문에 D0는 부분 답변을 했고 C1은 정상 보류 대신 오류를 반환했다.

이 결과는 형식만 보강하는 후속 후보의 충분한 근거가 아니다. 생성 전에 근거 단위가 조건·결론을 보존하도록 구성하는 접근과 그 한계를 별도로 설계한다. 인용을 무조건 넓혀 오답을 숨기거나 평가 기준을 완화하지 않는다. 같은 네 질문으로 수정본을 비교하지 않는다.

사용자 검수는 0이다. 두 정책의 같은 문장과 오류 모양으로 역할을 추측할 수 있는 한계, 동일 기반 AI 검토라는 한계가 남는다. 검토 완료 후 공개한 [shuffle seed·재현 정보](../experiments/results/meetings-c1-calibration-partial-audit-repro-v1.json)로 새 부분 감사 도구를 재생했고 입력·대응표·영수증 3개가 원본과 바이트 단위로 일치했다. 이 재생에는 모델 호출이 없다.

## 무결성·운영 기록

- 원본 [중립](../experiments/results/meetings-c1-neutral-v1.json)과 [calibration](../experiments/results/meetings-c1-calibration-v1.json)을 바이트 그대로 보존한다.
- calibration 보고서의 `sources_unchanged`, `resources_passed`, `security_passed`는 조기 실패 때문에 초기 false로 남았다. 소스 변경이나 보안 유출이 발생했다는 진단으로 쓰지 않는다. 별도 종료 후 검사에서 계획의 92파일 해시가 모두 일치했다.
- native 운영 로그는 1파일·0바이트였고, 질문/원문 조각 일치 0을 확인했다. 원문과 모델 출력은 등록된 공개·합성 실험 보고서에만 보존한다.
- 실행 프로세스 종료와 잠금 정리를 확인했다. 같은 출력 디렉터리로 재실행하거나 남은 4개를 이어 실행하지 않는다.
- `45810d2`의 push/PR 필수 CI는 모두 통과했고 GitHub 작성자·커미터는 `lingter100`이다. CI 통과와 후보 품질 실패는 동시에 성립한다.

다음은 불완전한 근거 선택을 다루는 새 근거 단위 설계와, 품질 문항을 재사용하지 않는 중립 검증이다. 구조 누락 방지만으로 선택 인용의 의미 문제가 해결된다고 가정하지 않는다. 무료 로컬 모델만 사용하고 원래 평가 게이트나 120초 제한을 실행 중 완화하지 않는다. 후속 선택의 최신 상태는 STATUS를 따른다.
