# DocTrail 단계별 완료 기준

기준일: 2026-10-12. 일정·인원·채용 성과를 보장하는 계획이 아니다. 아래 표는 의존 순서와 검증 조건이다. 실제 완료한 항목은 [STATUS.md](STATUS.md)에 실행 증거와 함께 기록한다.

## M1 · 업로드에서 원문 근거까지

실제 사용자가 넣은 문서를 영속 저장하고 권한을 지키며 키워드로 찾는 흐름을 완성한다.

**산출물**

- Python/FastAPI API, SQLite 저장, 세션 인증, 워크스페이스·문서 권한.
- 한국어 업로드·검색·원문 확인 화면, 수정·삭제·실패·재처리 흐름.
- 형식·파일 크기 제한과 텍스트 PDF의 페이지 근거.
- API 계약, 실행 안내, 테스트·빌드 결과, 구현 한계.

**완료 조건**

- 새 계정으로 문서 업로드→검색→원문 확인을 실제 화면에서 수행한다.
- 재시작 후 문서와 검색 대상이 유지된다.
- 개인 문서·다른 워크스페이스 문서의 목록·검색·직접 조회를 차단한다.
- 수정·삭제·반복 재처리 후 오래되거나 중복된 청크가 남지 않는다.
- 한국어·영어·Unicode와 PDF의 근거 문자열·위치가 일치한다.
- 관련 자동 테스트와 프런트엔드 빌드를 통과한다. 수행한 범위만 기록한다.

**포트폴리오 표현:** “권한을 고려한 키워드 문서 검색을 로컬에서 구현하고 제한된 시나리오를 검증했다.” 임베딩·RAG 답변·학습·실사용 성과는 이 단계의 성과가 아니다.

## M2 · 재현 가능한 데이터와 평가 기준선

기능을 늘리기 전에 품질을 비교할 토대를 만든다.

**산출물**

- 공개 라이선스 문서 수집·정제 도구, 고정 커밋 manifest, attribution.
- 약 1,000문서 목표의 실제 수량 보고와 문서 계열별 중복·번역·버전 처리 기록.
- 200~300개 질문 목표의 작성·자동검사·사람 검토 상태, 문서 계열 기준 분할.
- BM25 평가 실행기, 질문별 결과, 오류 분류표, 메모리·지연시간 기록.

M2 실제 상태: 313문서·최초 240/활성 239질문을 준비하고 dev 기준선과 실제 HTTP 지연을 측정했다. 최고 메모리 사용량은 미측정이다. 메모리 계측은 M3 로컬 모델 비교 전에 보완하며, 이 항목까지 완료했다고 주장하지 않는다. 사람 검수 0개·test 성능 미공개 상태에서 예비 개발 평가만 수행했다.

**완료 조건**

- 깨끗한 환경에서 같은 소스와 설정으로 문서·질문 해시를 재현한다.
- 라이선스·출처 누락, 문서 계열 분할 충돌, 근거 오프셋 오류를 검사한다.
- AI 초안과 사람 확인 라벨을 분리한다. 사람이 검토하지 않은 상태를 숨기지 않는다.
- 작은 기능 시험과 전체 품질 평가를 분리해 보고한다.
- 기준선 실패를 파싱·토큰화·청크·순위·근거 부족 등으로 분류한다.

**다음 단계의 판단:** 실제 평가셋이 작거나 검토가 부족해도 예비 실험은 진행할 수 있다. 대신 확정 성능·일반화·학습 개선 주장은 보류한다.

## M3 · 밀집·혼합·재순위화 비교

사용자의 Java 요청으로 서비스 백엔드를 `server/`로 전환했다. 기존 동결 실험은 Python에서 유지하며 새 모델의 서비스 연결 대상은 Java다. 전환 회귀 결과는 [JAVA-MIGRATION](JAVA-MIGRATION.md)과 STATUS에 기록한다.

BM25, 사전학습 임베딩, 혼합 검색, 재순위화를 같은 조건에서 비교한다.

M3 현재 상태: 고정 dev 79질문에서 실제 로컬 GPU 비교와 후보 선택 후속 비교를 완료했다. 필수 원문 근거 @5는 BM25 30/59, E5 29/59, RRF 27/59, 기존 RRF+리랭커 36/59, 균등 깊이 후보+리랭커 37/59다. Java에 선택적 모델 경로를 연결하고 합성 HTTP·실제 GPU·브라우저로 권한·수정·삭제와 원문 흐름을 검증했다. 이 운영 검사는 새로운 검색 품질 평가가 아니다. 사용자 검수0·최종 test 잠금은 유지한다. 다음은 실패 원인에 맞춘 train 데이터와 학습 설계다. [실측 분석](M3-ANALYSIS.md), [후속 분석](M3-CANDIDATE-ANALYSIS.md), [모델 운영](MODEL-SERVING.md)을 따른다.

**산출물**

- `multilingual-e5-small` 등 후보의 고정 리비전·라이선스·실행 설정.
- 정확 벡터 검색 기준선, RRF 결합, 재순위화 선택 실험.
- 한국어·영어·언어 교차·오류 코드 유형별 점수와 p50/p95·자원 측정.
- 품질이 하락한 질문과 개선된 질문의 원문 비교.

**완료 조건**

- 개발셋에서 후보를 고르고 최종 평가 전에 설정을 고정한다.
- 전처리·후보 수를 맞춘 공정 비교와 재순위화 이전 회수율을 제공한다.
- 잘린 텍스트 비율과 GPU OOM·CPU fallback을 기록한다.
- 모델이 좋아졌다는 결론이 없어도 기준선 포함 전체 결과를 남긴다.
- 임베딩·재순위화 경로에서도 권한·수정·삭제 조건을 유지한다.

**저장소 확장:** PostgreSQL+pgvector는 실제 필요를 설명할 수 있을 때 도입한다. 데이터베이스 교체와 모델 변경을 한 번에 진행해 성능 개선 원인을 흐리지 않는다.

## M4 · 실패 원인에 맞춘 모델 학습

앞 단계에서 반복적으로 나타난 실패를 줄일 수 있을 때 임베딩 또는 재순위화 모델 학습을 선택한다.

**산출물**

- Train 계열에서만 만든 학습쌍과 검토한 hard negative.
- 학습 데이터·설정·seed·손실·학습 곡선·체크포인트 식별 정보.
- 사전학습 모델과 학습 후 모델의 동일 조건 평가, 데이터 양·음성 예시의 ablation.
- 6GB GPU에서 실제 가능한 배치·토큰 길이·메모리·시간 기록.

**완료 조건**

- Dev/test 계열의 정답·질문·음성 예시가 학습에 들어가지 않는다.
- 표현만 바꾼 질문과 번역·이전 버전이 분할 경계를 넘지 않는다.
- 학습쌍 수만 채우지 않고 거짓 음성 예시와 라벨 품질을 확인한다.
- 여러 seed 또는 제한된 단일 실행이라는 사실을 명시한다.
- 학습 완료·성능 개선·운영 채택을 각각 구분한다.

모델 학습을 했다는 항목만 채우려고 대형 생성 모델을 학습하지 않는다. 유료 GPU가 필요한 경우에는 무료 로컬 범위에서 가능한 대안과 예상 비용을 먼저 정리한 뒤 사용자 승인을 받는다.

## M5 · 근거 있는 답변과 답변 보류

검색 품질과 자원 조건이 확인된 뒤 생성 기능을 붙인다. 로컬 모델의 품질·속도를 먼저 평가하며 유료 API 호출은 승인 없이 사용하지 않는다.

**산출물**

- 근거 구간과 버전이 연결된 답변, 근거 부족·조건 불명확 상태.
- 프롬프트·모델·추론 설정 기록, 인용 정확도·근거 지지율 평가.
- 답변 범위와 답변한 질문의 오답률을 함께 보여주는 결과.
- 문서 내 지시문, 모순된 버전, 제한 문서에 대한 실패 분석.

**완료 조건**

- 답변에 사용한 모든 근거가 현재 사용자 권한을 통과한다.
- 근거 없는 주장을 그럴듯한 출처로 포장하지 않는다.
- 보류 임계값을 개발셋에서 정하고 최종셋에서 변경하지 않는다.
- 자동 판정 점수와 사람이 확인한 점수를 분리한다.
- 수정·삭제·공개 범위 변경이 생성 문맥과 캐시에도 반영된다.

## M6 · 포트폴리오 패키지와 운영 검토

**산출물**

- 재현 가능한 설치·평가 안내, 데이터 카드, 모델 선택 보고서, 실패 사례.
- 실제 화면 녹화 또는 데모 자료, 한눈에 읽는 실험 비교표.
- 설계 결정 기록, 코드·AI 보조·사용자 기여의 구분, 남은 한계.
- 운영 설정·백업·복원·로그·보안 검토 결과.

**완료 조건**

- 새 환경에서 실행과 평가를 재현하고 누락된 설정을 수정한다.
- 저장소에 비밀·업로드 자료·개인 식별 정보·불필요한 가중치가 없다.
- 문서의 완료 표현이 실제 결과와 일치한다.
- 사용자 검증이 있었다면 실제 참가자 수·방법·한계를 기록한다. 없으면 미검증으로 남긴다.
- 원격 CI 성공, 로컬 검증, 서비스 배포 상태를 각각 구분한다.

공개 GitHub 저장소와 실제 서비스 공개는 별개다. 소스 공개 승인은 서비스 배포·사용자 자료 수집·유료 사용 승인을 포함하지 않는다.

## 각 단계에서 남길 기록

`STATUS.md`에는 수행한 명령과 실제 결과·실패·미검증 범위를, `DECISIONS.md`에는 바꾼 선택과 이유를, `CONTRIBUTIONS.md`에는 작성자와 AI 보조 역할·실제 확인한 모델 설정을 남긴다. 실험은 설정과 데이터 해시가 연결된 `run_id`로 참조한다.

진행 우선순위는 **운영 정확성 → 데이터·평가 품질 → 검색 개선 → 학습 → 생성 기능 → 확장 기능**이다. 반복 작업 자동화는 시간을 줄이는 수단이며 실제 데이터·평가·사용자 확인을 대신하지 않는다.

## 2026-10-13 M4 실제 완료 범위와 다음 순서

제한된 단일 학습16updates, 내부 calibration 및 사전 고정 main-dev 비교, 실제 checkpoint-bound Java/React 운영16검사 묶음을 완료했다. [운영 결과](M4-OPERATIONS-RESULTS.md)와 [main-dev 분석](M4-MAIN-DEV-ANALYSIS.md)을 따른다. 여러 seed·데이터 ablation은 수행하지 않았고, 이를 완료 조건 충족으로 소급 주장하지 않는다. 작은 AI 검토 자료·다중 문서 퇴보·사용자 검수0을 제한으로 기록한다.

다음은 M5 설계다. 생성 모델의 라이선스·로컬 자원과 답변/인용/보류 계약, 문서 내 지시문·모순·수정/삭제·권한 경합 평가를 먼저 정한다. 완료된 retrieval dev를 다시 설정 탐색에 사용하지 않고 test 잠금을 유지한다. 이후 M6 운영·화면 완성도와 포트폴리오 정리를 이어간다.
