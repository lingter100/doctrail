# 요약 엔진 도구 취득 실패: 공용 헤더 배치

2026-10-30. 실제 LLVM 취득이 `extract-llvm` 단계의 `llvm_required_subtree` 검사에서 멈췄다. 정상 종료한 시도로 바꾸거나 다시 실행하지 않는다. 모델을 호출하지 않았으므로 요약 품질 실패로 분류하지 않는다.

정확히 받은 고정 ZIP은 171,028,561바이트이며 SHA256은 `82babcd6aae4dc3606e8e0471d816989c384b4bf86a139f184a8b4a1b2c2758d`다. 중앙 목록 9,353개 항목을 읽어 확인한 결과, 코드가 필수로 요구하던 `x86_64-w64-mingw32/include/`는 이 배포에 없었다. 실제 헤더는 공용 `include/`에 있고, 그 아래 비어 있지 않은 파일 4,128개·107,914,638바이트가 선언돼 있다. Clang 자원 헤더와 x64 라이브러리도 별도 경로에 있다. 파일 본문을 추출하거나 도구를 실행해서 얻은 결과는 아니다.

검사는 선택 파일을 쓰기 전에 실패했다. 따라서 이 실패의 원인은 다운로드 손상이나 추출 속도가 아니라, **실제 배포 구조와 검사 코드의 가정이 다른 것**이다. 기존 합성 ZIP에도 잘못된 대상별 헤더 경로가 들어 있어 테스트만으로 발견하지 못했다.

최소 수정은 없는 경로를 요구하던 조건을 실제 공용 헤더의 필수 검사로 대체하는 것이다.

- `include/windows.h`: Windows 헤더 위치 확인.
- `include/_mingw.h`: MinGW 공용 설정 확인.
- `include/c++/v1/__config`: C++ 공용 설정 확인.

이 파일들은 각각 존재하고 비어 있지 않아야 한다. 공용 include·Clang 자원·x64 라이브러리·드라이버 등 나머지 검사, 파일 선택과 라이선스 보존, CRC·길이·해시·자원·시간 제한은 유지한다. 일반적인 여러 배포 형식을 처리하는 새 추상화는 만들지 않는다.

회귀 검사는 실제처럼 대상별 include가 없는 공용 배치의 성공, 각 필수 공용 파일의 누락·빈 파일 거절, 공용 파일 없이 대상별 경로에만 파일이 있는 경우의 거절을 다룬다. 고정 ZIP 중앙 목록을 수정된 선택 함수에 통과시키는 확인은 전체 추출·컴파일·엔진 호환성 검증과 구분한다. 대표 파일 존재가 모든 의존성의 완결성을 증명하지 않는다.

[실패 실측](../experiments/results/meetings-summary-engine-v3-oct30-acquisition-v1.json)의 실행·관찰 세션은 종료 코드1로 닫혔다. 알려진 소유 프로세스9개와 내부 관찰6개의 부재, 고정 참조127개 보존을 확인했다. 받은 ZIP과 부분 파일8개, 최초 오류와 소비 기록을 보존했다. 이후 수정 검증과 새로운 실제 실행은 별도로 기록한다.

관련 합성·fixture 사용 검사302개가271.75초에 통과했고 Ruff도 통과했다. 수정된 함수가 실제 ZIP 중앙 목록에서6,116개를 선택·3,237개를 제외했으며 본문 열람·추출은0회였다. 처음에는 임시 폴더 권한 때문에 검사 본문 전302개 setup 오류가 났고, 별도 인자 전달 오류1회도 본문 실행 전에 끝났다. 원래 기록을 보존하고 소스 변경 없이 같은 검사 묶음만 실행 가능한 임시 경로로 재확인했다. [검증과 한계](../experiments/results/meetings-summary-engine-shared-headers-repair-v1.json).

별도 Astra xhigh의 변경 검토는 차단0·권고0이었다. 검사한 소스와 현재 파일이 일치하며 선택 함수의 필수 경로 조건 외 제품 동작은 바꾸지 않았다. 게시할 정확 커밋의 CI와 수정 뒤 실제 취득·컴파일·내용 품질은 별도 확인 사항이다.
