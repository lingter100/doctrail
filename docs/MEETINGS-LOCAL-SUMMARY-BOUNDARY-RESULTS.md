# 요약 길이 경계의 작은 기술 검토

2026-10-27 · 모델 없는 순수 검사만 완료 · 실제 엔진과 내용 품질 미검증

기존 요약은 개별240자·합계1200자를 넘어 거부되기도 했다. [설계](MEETINGS-LOCAL-SUMMARY-BOUNDARY-NEXT.md)에 따라 이 길이 조건을 생성 문법으로 표현할 수 있는지 검토했다. 여섯 문장을 모두200자로 제한하거나 주장 수를 줄여 원래 허용된 요약을 배제하지 않는 것이 조건이다.

후보는 여섯 주장을 세 쌍으로 묶고, 각 쌍에서 사용할 수 있는 길이를 전체 합계와 연결한다. 길이 배분은 고정하지 않는다. 생성된 문법은910,051바이트·명시 규칙1,452개로 사전에 정한 크기 상한 안이었다. 분기 수와 실제 엔진 내부 확장은 별도이므로 작은 실행 비용을 뜻하지 않는다.

| 확인한 것 | 실제 결과 |
| --- | --- |
| 최초 순수 검사 | 격리 파서의 기존 상수 `SPAN_FIELDS` 누락으로 실패, 완료 묶음0 |
| 별도 준비 코드 수정 | 원래 상수만 추가, 문법·합성 입력·예상값·한도 그대로 |
| 수정 후 순수 검사 | 고정 합성106개와 길이 배분 경계288,956건의 예상값 비교 통과, 약0.109초 |
| 원본 보존 | 최초 파일13개 불변, 실패와 수정 결과를 별도로 보존 |
| 실제 생성 엔진 | 준비된 고정 버전에 검증기가 없어0회 |
| 실제 모델과 제품 연결 | 0회 |

합성 입력은 한글·ASCII·비BMP 문자, JSON escape·surrogate pair, 개별/전체 길이 경계와 비균등 여섯 주장 등을 포함한다. 기존 문법과 파서는 키 순서·공백·보류·근거 유효성에서 원래 차이가 있어 각 예상값을 구분했다. 이 검사는 생성된 문법을 실행한 결과나 모든 문자열의 동치 증명이 아니다. Prefix10개도 실제 엔진에서는 미검증이다.

[공개 집계](../experiments/results/meetings-local-summary-boundary-feasibility-v1.json)에 원본·수정·문법·합성 입력의 해시와 한계를 기록했다. 로컬 격리 프로토타입의 새 환경 재현 패키징은 아직 남아 있다. 다운로드·빌드·다른 엔진으로 검사를 대신하지 않았다.

다음 판단에는 고정 엔진의 문법 초기화·Unicode·완결과 prefix·자원·시간 검사가 필요하다. 통과해도 실제 토큰 처리 비용과 의미 충분성은 따로 평가한다. 길이 제한 준수는 이전768토큰 미완결을 해결한다는 증거가 아니며, 이 후보는 아직 서비스에 연결하지 않았다. QA 전용 지침 후보의 코드·실험과도 구분한다.
