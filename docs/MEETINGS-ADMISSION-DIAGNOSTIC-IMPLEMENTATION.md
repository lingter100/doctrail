# 입력 수용 조건 진단 구현

2026-10-20. 일반 합성 예시12개의 입력과 기대값을 고정하고 기존 처리기·문단 파서·입력 수용 함수·직렬화 함수를 그대로 관찰하는 작은 진단을 구현했다. 실제 문서나 질문, 토크나이저와 모델을 실행하는 도구가 아니다.

## 구현과 검증

추가 파일은 `scripts/diagnose_meeting_admission.py`, literal fixture JSON, 단위 검사 한 파일이다. 기존 동결77개 파일을 수정하지 않는다. 원래 수용 결과와 추가 관찰을 분리하고, 공식 실행은 고정 경로의 최초 실행만 허용한다. 입력·코드·Git HEAD가 바뀌거나 예측과 다른 결과가 나오면 중단하며 최초 원인과 실행하지 못한 예시를 남긴다.

검토에서 결과 저장 실패가 최초 원인을 가리는 문제, 마지막 결과 읽기 실패 처리, 파일 접근 시간 오인, 초기 실패 뒤 재실행 가능성, 디스크 동기화 실패 뒤 성공 파일 잔존 가능성을 수정했다. 마지막 항목은 임시 파일을 먼저 동기화한 뒤 새 결과 경로에 배타적인 hard link를 만드는 방식으로 처리한다. 실패한 임시 파일은 보존하며 성공 결과로 사용하지 않는다.

실제 Astra high 구현자와 별도의 Astra xhigh 코드 검토 역할이 확인했다. 검토자는 이 진단의 설계자이며 기존 calibration 원문 노출이 있으므로 독립 source 검토나 미노출 judge라고 하지 않는다. [코드 검토 기록](../experiments/results/meeting-admission-diagnostic-review-v1.json)에 최종 세 파일 hash와 역할 한계를 남겼다.

최종 좁은 단위 검사는 **11통과/13.82초**, Ruff 통과다. 초기11통과/10.55초와 Ruff 스타일 지적7개는 별도 보존했고 합산하지 않는다. 검사에는 실제 고정12예시 처리와 호출 계측, 임시 Git 저장소의 내용/HEAD 변경, 최초 실패 보존, 부분 쓰기, 정상 측정 후 전체 terminal 쓰기·flush·fsync 실패가 포함된다. 실패 주입은 진단 저장 경계에 적용하며 동결 처리기·수용 함수·직렬화 동작을 모형으로 바꾸지 않는다.

[단위 검증 영수증](../experiments/results/meeting-admission-diagnostic-implementation-v1.json)은 local 원본862787a9의 exact copy다. 부모가 코드3개와 로그7개 hash·실행 전후 일치·기존77개 불변을 확인했다. 최초 관측 metadata의 검사 수가 숫자77 대신1을77개 나열한 형식 오류도 원본을 보존하고 최종 영수증에 설명했다. 마지막 fsync 검사 강화 부분은 부모가 현재 파일에서 추가로 읽었으며 검토자가 다시 읽은 것으로 주장하지 않는다.

## 실행 범위

단위 검증과 공식 진단은 구분한다. 공식 증거는 검토한 구현이 커밋되고 통상 CI를 통과한 뒤 다음 명령을 한 번 실행해 만든다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.diagnose_meeting_admission
```

공식 출력은 `.local/meetings-admission-diagnostic-v1`이다. 이미 존재하면 소비된 실행으로 간주한다. 실패하더라도 삭제·재시도하지 않는다. 성공은 종료 코드0·CLI 요약과 저장된 영수증 일치·12개 관찰 일치·입력과 HEAD 불변을 모두 확인해야 한다.

이 문서 생성 시 공식 실행은 아직0이다. 최초 실패 또는 실제 완료 결과는 별도 결과 기록에 남긴다. 성공하더라도 문서 형식 제한에 관한 합성 관찰일 뿐이며, 공개 자료 적합성·토큰 수·모델 응답 속도·답변 품질·Phase1 완료를 입증하지 않는다.
