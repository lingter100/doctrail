# M3 후보 선택 후속 실험 설계

기준일: 2026-10-12. **새 정책의 결과를 계산하기 전에 고정하는 단일 dev 실험**이다. 기존 [M3 설계](M3-DESIGN.md)와 [실패 분석](M3-ANALYSIS.md)을 이어가며 모델·청크·라벨은 바꾸지 않는다. 저장된 B50·D50 후보에서 선택 규칙 하나만 변경하고, 질문마다 최대 50쌍을 동일 BGE로 한 번 재순위화한다. 전체 M3의 BM25·E5 추론을 다시 실행하지 않는다.

설계 위임에 도구가 수락한 개발 보조 설정은 `gpt-6-astra / xhigh`다. AI 작성 설계이며 사용자 검수나 부모 채팅 모델 변경의 증거가 아니다. 질문의 사용자 검수는 계속 0개다. 이 문서에는 새 정책의 관측 결과가 없으며 실행 결과는 별도 파일에 기록한다.

## 1. 질문과 사전 결정

기존 B50·D50 합집합은 양성 59질문 중 40개의 모든 필수 근거를 포함했다. RRF 상위 50개로 줄이면 37개, BGE의 최종 top-5에서는 36개였다. 합집합에서 이미 부족한 19개와 축소 중 잃은 `013/017/040`, 후보가 충분해도 최종 순위에서 실패한 `060`은 서로 다른 문제다.

이번 질문은 **두 검색기의 후보를 같은 깊이로 읽고, 중복으로 남는 자리를 더 깊은 후보로 채우면 RRF 상위 50개 선택보다 근거를 더 보존하는가**다. 이미 사전 지정했던 B25·D25 합집합 진단 H25를 중복 제거 후 50개까지 채우는 방식으로 확장한다. H25의 기존 후보 완전 회수 36/59를 새 정책의 결과로 대신하지 않는다.

각 분기 top-10 보호 후 RRF 채우기는 B28·D48·D49를 직접 보호하지 못한다. 알려진 실패 순위를 위한 별도 예약석도 두지 않는다. 균등한 깊이 증가 역시 D48·D49까지 도달한다는 보장은 없고, B28 회복도 결과 확인 전에는 가설이다. 개선이 없거나 퇴보해도 이 한 결과를 보존한다. 같은 dev에서 정책·깊이·분기 가중치·RRF 상수를 바꿔 재탐색하지 않는다.

## 2. 고정 선택 규칙 `balanced_depth_rrf50_v1`

입력은 원래 보고서의 질문별 `bm25.candidate_chunks`와 `dense_e5.candidate_chunks`이며 각 분기의 저장된 순서를 그대로 사용한다. 아래 순서는 1부터 센다.

1. `B1, D1, B2, D2, …, B50, D50` 순서로 읽는다. 해당 순위가 없는 분기는 건너뛴다.
2. 처음 보는 청크만 선택한다. 같은 청크가 다시 나오면 자리를 소모하지 않는다. 선택 수가 `min(50, 합집합의 고유 청크 수)`에 도달하면 즉시 멈춘다. 마지막 자리에서 두 분기가 경쟁하면 B를 먼저 읽는 고정 순서를 사용한다. 질문 내용·언어·라벨·기존 BGE 점수로 분기를 고르지 않는다.
3. 선택된 집합을 **전체 원래 B50·D50 순위**의 동일 가중치 RRF `Σ 1/(60 + rank)` 내림차순으로 정렬한다. RRF 동점은 기존 코퍼스 순서인 document ID와 청크 ordinal을 따른다. 후보를 고른 순서나 선택 후 다시 매긴 분기 순위를 RRF에 사용하지 않는다.
4. 이 순서를 BGE 입력 순서로 사용한다. 모든 선택 쌍의 새 raw logit을 내림차순 정렬하고 정확한 동점은 입력 순서를 유지한다. 최종 10개를 반환하고 첫 5개로 주 지표를 계산한다.

이 규칙은 B25·D25 합집합을 모두 포함한다. 처음 25쌍의 위치에는 최대 50개의 고유 후보만 있으므로 그 전에 중복 때문에 후보를 잃지 않으며, 중복이 있으면 남은 자리를 더 깊은 순위로 채운다. 이것은 양쪽의 **읽는 깊이**를 균등하게 유지하는 방식이다. 최종 집합의 분기 전용 후보 수가 각각 정확히 25개라는 뜻은 아니다. B가 마지막 한 자리에서 먼저 선택되는 비대칭을 숨기지 않고 실제 읽은 분기 깊이·고유 기여 수·교집합 수를 기록한다.

새 정책은 하나다. 원래 B/D/H/HR/H25는 저장된 비교 자료이고, RRF로 정렬한 새 후보의 top-5는 추론 없는 보조 진단이다. 이를 별도 모델 실험이나 추가 후보 정책으로 세지 않는다. 문서/번역 중복 억제, MMR, query 확장, 더 큰 합집합 재랭킹, 청킹 변경, 학습은 이번 실험에 넣지 않는다.

정제된 공개 원문을 검증하고 기존 extraction·chunking으로 텍스트를 복원한다. 후보 ID뿐 아니라 document ID·ordinal·offset·page와 원문 UTF-8 SHA-256을 맞춘다. 전체 청크 digest와 원래 문서별 해시도 대조한다. 질문 ID·본문·순서·근거·분류와 원래 결과의 79개 행이 일치해야 한다. 동일 ID의 상충하는 metadata, 중복 후보, 알 수 없는 청크, 50개를 넘는 분기, 비유한 점수, 분할/해시 불일치는 실패다. 원본 결과를 수정해 검증을 통과시키지 않는다.

새 정책 평가 전에 저장된 B50·D50으로 기존 H50을 재구성해 후보 ID·순서·RRF 점수·offset의 정확 일치를 확인한다. 기존 H25와 후보/최종 지표의 재계산도 원래 결과와 대조한다. 이 과정은 저장된 순위와 원문 근거의 재생이며 BM25 재검색·E5 재인코딩·모델 품질 재실행이 아니다. test 질문 파일을 읽거나 test 160개를 검색하지 않는다. dev 이외의 입력은 모델 로드나 출력 생성 전에 거부한다.

설계 문서·설정·실행 코드의 hash와 Git SHA를 새 결과에 기록한다. 새 정책의 후보 진단이나 모델 실행 전에 이 설계와 실행 설정을 커밋한다. 결과를 본 뒤 설계를 바꾸면 새 버전·별도 실험으로 남겨야 하며 이번 run을 대체하지 못한다. 원래 M2/M3 입력·결과·journal은 실행 전후 해시가 같아야 한다.

## 4. 점수 재사용 판단과 실제 추론

원래 보고서의 HR `ranked_chunks`와 journal의 `final_chunks`에는 **최종 10개 raw logit만 있다**. 50개의 `candidate_chunks.score`는 RRF 점수이며 BGE 점수가 아니다. 따라서 새로 들어온 청크만 추론하고 나머지 40개 점수를 재사용하는 방식으로 새 순위를 복원할 수 없다. 누락 점수를 0이나 최저값으로 채우지 않는다.

이번 실행은 선택된 모든 후보를 동일 pinned BGE로 새로 점수화한다. dev 79질문을 원래 순서로 한 번 순회하며 측정 쌍은 총 최대 3,950개다. 미변경 후보도 같은 새 실행에서 계산하고 오래된 점수와 혼합하지 않는다. 원래 H50 전체를 추가로 재랭킹하지 않는다.

| 항목 | 유지할 값 |
|---|---|
| 모델 | `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e` |
| 가중치 SHA-256 | `d9e3e081faff1eefb84019509b2f5558fd74c1a05a2c7db22f74174fcedb5286` |
| 실행 | 원래 잠금 의존성, CUDA FP16, batch 1, eager attention, eval/inference mode, seed 42 |
| 입력 | 원 질문과 원 `chunk.text`, 접두어/제목 추가 없음, 최대 512, 오른쪽 `only_second` 잘림 |
| 준비 | 원래 고정 합성 질문·passage 1쌍을 2회 warmup; dev 추론과 별도 집계 |
| 안전 실패 | 모델/설정/입력 drift, OOM, 비유한 logit, 누락 결과는 실패 기록; CPU로 자동 전환하지 않음 |

로컬 tokenizer/config/가중치 해시와 runtime dtype·라이브러리·CUDA·TF32·determinism 설정을 원래 보고서와 대조한다. 모델은 검증한 local snapshot에서 offline으로 로드한다. 의존성 동기화와 모델 추론을 동시에 실행하지 않는다. GPU 비트 결정성은 원래도 보장하지 않았으므로 새 결과와 원래 결과의 비교에는 별도 실행의 수치 변동 가능성이 남는다.

각 질문에서 원래 HR top-10과 새 후보가 겹치는 쌍은 추가 forward 없이 새 점수와 이전 raw logit의 정확 일치 여부·차이 최댓값을 기록한다. 매칭 키는 질문 ID/본문 hash, 청크 원문 hash와 위치, 모델/tokenizer/config/dtype fingerprint다. 이것은 이용 가능한 일부 쌍의 drift 진단이며 50개 전체의 수치 동등성을 증명하지 않는다. 차이가 있으면 후보 정책만의 효과로 단정하지 않고 불일치와 영향 범위를 공개한다.

새 결과에는 모든 선택 쌍의 input ordinal·chunk identity·RRF score·raw BGE logit·토큰 수·잘림·score provenance를 저장한다. 향후 부분 점수 재사용은 모든 요청 쌍의 동일 fingerprint와 완전한 raw 점수 cache가 있을 때만 별도 사전 설계한다. cache/fresh 점수의 입력 순서 기반 동점 처리, JSON round-trip 후 순위 재현, 누락/중복/불일치 거부를 검증해야 한다. 현재 실험에서 그 가능성을 실행 완료로 기록하지 않는다.

## 5. 후보 실패 분류와 span 경계

기존 계약을 유지한다. grade 2 근거만 필수이며 같은 evidence group의 대안 span은 OR, 서로 다른 필수 group은 AND다. 하나의 span은 동일 문서의 한 청크가 `[start_offset, end_offset)` 전체를 포함해야 한다. 인접한 두 청크의 부분 span을 합쳐 성공으로 만들지 않는다. grade 1 배경 근거·문서 ID 적중만으로 완전 근거를 인정하지 않는다.

| 분류 | 필수 근거 그룹별 판정 |
|---|---|
| `chunk_boundary_uncoverable` | 전체 고정 코퍼스의 어떤 한 청크도 그 그룹의 grade 2 대안 span 중 하나를 완전히 담지 못함 |
| `evidence_document_absent` | 커버 가능한 대안은 있지만 검사하는 후보 집합에 그 대안의 문서가 하나도 없음 |
| `same_document_wrong_chunk` | 커버 가능한 근거 문서는 후보에 있으나 그 그룹의 전체 span을 포함하는 청크가 없음 |
| `selection_cutoff_loss` | B50·D50 합집합에서는 그룹을 덮었지만 H50 또는 새 50후보 선택 후에는 덮지 못함 |
| `final_top5_ranking_miss` | 선택 후보가 모든 그룹을 포함하지만 실제 재랭킹의 첫 5개는 모두 포함하지 못함 |

한 그룹의 번역 대안 하나가 경계를 넘더라도 다른 대안을 한 청크가 담으면 그 그룹을 구조적으로 불가능하다고 세지 않는다. 질문별로 여러 그룹·원인이 함께 있을 수 있으므로 그룹별 원인을 먼저 저장하고 질문별 집계의 중복 허용 여부를 명시한다. B/D/합집합/H50/새 후보를 각각 검사하고, 후보 축소 손실과 합집합 단계부터의 부재를 구분한다. 기존 경계 실패 3질문을 주 지표 분모에서 제외하지 않는다.

청크 중복·문서 집중도는 같은 문서/리비전의 offset 교집합과 동일 주석 그룹을 덮는 후보 수로 진단한다. 번역·겹침이 있다는 이유만으로 이번 선택에서 제거하지 않는다. 같은 문서의 다른 필수 사실과 같은 사실의 여러 대안을 구분한다. 라벨에 없는 새로운 유용한 후보는 자동 정답으로 추가하지 않고 후속 검토 대상으로만 남긴다.

잘림은 위 후보 분류와 별도 축이다. 정확한 tokenizer offset/sequence ID로 passage 토큰만 원문 codepoint에 대응시킨다. `max(offset)`나 decode 문자열만으로 span 전체가 보였다고 판정하지 않는다. retained-token offset의 구간 합집합이 annotation 전체를 덮는 보수적 검사를 두고, 공백·정규화로 mapping이 없는 틈은 `not_proven`으로 표시한다. 이는 모델이 반드시 읽지 못했다는 뜻이 아니다. 별도로 잘림 전 evidence와 겹치던 토큰 중 보존/제거된 수와 `all_evidence_overlapping_tokens_retained`를 계산할 수 있다. 토큰 보존, 문자 범위의 엄격한 포함, 의미 이해는 다른 주장이다. 한국어·Unicode·공백·문장부호·반복 구절·특수 토큰 검증 전에는 model-visible 수치를 발표하지 않는다.

## 6. 지표, 시간과 결과 판단

주 지표는 양성 59개에 대한 기존 `evidence_all_at_5_chunks`다. 후보의 완전 근거 포함, group recall, 최종 any/group recall, 기존 언어·교차언어·단일/다중 문서 분류의 분모와 성공 수, 원래 HR 대비 회복·퇴보 ID를 함께 보고한다. 79개 모두에 후보 개수·분기 깊이·추가/탈락 ID·새 logit provenance를 남긴다. 근거 없음 12개·조건 불명확 8개는 따로 기록하고 답변 보류 정확도로 해석하지 않는다.

후보 완전 회수는 최종 top-5의 필요조건이다. 합집합의 40/59는 이번 고정 입력에서 관찰한 후보 조건이며 달성 가능한 oracle@5나 의미상 정답률이 아니다. 새 후보 점수가 좋아도 BGE top-5가 좋아질지 미리 확정하지 않는다. 이전 HR보다 나빠진 질문도 모두 공개한다. 개발 집합을 이미 분석해 고른 후속 정책이므로 독립 검증·test 일반화·통계적 유의성을 주장하지 않는다.

시간은 두 범위로 나눈다. **저장 후보 재생/선택 시간**은 CPU 진단 비용이며 모델 추론 지연이 아니다. **새 BGE reranker-only 시간**은 선택된 쌍의 tokenization·전송·forward·정렬을 포함하고 CUDA 경계 동기화 후 측정한다. 모델 로드와 합성 warmup은 별도다. 실행 쌍 수, 질문별 표본, p50/p95, 실패 수와 단계 메모리를 기록한다. 예전 BM25/E5 시간에 새 시간을 더해 실제 새 end-to-end 수치처럼 발표하지 않는다. HTTP·Java 서비스 지연, 동시 상주 모델 메모리, 부하 성능은 측정하지 않는다.

## 7. 실행 전 검증과 산출물

새 selector 테스트는 양쪽 중복 없음/완전 중복/부분 중복, 빈/짧은 분기, 50개 한도, 고정 중단 순서, B25·D25 포함, 원래 전체 순위 RRF 사용, corpus-ordinal 동점, BGE 동점 입력 순서, 라벨/score 비의존성을 검사한다. 근거 검사는 OR 대안·AND 그룹·부분 span 두 개의 오인 성공·구조적 경계·동일 문서 다른 청크·축소 손실·후보 충분/최종 실패를 구분한다. 원본 hash/점수/offset drift와 기존 출력 덮어쓰기는 거부한다.

구현 예정 진입점은 `scripts/analyze_candidates.py`와 `scripts/evaluate_candidates.py`다. 실제 지원 인자와 실행 명령은 구현 후 runbook/결과에 기록한다. 진단과 실제 추론은 서로 다른 새 파일을 사용하며 기존 결과를 덮어쓰지 않는다. 시작/완료/안전 오류와 실행 전후 fingerprint를 journal에 남긴다. 실패를 지워 성공한 표본만 집계하지 않는다. 원문·질문 본문은 운영 로그에 넣지 않는다.

완료 조건은 설계/설정 선고정, 원래 결과의 정확한 재생, 단일 정책 진단과 최대 50쌍의 실제 BGE 비교 또는 명시적 실행 실패, 모든 회복·퇴보와 한계 기록이다. 구현 통합 전 관련 Java/Python 검사와 production frontend build를 수행하고, 실제 명령·결과·제한은 `STATUS`, `DECISIONS`, `CONTRIBUTIONS`, 실험 기록에 추가한다. 이 설계 작성 작업은 이 파일만 변경한다.

결과가 정체되면 합집합에 없는 근거와 청크 경계/잘림을 우선 연구할 근거로 남긴다. 서비스 기본값 변경, Java 모델 연결, 사용자 검수, train 학습, 생성 답변, 유료 사용, 공개 서비스 배포는 이번 오프라인 실험의 완료 항목이 아니다.
