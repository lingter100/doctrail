# 캐시9B 사고 모드 후보 — 설계와 연결 상태

2026-10-31. 무료·로컬 실험 후보이며 아직 서비스에 채택하거나 실제 품질을 확인하지 않았다. 기존7B·닫힌 C0–C7 실행·평가 기준은 변경하지 않는다. 새 가중치를 받거나 유료 API를 사용하지 않는다.

## 문제와 선택

7B 질문 분해 경로는 대상·시점·사실 종류를 잘못 계획했고 실제 선택 인용도 주장을 지지하지 않았다. 회의 전체 추출도 원문 좌표·언어·상태·작업 오류가 있었다. 행 수나 인용 형식만 고쳐 반복 실행할 근거가 부족하다.

이미 확보한 Qwen3.5-9B가 질문과 권한 있는 전체 근거를 한 번에 읽고 기존 인용 답변을 반환하는 후보를 선택했다. 별도 계획 전달·답변 재작성·같은 모델의 합격 검토를 추가하지 않는다. 과거 C5는 한 응답 후 시간 초과로 의미 판정을 완료하지 못했고 C6/C7은 생성 전에 멈췄다. ‘의미 판정0건’을 ‘정답0건’으로 해석하지 않는다. 큰 모델이라는 이유만으로 성공을 예상하지도 않는다.

## 새 후보의 계획된 한도

| 항목 | 새 후보 설정 |
| --- | --- |
| 모델 | 고정 manifest의 캐시 Qwen3.5-9B Q5_K_M / llama.cpp b11429 |
| 실행 | GPU layers28, CPU2, parallel1, greedy/seed0, cache off |
| 입력·문맥 | 전체 입력6,144토큰, native context8,192토큰 |
| 출력 | 사고 요청512·최종 본문 최대768·전체 hard cap1,312토큰 |
| 시간 | 요청 전체150초, 시작120초 |
| 호스트 메모리 | 소유 프로세스 합산8GiB, 시작 가용10GiB, 실행 중 가용2GiB |
| 두 질문 수집 | 내부455초 = 시작120+준비30+답변2×150+정리5, 외부490초 |

출력의32토큰 여유는 프레임 할당이며 세 구간이 각각 독립적으로 강제된다고 주장하지 않는다. 최종 본문은 다시 토큰화해768 이하인지 검사한다. 전체 원문을 자르지 않으며 정상 EOS와 유효 응답이 필요하다. 한도를 넘으면 실패로 보존하고 자동 재시도·상한 확대를 하지 않는다.

과거 GPU28 관측의 소유 메모리는 약6.127GiB였으므로 기존7B의6GiB 제한을 그대로 쓰면 안 된다.8GiB는 새 문맥과 서비스 프로세스에 대한 여유일 뿐 새 실행의 적재 성공 증거가 아니다. 기존 GPU 가용686MiB도 peak나 문맥8,192의 측정이 아니었다. 매번 실제 가용 메모리·다른 작업·프로세스 소유권을 확인하고 조건을 만족하지 않으면 실행하지 않는다. 다른 프로젝트 프로세스를 종료하지 않는다.

과거 native 생성 속도·prefill·비-native 시간을 새 한도에 단순 비례해 약119초로 계산한 값은 설계용 추정이다. 예측 지연·p95·대화형 응답속도나 배포 성능으로 인용하지 않는다. 공식 모델의 권장 샘플링·출력 길이와 이 짧은 greedy 후보도 다르다. [고정 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B/blob/c202236235762e1c871ad0ccb60c8ee5ba337b9a/README.md)

## 검증 경계

새 어댑터의 가상 HTTP 검사는 실제 모델 적재·생성·자원 감시·Java 서비스 통합을 대신하지 않는다. 독립 코드 검토에서 실패 후 호출/토큰 기록이 사라지는 문제를 발견해 안전한 단계·오류 코드와 최초 실패를 보존하도록 수정했다. 어댑터40개 가상 검사 뒤 실패 기록 보정의 영향8개 검사, 검증기 고유20개 검사와 Ruff를 통과했다. 겹치는 검사를 합산하지 않는다. 독립 Astra xhigh 검토에서 실패 기록 문제 해결과 검증기의 최종 본문 분리를 확인했다. 실행기와 하드 시간/메모리 감시, Java 연결은 별도 통합 검토 대상이다.

검증기는 공개 자료의 전체 요청, 분리·EOS·JSON 검증을 마친 최종 본문과 안전한 수치를 저장한다. 모델 사고 원문과 원시 native 응답은 남기지 않으며, 이는 최종 본문 자체의 의미 수용을 뜻하지 않는다.

후보 동결 뒤 기존 공개 개발 두 질문을 한 번 확인한다. 완전한 근거 답변과 올바른 보류가 모두 독립 기준을 통과할 때만 이미 고정한 다른 출처6문항을 실행한다. 이 자료도 AI 검토 개발 자료이며 사용자 검수·격리 최종 평가를 대체하지 않는다. 실제 결과는 STATUS에 따로 기록한다.
