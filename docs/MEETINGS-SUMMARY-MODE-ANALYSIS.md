# 로컬 요약의 인용 일치와 내용 품질을 분리한 결과

2026-10-26. 공개 자료를 이용한 작은 개발 진단이다. 격리 validation·최종 test·사용자 검수 결과가 아니며 현재 후보를 서비스 개선 모델로 채택하지 않는다.

## 해결하려던 문제와 결과

같은 로컬 Qwen3.5-9B의 두 추론 방식을 같은 원문·prompt·예산으로 비교하려 했다. 첫 시도의 Python 진입 오류를 보존한 뒤 별도로 등록한 실제 실행에서 생성2회·자기검토1회를 수행했다. 두 번째 초안의 인용 ID 순서 오류로 중단돼 나머지6개 비교는 실행하지 않았다. 실제 명령 종료는 실패다. [실행 결과](../experiments/results/meetings-summary-mode-development-v2.json)

인용 ID는 유효하고 중복도 없었으나 원문 오름차순 계약을 위반했다. 이는 기존 파서가 계약을 잘못 구현했다는 증거가 아니다. 이후 새로운 표현 정책에서 유효 ID 집합을 정렬할 수는 있지만 원래 실패를 성공으로 바꾸거나 내용 품질을 입증하지 않는다. [구조 진단](../experiments/results/meetings-summary-mode-structural-diagnosis-v2.json)

## 독립 내용 검토

반환된 유효 요약1개를 모드·자기검토·시간 정보를 공개하기 전에 독립 AI 판단자가 기존 기준으로 검토했다. 원문 인용20개는 모두 문자열·좌표가 정확했다. 그러나 주장5개 중 전체 원문 기준으로 완전히 지원된 주장은1개, 부분 지원은4개였다. 선택한 인용 기준으로는5개 모두 부분 지원이었고 회의 핵심도 충분하지 않았다. 읽기 쉬운 한국어와 사실적으로 충분한 요약은 서로 다른 조건이다. [잠긴 검토 결과](../experiments/results/meetings-summary-mode-review-v2.json)

오류 주제는 다음과 같다. 같은 주장에 여러 오류가 있어 합계8건을 서로 다른8개 주장으로 세지 않는다.

| 주제 | 해당 주장 수 |
| --- | ---: |
| 원문이 확정하지 않은 관계·목적을 덧붙이거나 변경 | 3/5 |
| 계획·완료 상태 또는 시간 범위 변경 | 3/5 |
| 주장 일부에 필요한 근거를 선택 인용에서 누락 | 2/5 |

원래 판단을 잠근 뒤 모델의 자기검토와 대조했다. 모델은5개 주장 모두 지원되고 핵심도 충분하다고 답했다. 전체 원문 기준 판정과4개, 선택 인용 기준 판정과5개가 달랐다. 자기검토 라벨이 사실 보증이 될 수 없다는 한 사례이며, 이 표본만으로 일반 오류율을 추정하지 않는다. [자기검토 비교와 분모](../experiments/results/meetings-summary-mode-self-review-v2.json)

## 다음 개발 판단과 면접 설명

다음 개선은 인용 번호의 형식 처리와 별개로 관계·시점·상태의 변형, 복합 주장에 빠진 근거, 문서 핵심 누락을 다뤄야 한다. 기존 관계 묶음과 추가 재작성도 개선하지 못한 결과가 있으므로 같은 방식의 반복을 자동 선택하지 않는다. 새 설계는 일반 코드와 안전한 오류 집계만 사용하고 다른 개발 자료의 기준을 출력 전에 확정한다. 이미 종료된 시도나 보호 평가 자료를 재튜닝하지 않는다.

면접에서는 “인용 문자열 일치20/20이었지만 주장 전체의 지원은 통과하지 못했다. 따라서 구조 검사, 원문 대비 의미 검토, 문서 핵심 포함 여부를 별도로 측정했다”라고 설명할 수 있다. 이 판단과 구현·검사는 AI가 수행했으며 사용자의 직접 검수는 아직0이다. 사용자는 이후 실제 화면에서 원문과 요약을 비교하고, 어떤 조건·상태 누락을 업무상 허용할 수 없는지 직접 판단해야 한다.
