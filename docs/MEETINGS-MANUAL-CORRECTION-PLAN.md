# 회의 분석 수동 보정 최소 완결 계획

2026-10-27 · 설계만 완료. 사람이 AI 초안의 누락·오추출·잘못된 근거를 고쳐 저장하고 작업·결정 화면에서 확인하는 흐름이다. 모델 품질 개선과 독립적이며, 사용자 검수·전체 1차 완료를 뜻하지 않는다.

## 현재 계약과 구현 판단

- `MeetingViews.tsx:117-143`은 기존 항목의 문구·분류·상태·담당자·기한·우선순위를 편집하지만 항목 추가/삭제와 항목 근거 교체는 없다. v2 요약 문장/근거 추가·삭제와 메타데이터 편집은 이미 있으므로 보존한다.
- `MeetingController.java:27`, `MeetingService.java:31-39`의 소유자 전용 전체 analysis PUT이 항목 배열 교체, revision/version CAS, 사용자 수정 스냅샷을 이미 지원한다. 새 endpoint·테이블·작업 전용 PATCH는 만들지 않는다.
- `MeetingAnalysis.java:29-34,69`는 고유 ID·필수 필드·종류별 상태·정확한 codepoint 인용을 검증한다. items는 0~150개이므로 마지막 항목 삭제도 가능하다. 원문·AI 원본·기존 summary v1/v2 계약을 유지한다.
- `MeetingService.java:72-81`은 확정 결정의 전체 항목 스냅샷이 달라지면 연결을 현재 목록에서 제외하고, 작업 목록은 활성 분석에서 다시 산출한다. 연결과 무관한 작업 편집으로 결정 연결을 없애지 않는다.
- `useMeetings.ts:132-218`과 기존 편집 복구·저장 대기 구현을 확장한다. 준비된 현재 분석의 소유자 보정이 범위이며, failed/stale 분석에서 새 분석을 시작하는 기능은 추가하지 않는다.

## 사람의 보정 흐름

- 분석 편집에 `항목 추가`를 두고 논의·제안·결정·미해결·후속 작업 중 종류를 고르게 한다. 150개 한도·빈 목록 상태에서도 다음 행동을 안내하고 새 항목 내용으로 초점을 이동한다.
- 추가 시 클라이언트 UUID를 한 번 발급하고 초안·재시도·행 key에 유지한다. 기존 ID는 보존한다. 서버는 수동 ID의 고유성을 검증하며 AI 항목 ID의 서버 발급 경로는 바꾸지 않는다.
- 새 항목은 내용과 원문 근거가 필수, 상태는 `needs_confirmation`, 담당자/기한/우선순위는 null로 시작한다. 명시 저장 전에는 서버 작업·연결 목록에 나타나지 않는다.
- 항목 삭제는 초안에서만 제거하고 `삭제 취소`로 같은 ID·입력·순서를 복원한다. 삭제/되돌리기 후 가까운 항목 또는 추가 버튼에 초점을 돌려준다. 기존 원문·AI 초안은 삭제하지 않는다.
- 항목 내용은 공백만 허용하지 않고 3,000 codepoint, 근거 12,000, 담당자 200자 및 실제 날짜·종류별 상태를 저장 전에 검사한다. 오류 항목에 안내·초점을 제공하고 잘못된 PUT은 보내지 않는다.
- 비작업은 `needs_confirmation|confirmed`, 작업은 `needs_confirmation|todo|doing|done`만 제공한다. 종류 변경은 확인 필요로 돌리고 비작업의 담당자/기한/우선순위를 null로 정리한다.
- 확정 결정의 문구·분류·근거를 바꾸면 다시 확인 필요로 돌려 명시적 재확정을 받는다. 원문 인용의 구조적 일치가 결정 의미를 검증했다고 표시하지 않는다.
- 담당자·기한·우선순위·작업 상태는 기존 입력으로 수정한다. 원문에 없는 값은 기본 공란이며, 사용자가 보완한 배정은 사용자 수정으로 저장할 수 있다(`MeetingAnalysis.java:34`의 원문 포함 검사는 AI 출력에만 적용).
- 변경/삭제되는 결정에는 연결 재확인 안내를 붙인다. 현재 접근 가능한 연결만 근거로 보여주고 미조회/실패를 연결0으로 단정하지 않는다. 저장 뒤 유효 연결 목록을 새로 조회하며 자동 재연결하지 않는다.
- 저장 전 추가/삭제/수정 개수와 연결 영향 안내를 보여주고 전체 스냅샷을 한 번 저장한다. 성공한 응답의 version을 채택하고 작업·분석·연결을 갱신하며, 조회 실패를 저장 실패로 오인하지 않는다.

## 원문에서 근거 고르기

- 새 `SourceSpanPicker`는 기존 dialog/버튼/입력 스타일을 쓴다. 읽기 전용 전체 원문에서 마우스·터치 또는 Shift+방향키로 구절을 선택하고 `선택한 구절 사용`을 누른다. offset 숫자는 입력하거나 표시하지 않는다.
- 키보드/모바일 보조 경로로 정확한 구절 붙여넣기를 제공한다. 일치 위치를 앞뒤 문맥과 강조된 구절로 보여주고 사용자가 선택한다. 같은 구절이 반복돼도 첫 위치를 자동 채택하지 않는다.
- 서버가 반환한 NFC/LF 원문을 그대로 기준으로 삼는다(`Ingest.java:34-35`). textarea 값이 기준 문자열과 같은지 확인하고 UTF-16 선택 경계를 codepoint 경계표로 변환한다. 반쪽 surrogate 선택·불일치·빈 구절은 거부한다.
- quote는 기준 원문 slice에서 생성한다. trim/유사 검색/재정규화로 인용을 고치지 않는다. 한국어·영어·emoji/ZWJ·결합문자·반복 문장·여러 줄 선택에서도 quote와 위치가 정확히 일치해야 한다.
- 선택기 열기 전 기존 GET으로 현재 접근권한·원문 revision·분석 version/ready 상태를 확인한다. 같을 때만 기준 원문을 열고, 다르면 기존 충돌 복구로 보내며 draft나 근거를 자동 교체하지 않는다.
- 선택기 취소/Esc는 기존 근거를 유지하고 호출 버튼으로 초점을 돌린다. 선택기 안의 임시 구절은 적용 전 draft를 바꾸지 않는다. 다른 항목·회의·workspace·세션의 늦은 조회/선택 결과는 무시한다.
- 항목 근거 교체에 이 선택기를 사용하고 기존 요약/메타데이터 구절 선택에도 같은 위치 선택 방식을 공유한다. summaryProjection·v2 문장/근거 상한과 정렬·중복 검사는 유지하며 자동 v1 변환은 금지한다.

## 미저장·충돌·접근 변경

- basis와 전체 draft의 차이로 미저장 표시를 만들고 추가/삭제/근거/필드 변경을 모두 포함한다. 초안은 현재 화면 메모리에만 두며 localStorage나 별도 서버 초안 저장은 추가하지 않는다.
- 취소·편집 닫기·목록/다른 화면/workspace 이동은 수정이 있으면 `계속 편집 / 버리고 이동`을 묻는다. 단일 등록식 leave guard를 useDocTrail에서 호출하고, 선택 전 navigation/context 토큰이나 화면을 바꾸지 않는다.
- 실제 페이지 종료/새로고침은 dirty일 때만 beforeunload를 등록한다. 앱의 강제 세션 만료·접근 거부는 guard로 막지 않으며 서버본 선택은 기존 명시적 폐기 동작을 사용한다.
- 저장 중에는 기존 fieldset 잠금에 추가/삭제/복원/근거 선택·취소를 포함하고 중복 제출과 임의 화면 이동을 막는다. 로그아웃 시도는 기존 요청 무효화를 유지하며 실패하면 초안을 유지하고 성공/만료면 폐기한다.
- 409는 전체 초안과 새 ID를 유지하고 서버본을 비교한다. 동일 원문 revision·ready·동일 summary 계약일 때만 명시적으로 새 version을 채택하고 다시 저장한다. 두 번째 경합도 CAS로 거절하며 자동 병합/재저장하지 않는다.
- 원문 수정/재처리로 revision이 바뀌면 이전 구절·추가 항목의 그대로 저장을 막는다. 접근이 유지될 때만 초안을 읽기/복사 가능하게 남기고 최신 서버본에서 재선택하게 한다.
- 401 또는 현재 회의의 403/404·삭제를 확인하면 선택기·편집기·원문·연결 캐시를 숨기고 기존 denyCurrentMeeting/sessionExpired 경로를 재사용한다. 저장 거부도 같은 처리에 합류시킨다.
- 422/네트워크/503은 초안과 오류를 보존하고 명시 재시도만 허용한다. 응답 유실은 서버 저장 여부가 불명확하므로 먼저 서버 version을 확인하며 성공으로 표시하거나 자동 중복 PUT하지 않는다.
- 저장/조회 응답은 기존 mounted·요청 번호·AbortController와 선택 회의/세션 문맥에 묶는다. 폐기된 응답이 새로운 초안·로딩·로그인을 바꾸지 못해야 한다.
