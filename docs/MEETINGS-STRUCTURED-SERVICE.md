# 구조화된 로컬 회의 요약·답변 후보

2026-10-31. 기존 Java/React 서비스에 연결하는 무료 로컬 개발 후보다. 실제 내용 품질과 최종 운영 검증을 마치기 전에는 기본 모델로 채택하지 않는다. 닫힌 QA 비교·경계 문법 실험·최종 평가 자료는 변경하지 않는다.

## 해결할 문제와 방법

기존 실제 답변에는 JSON 형식 오류와 근거 누락, 제안의 확정 오인이 함께 있었다. 분류 결과에서 원문 네 줄을 고르는 기능도 완전한 자연어 요약은 아니다. 새 후보는 이미 확보한 고정 모델과 prebuilt 실행기를 사용하며 추가 컴파일이나 유료 서비스를 요구하지 않는다.

- `meeting_structured.py`는 JSON-schema 출력과 엄격한 파싱을 연결한다. 원문 전체를 바탕으로 한국어 요약을 생성하고 근거·같은 모델의 검토·메타데이터/항목 추출을 조립한다. 같은 모델의 검토는 독립 평가가 아니다.
- `serve_meetings_structured.py`는 실제 모델 식별자와 설정을 노출하는 별도 실행 경로다. 기존 Qwen 실행기나 동결 모듈을 다른 모델인 것처럼 사용하지 않는다.
- 기본 후보는 Ministral이며, 명시적인 `--profile qwen25-7b-q4km-json-schema-grounded-v1`은 기존 Qwen2.5-7B 두 파일과 고정 실행기를 확인한 뒤 사용한다. 최초 파일 해시를 alias로 표시하고 두 파일의 해시와 GGUF revision을 함께 노출한다. 알려지지 않은 base 변환 revision은 null로 유지한다.
- `literal_optional_v1`은 모델이 선택한 제목·날짜·참석자·목적에 명시적인 원문 형식을 요구한다. 불명확한 값은 비우고 필드·단위 ID·이유만 진단에 남긴다. 분류값 자체를 맞았다고 바꾸거나 본문·요약 기준을 수정하지 않는다.
- Java의 인접 문맥 후보는 권한·필터·revision이 확인된 snapshot만 사용한다. 원래 답변 청크가10개 미만일 때 원래 순위 순서로 직전·직후 청크를 추가하며 같은 문서/revision/page와 기존 ID를 유지한다. 확장은 한 단계이고 최대10개다. 기본 옵션은 꺼져 있고 새 후보 실행기에서 명시적으로 켠다. 원래 검색 순위와 기록은 유지한다.

## 새 후보의 설정

입력6,144토큰·native context8,192토큰, QA/요약 출력 각각768토큰, 검토128토큰, 한 요청의 모든 단계에 공유되는120초 기한을 사용한다. 이전 전체 근거 표현의 실측4,471/4,470토큰이4,096을 넘었기 때문에 새 후보의 입력 한도를 명시적으로 정했다. 새 템플릿의 실제 토큰 수는 별도로 측정하며 초과 입력을 자르지 않는다. 자동 한도 확장이나 재시도는 없다.

기존 고정 로컬 GPU 경로와 CPU2스레드, 실행 소유권 잠금·모델 신원·프로세스 확인을 유지한다. 이 서비스 경로에는 확인된 수치형 VRAM 제한이 없다. GPU 메모리는 선택적으로 관측할 수 있지만 적재 적합성을 보장하지 않는다. 검색v6의 CPU-only 관측을 이 생성 후보의 GPU 적재·속도 증거로 사용하지 않는다. 실제 요청별 입력/출력 토큰, 종료 사유, 시간과 설정을 기록한다. 운영 로그에는 원문·질문·환경 값·raw 모델 응답을 넣지 않는다. 개발용 공개 자료의 원본 출력은 별도 로컬 결과에만 저장한다.

## 검증과 완료 판단

첫 실제v1의 [독립 진단](../experiments/results/meetings-structured-diagnosis-v1.json)은 chat 입력 계산과 출력 프레임의 연결 오류뿐 아니라 내용 오류도 확인했다. 고정 실행기의 같은 chat 입력 계산과 엄격한 출력 프레임 관계로 고쳤다. 7B v2는 시작했지만 [이전 회의 링크의 제목 오분류](../experiments/results/meetings-structured-v2-diagnosis-v1.json)로 실패했다. 새 선택 정보 정책을 적용한 [v3](../experiments/results/meetings-structured-service-v3.json)는 두 분석·두 답변을 모두 시도했고, 첫 요약 자체 검토 거절을 전체 실패로 남겼다. 나머지 세 건의 기술 완료는 내용 품질 수용이 아니다. 기본 모델로 채택하지 않았다.

자료는 기존 공개 OpenSearch 회의2건과 일반 규정 문서1건이다. 출처·본문·질문·참고 답변·보류 기준은 바꾸지 않는다. 자료의 날짜 불일치도 임의 수정하지 않는다. 두 질문은 개발 자료이며 held-out 평가가 아니다.

명시적인 `--qa-contract requested_facts_v1`은 언어·요청한 모든 사실·절차와 실제 확정 사실의 차이를 강조한 비교 경로다. `--qa-only` 개발 수집은 같은 세 문서를 일반 문서로 등록해 자동 분석 없이 두 답변만 요청한다. 기본 경로는 바뀌지 않는다. 이 비교의 기술 실행은2/2였으나 [독립 내용 수용은0/2](../experiments/results/meetings-qa-request-contract-v1.json)다. 새 DB와 문서 종류가 달라졌고 전체 확장 모델 입력의 일치는 캡처하지 않았으므로 엄격한 동일 입력 비교로 주장하지 않는다. 한국어 출력 개선만 확인했으며 이 옵션을 품질 개선이 입증된 서비스 기본값으로 사용하지 않는다.

`--qa-contract evidence_plan_v1 --qa-only`는 질문 전용 계획192토큰과 전체 원문 근거 표576토큰을 순서대로 만들고 직접 답변으로 조립하는 별도 실험 경로다. 한 요청120초·합산768토큰, 최대2HTTP/4native 요청을 유지하며 정확한 공개 개발 입력과 중간 결과만 로컬에 보존한다. 기존 기본값·요약·분류는 바뀌지 않는다. [실제v1](../experiments/results/meetings-evidence-plan-service-v1.json)은 첫 계획의 시점 표현이 원문과 달라 실패했으며 두 번째 질문은 미실행이다. [진단](../experiments/results/meetings-evidence-plan-v1-diagnosis.json)의 범위 누락과 표현 오류를 해결하기 전에는 서비스 권장 설정이 아니다.

`--qa-contract evidence_plan_v2_scope_refs --qa-only`는 중복 시점/대상 문자열 대신 원문 구절 번호를 참조한다. [실제v2](../experiments/results/meetings-evidence-scope-service-v1.json)는 첫 계획의 형식은 통과했지만 근거 행 누락과 의미 오류가 확인됐다. 형식 통과를 질문 이해나 근거 지지로 해석하지 않으며 이 경로도 기본 채택하지 않는다.

`--analysis-contract agenda_extraction_v1 --analysis-only`는 원문 전체와 명시적 안건·목록 관계로 요약/항목을 한 번에 추출한다. 내부475초(시작120·준비30·두 분석 각160·정리5), 외부510초, 실제 모델 호출 최대2회/전체 출력1,536토큰이며 QA는 요청하지 않는다. 한 분석의 공유120초·출력768토큰은 유지한다. [첫 실제 분석](../experiments/results/meetings-agenda-service-v1.json)은 단위 번호와 문자 위치 혼동으로 실패했고 언어·내용 오류도 확인했다. 두 번째 회의는 미실행이며 기존 분류/자체 검토 기본 경로는 보존한다. 현재 어떤 실험 경로도 의미 품질이 입증된 운영 설정으로 권장하지 않는다.

첫 실제 개발 흐름의 내부 기한은715초(준비120·작업590·정리5), 외부 관찰은750초이며 마지막5초를 정리에 남긴다. 작업590초는 준비 HTTP30초, 회의 등록/분석 확인 각160초, 답변 각120초의 상한에서 정했다. 최대2회 자동 분석과2회 답변을 순차 요청하며 첫 실패에서 남은 생성을 미시도로 보존한다. 분석 안의 최대160개 단위 분류도 모델 호출이므로 “모델4회”로 세지 않는다. 최악의 native completion 상한은326회, 요청 출력 토큰 합계는4,608이다. 실제 호출·토큰을 별도로 기록한다. 기존 native RSS6GiB·시작 가용 RAM8GiB·실행 중2GiB와 세 소유권 잠금을 유지한다. 이는 OS 자원 보장이나 실제 적재 성공이 아니다.

v3에서 명시적으로 사용한 개발 옵션 `--continue-content-failures`는 요청/native 종료와 idle 상태가 확인된 내용 검증 실패 뒤 다음 독립 요청만 수행한다. 같은 분석을 재시도하지 않으며 하나라도 실패하면 전체 결과와 종료 코드는 실패다. 기본 첫 실패 중단과 시간·요청·토큰 상한은 유지한다. 전송·프로토콜 무결성·시간·자원·정리 실패나 불명확한 상태에서는 계속하지 않는다.

같은 실행에서 얻은 AI 결과를 보존한 DB는 후속 Java-only 브라우저 검사에 사용할 수 있다. 그 경우 화면에서 실제 생성 결과를 읽었다는 사실과, 브라우저가 모델을 새로 호출하지 않았다는 사실을 함께 기록한다.

회귀 검사는 기본 옵션이 꺼진 동작, 원래 청크 보존·이웃 순서·경계·개수, 권한/세션/revision 변경 중 폐기, schema와 parser의 일치, 입력/출력·기한·정리·정보 노출을 확인한다. 실제 실행은 회의 등록→자동 요약→일반 문서와 통합 검색→자연어 답변→원문 확인을 연결한다. 형식·정확한 인용·내용 지지·충분성·제안/확정·한국어·담당자/날짜/null·답변 보류는 따로 판정한다.

저장된 검색 결과에 대한 인접 문맥의6/6 근거 포함 예상은 오프라인 예측이다. 실제 답변 품질로 기록하지 않는다. 실측·독립 AI 검토·사용자 검수·배포 상태는 [STATUS](STATUS.md)에 별도로 남긴다.
