# 모델 준비 단계만 분리하는 진단

2026-10-29. 진단 코드 `3eb727b`의 양쪽 필수 CI를 확인한 뒤 선택한 다음 설계다. [이전 중립 실패](MEETINGS-FREE-QA-NEUTRAL-RESULTS.md)의 정확한 원인은 여전히 미확정이다. 이 문서는 새 실제 실행 결과가 아니다.

## 해결할 문제

이전 실행은 답변 생성 전 실패했지만, 서버 준비 실패인지 그 직후 설정 확인 실패인지 구분할 정보가 부족했다. 다음 측정은 **같은 모델의 준비 확인 → 공개 설정 조회 최대 1회 → 정리**만 수행한다. 답변 생성과 요청 출력 토큰은 0이며 원문·질문·비공개 평가 기준을 읽지 않는다.

새 모델이나 요약 엔진으로 바꾸면 현재 실패 경로를 구분하기 어렵다. 기존 자산과 설정을 유지한 채 준비와 설정 확인을 나누는 것이 먼저다. 성공해도 토큰화·생성·답변 품질을 검증한 것으로 보지 않는다.

## 최소 코드 변경

- 기존 실행기의 모델 검증 부분을 분리한다. 모델 식별·정확한 profile/binding/runtime·취득 성공과 외부 종료·보존 기록 검사를 유지한다. QA 경로는 기존 비교 계약 검증 후 같은 공통 검사를 호출한다.
- 기존 자산 준비도 실제 검증된 모델 정보만 받도록 분리한다. 전체 파일 목록·해시·파일 신원·shard 내부 설정 검사는 유지한다. 가짜 QA 계약이나 PreparedModel로 우회하지 않는다.
- 기존 어댑터의 `/props` 순수 검증을 재사용한다. 모델 별칭·빌드·경로·문맥 크기·슬롯·awake 상태·template 해시를 확인한다.
- 새 작은 시작 진단 CLI와 관련 모형 검사를 추가한다. 기존 QA 어댑터·epoch 실행·생성 메서드는 호출하지 않는다. 새 실행 프레임워크나 관찰 서버는 만들지 않는다.

## 별도 실행 조건

닫힌 비교의 계약·신뢰 파일·once·출력은 유지한다. 새 진단은 별도의 로컬 신뢰 목록, 공개 모델/소스 참조, 출력 위치와 once로 검증하며 등록 파일이 스스로 권한을 부여하지 못하게 한다. 진단 결과는 QA의 성공 선행 결과로 사용할 수 없다.

현재 단계는 구현·합성 검사·독립 검토·게시 소스 CI까지다. 이후에만 새 공개 실행 파일 후보를 준비·검토하고, 정확한 별도 실행 배정을 만든다. 실제 실행자는 직전 충돌·조회 가능성과 lease를 확인하며, 조건 실패 시 다른 프로세스를 종료하거나 통과할 때까지 재시도하지 않는다.

## 검증과 결과 해석

기존 QA 검증·자산 준비·어댑터 동작을 회귀 검사하고, 새 진단은 잘못된 권한·모델/자산·준비 오류·두 오류 동시 발생·설정 응답 실패/초과·정리·once·생성 0 조건을 모형으로 검사한다. 공개·비공개 자료를 복제한 새 fixture 묶음은 만들지 않는다.

- 준비 실패: 기록된 준비/자원/소유권 오류만 해석한다. 이전 실패의 원인이나 GPU OOM으로 소급하지 않는다.
- health 성공 후 props 실패: 새 실행의 준비 성공과 설정/전송/식별 실패를 구분한다.
- health·props·정리·보존 모두 성공: 그 설정의 준비와 공개 식별 확인만 수용한다. 생성·품질 검사는 별도 설계가 필요하다.
- 원인 없는 조기 종료·정리 불확실·저장 실패: 실패를 유지하고 그 증거로 다음 조사만 정한다. 자동 반복하지 않는다.

첫 측정에는 native 로그 분류기를 추가하지 않는다. 기존 명령은 로그를 비활성화하고 이전 실행도 출력 0바이트였으므로, 우선 구조화된 오류로 실패 구간을 구분한다. 여전히 불명확하면 별도의 관측 설계를 판단한다. 한도·모델·로그 설정을 자동 변경하지 않는다.

설계는 Astra xhigh의 공개/안전 입력 15개 검토에 근거하며, 부모가 결정문과 입력 16참조를 대조했다. 원본 설계 영수증 SHA는 `a8d9a7db13c9a6bbdf527e9db8bf92623f08a2ef717824183e798ec3ae9f3b20`다. 사용자 검수와 새 실제 실행은 0이다.

## 현재 구현과 재현

기존 실행기·어댑터의 공통 부분과 새 `scripts/probe_meeting_free_qa_startup.py`를 구현했다. `verify`는 별도 신뢰·등록의 메타데이터만 검사하며 실제 가중치를 준비하거나 실행하지 않는다. `run`은 정확한 등록 SHA와 once를 요구하는 별도 실제 실행 진입점이다. 독립 검토 뒤 별도 로컬 신뢰·등록 파일을 설치했고 공식 메타데이터 검사 1회가 종료 0·1.703초로 통과했다. 이후 실제 시작 진단 1회는 준비 확인 뒤 설정 검증에서 중단됐고 once는 소비됐다. [실제 결과와 보존 검증 실패](MEETINGS-FREE-QA-STARTUP-RESULTS.md)를 성공이나 QA 선행 조건으로 바꾸지 않는다.

관련 QA 189개와 새 진단 65개, 총 254개·Ruff가 통과했다. 초기 모형 오류와 수정 결과는 [구조화 기록](../experiments/results/meetings-free-qa-startup-implementation-v1.json)에 보존했다. 독립 Astra xhigh 변경 검토는 차단 0·권고 0으로 완료했다. 공유 검증/준비 조건과 기존 QA 실행·once·종료 흐름의 보존을 확인했다. 게시 커밋2bda334의 양쪽 필수 CI는 모두 통과했다. Python 5,327개 통과·21개 제외, 브라우저 158개 통과와 실제 Java 운영 검사는 [CI 기록](../experiments/results/meetings-free-qa-startup-ci-v1.json)에 별도로 남겼다. 이는 실제 모델 준비·답변 품질 검증이 아니다.

```sh
python -B -m pytest tests/test_meeting_free_qa.py tests/test_meeting_free_qa_startup.py -q -p no:cacheprovider
ruff check tools/free_qa/runner.py tools/free_qa/adapter.py scripts/probe_meeting_free_qa_startup.py tests/test_meeting_free_qa.py tests/test_meeting_free_qa_startup.py --no-cache
```

잠긴 의존성을 사용한다. Windows의 합성 하드링크 fixture는 해당 파일 생성 권한이 필요하다. 위 검사는 모델을 실행하지 않는다. 실제 실행의 등록·명령·관찰 기록은 [결과 JSON](../experiments/results/meetings-free-qa-startup-actual-v1.json)의 로컬 원본 참조로 연결한다. 소비된 실행은 재시도하지 않는다. 이 문서의 종료 시점 바이트도 별도로 보존했으며, 향후 고정 보존 목록에 들어간 문서는 실행 중 갱신하지 않는다.
