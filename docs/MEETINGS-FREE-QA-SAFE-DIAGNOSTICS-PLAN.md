# 무료 QA 실행 진단 정보 보완

2026-10-29. [중립 실제 실패](MEETINGS-FREE-QA-NEUTRAL-RESULTS.md)의 정확한 원인은 현재 증거로 확정할 수 없다. 독립 Astra xhigh 분석은 안전한37참조와 공개 코드9개를 확인했고, 기존 실행기에서 의미 있는 내부 오류 코드가 사라지는 문제를 다음 수정 대상으로 정했다. 유료 서비스나 다른 모델 탐색, 닫힌 시험 재실행은 이번 범위가 아니다.

## 문제와 선택

실제 실행은 네이티브 프로세스 기동과 시작 자원 표본430개를 남겼으나 어댑터 적재 단계 기록은 없다. 실패 범위는 네이티브 준비 또는 그 직후 어댑터 적재 전 설정이다. 준비가 잠시 성공했는지는 확정하지 못한다. 표본 RSS·가용 RAM 수치만으로 누락된 실패 표본이나 VRAM 상태를 추정하지 않는다.

공유 자원 검사기의 안전한 ValueError 문자열은 현재 일반 free_qa_boundary로 변환된다. 준비 확인 중 발생한 오류를 자원 검사기가 종료하면서 다른 오류로 덮을 수도 있다. 기존 보고서에는 그 둘을 나눠 볼 정보, 단계별 시간, 정리 전 프로세스 종료 코드가 없다. 경과 시간만 보고 제한 시간을 늘리거나 모델 품질 실패로 결론내리지 않는다.

## 구현 범위

- 기존 tools/free_qa/runner.py에 자산 준비, 네이티브 준비, 어댑터 구성·적재, 생성 진입, 최종 보존 확인의 고정 단계와 경과 시간을 기록한다.
- 이미 정의된 안전한 내부 오류 코드만 허용 목록으로 보존한다. 알 수 없는 오류 내용·HTTP 본문·명령의 토큰·질문·답변·네이티브 로그는 노출하지 않는다.
- 준비 확인의 원래 오류와 자원 검사기의 마지막 오류를 구분하고, 확인 가능할 때 정리 전 프로세스 종료 코드를 기록한다.
- 기존 보고서와 정리 메타데이터를 활용한다. 종료 스키마·자원 및 시간 상한·모델·프롬프트·입력은 유지한다.

새 실행 프레임워크를 만들지 않는다. 이미 실패한 시험을 수정된 코드로 재실행하지 않고 원래 소스192a4e3와 실패 출력·계약·once를 보존한다.

## 검증과 완료 기준

기존 합성 프로세스·시계 도구로 준비 시간 초과, 프로세스 조기 종료, 자원·소유권 오류, 오류 두 개의 동시 보존, 적재 전 구성 실패, 알 수 없는 비공개 문자열의 차단을 검증한다. 정리·once·후속 실행 제한의 기존 동작도 유지해야 한다.

관련 QA 검사와 정적 검사를 통과한 뒤 독립 변경 검토와 게시 소스의 필수 CI를 수행한다. 이는 진단 기능의 구현 검증이며 실제 모델의 기동 성공이나 답변 정확성을 입증하지 않는다. 이후 네이티브 준비 원인을 직접 측정할 필요가 남으면 별도 설계를 먼저 정한다. 이번 계획에는 실제 모델 호출이 없다.
