# 소스 다운로드의 HTTPS 연결 재사용

2026-10-30 · 오류 보존 지적의 수정·재현 검사 완료, 최종 변경 검토 통과, 게시·필수 CI 대기. 실제 취득 시간 단축이나 엔진·모델 품질을 입증한 결과가 아니다.

파일 모드 결함 수정은 [3aa8dfb의 필수 CI](../experiments/results/meetings-summary-source-mode-ci-v1.json)를 통과했다. 하지만 종료된 v6의 실제 자료만으로 전체 소스 취득이 시간 안에 끝난다고 판단할 수는 없다. 고정 tree의 선택 파일은1,687개·33,232,611바이트다. 실패 전 받은53개·613,714바이트의 관측을 전체 완료 시간으로 확대하지 않는다.

현재 소스 전송은 파일마다 urllib opener를 만든다. 확인한 Python 표준 라이브러리는 요청에 `Connection: close`를 지정하므로 opener 객체만 공유해도 연결이 재사용되지는 않는다. 다음 수정은 **소스 다운로드 단계에서만 HTTPS 연결 하나를 재사용**하는 것이다. 소스 선택과 요청 순서를 유지하며1,687개 GET 자체를 줄이지는 않는다. TLS 연결 비용이 전체 시간에서 차지하는 비중과 실제 개선 폭은 아직 측정하지 않았다.

표준 라이브러리를 사용하고 추가 패키지나 별도 서비스는 도입하지 않는다. 도구·메타데이터·라이선스 다운로드는 기존 경로를 유지한다. 같은 허용된 서버에서 응답 본문을 완전히 읽은 경우에만 연결을 재사용하고, 오류·불완전 응답·크기 초과·redirect·조기 종료에서는 연결을 닫는다. redirect 본문을 숨겨서 읽거나 버리지 않는다. 실패한 요청을 자동 재전송하지 않으며 서버가 연결을 닫았을 때 다음 파일의 새 연결과 구분한다.

기존 HTTPS·호스트·포트·인증서 검증, redirect 제한, 본문 사용량 집계, 파일 크기·SHA-256·Git blob 검증, 경로 검사와 공유 deadline을 유지한다. 병렬 다운로드나 새 시간 옵션은 추가하지 않는다. 한 단계가 끝나거나 실패하면 소유한 연결을 닫는다.

Git partial/sparse 전송은 선택 blob을 묶어 받을 가능성이 있지만, 기존 acquire 실행 허용 목록과 Git helper·config·filter·hook 통제, 소비한 응답 바이트 집계까지 변경해야 한다. 전체 archive나 실패 폴더의 부분 파일 재사용도 현재 경계와 맞지 않는다. 이번에는 기존 byte 검증 경로를 재사용하는 작은 연결 변경을 선택했다.

가짜 소켓과 실제 표준 라이브러리 응답 파서로 집중70개를40.18초에 통과했다. 연속 두 파일의 재사용·정확한 본문 집계, 서버 종료 뒤 다음 파일의 새 연결, redirect·오류·잘림·조기 종료·기한 만료 시 정리와 재전송0을 확인했다. 최초 기능 실패는0이었다. 최초 Ruff 지적2개를 보존하고 주석과 동등한 테스트 구문만 정리해 관련1개 검사와 정상 Ruff를 통과했다. 전체70개는 반복하지 않았다. [검사 결과](../experiments/results/meetings-summary-source-https-v1.json).

가짜 소켓은 실제 TLS 접속이나 원격 서버가 연결을 얼마나 유지하는지 검증하지 않는다. 실제 네트워크 속도나 모델 품질 검사로 해석하지 않으며 독립 변경 검토·정확 CI 상태는 [STATUS](STATUS.md)를 따른다.

첫 독립 검토는 HTTP 상태·금지 redirect를 거절한 뒤 수동 close도 실패하면 정리 오류가 최초 실패를 덮는 경로를 지적했다. 초기 검사는 phase 본문 오류의 정리만 확인해 이 경로를 놓쳤다. 초기 소스·통과 결과·검토를 보존하고 새 close 메서드와 해당 가상 회귀 검사만 수정한다.

수정 전 새10개 중6실패·4통과로 이 문제를 재현했다. close 한 메서드에서 활성 최초 예외를 유지하고 정리 실패를 부가 정보로 남기도록 수정했다. 최초 오류가 없을 때에는 정리 오류를 숨기지 않고 전달한다. 수정 후 새10개와 관련19개, 총29개가0.86초에 통과했고 정상 Ruff도 통과했다. 기존70개를 전부 반복하지 않았으며 첫 검토와 재현 실패는 그대로 남긴다.

재검토에서 원래 오류 없이 응답과 연결의 정리가 함께 실패하면 두 번째 오류가 첫 오류를 덮는 조합을 추가로 확인했다. 수정 전1개 실패를 보존하고 연결 정리의 finally만 보완했다. 처음28개 통과·메모 기대값2개 실패 후, 정확한 오류 위치에 맞춘 기대값2개만 재검사해 통과했다. 최종30개 고유 사례와 Ruff가 통과했으며 최초 오류의 동일성·부가 메모·연결 정리 시도와 소유 상태 초기화를 확인했다. 이전70개·29개 검사와 중복되므로 합산한 고유 검사 수를 주장하지 않는다. 최종 변경 검토는 차단0·권고0으로 끝났으며 해당 소스의 필수 CI를 확인한다.

기존600초·새 고정1800초 정책, 정리5초, 다운로드512MiB·저장4GiB·메모리 제한과 빌드·native 예산은 바꾸지 않는다. v6 실패와 소비 기록도 유지한다. 이 코드 수정은 새 취득이나 자동 재시도를 승인하는 절차가 아니다.
