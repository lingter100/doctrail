# 한글 경로에서 발생한 CMake 오류

2026-10-31. 실제 로컬 진단과 검증된 호환 실행기 구현을 구분한다. 전체 엔진 빌드·문법 검사·모델 품질 수용은 아직 완료하지 않았다.

## 임시 파일 삭제 경합

[ASCII 별칭을 적용한 v3](../experiments/results/meetings-summary-compat-build-v3.json)는209.578초 후 구성 단계에서 실패했다. 실행 중 출력 용량 검사에서 임시 `.o` 파일을 찾지 못했다. Windows 오류 보고 프로세스는 관찰되지 않았으며 알려진12개 프로세스 종료와 드라이브 해제를 확인했다. 전체 traceback이 없어 특정 Python 줄에서 발생했다는 판단은 소스와 저장 결과에 근거한 추론이다.

후속 수정은 호환 드라이버의 configure/compile 호출 중에만 별도 검사를 적용한다. 고정 runtime의 실행 중 검사 callback 코드 객체와 해당 출력 루트가 정확히 일치할 때, 개별 파일 정보 조회의 `FileNotFoundError`만 다룬다. 루트·별칭·파일 신원을 재확인하고 사라진 항목을 기록한 뒤 다음 체크포인트를 실행한다. 권한 오류·다른 OS 오류·링크·경로 이탈·시간/용량 제한은 계속 실패하며 원본 inventory·입력·결과 저장 검사는 기존 함수를 사용한다. 호출이 끝나면 원래 검사를 복원하고 실행 기록에 정책·원 runtime·단계별 누락 수·복원 여부를 남긴다.

원래 BUNDLE/runtime 파일과 취득 수용 기록은 변경하지 않는다. 관련25개 가상 검사와 Ruff를 통과했으며 실제 수정 후 빌드 효과는 아직 확인하지 않았다.

첫 호환 실행은 컴파일 전 `inventory_changed`로 정상적인 오류 종료1·0.344초 만에 끝났다. 별도 원인 확인에서 승인된12파일의 BUNDLE에 자동 생성 캐시1개가 추가된 것을 발견했다. 캐시는 이번 실행보다 약37분 먼저 존재했고 생성 주체는 확인하지 못했다. 해당38,275바이트를 BUNDLE 밖에 보존하고 승인된12개 목록·해시가 모두 같은지 확인했다. 검사 완화·소스 변경·이전 실패 삭제는 하지 않았다. [실행 실패 기록](../experiments/results/meetings-summary-compat-build-v1.json).

복구 후 [두 번째 실행](../experiments/results/meetings-summary-compat-build-v2.json)은 CMake 사본8,032개를 검증하고 C/C++ 컴파일러 식별용 컴파일·링크의 종료0을 확인했다. 이후 구성 단계에서 Windows 오류가 재발했다. 마지막 완전 trace는 CMakeFindBinUtils의 도구 이름 목록 작성이며 실제 오류 명령과 대상은 미확정이다. 전체171.031초·자연 종료1, 엔진 컴파일0이고 내부 정리 오류도 보존했다.

## 일관된 ASCII 실행 경로

기존 Windows 짧은 경로9개는 같은 파일을 가리키지만 한글이 남아 있어 대안이 되지 않았다. 추가 CMake 한 줄 수정을 추측하는 대신, 비어 있는 드라이브에 저장소의 임시 ASCII 별칭을 연결하는 선택적 `--native-drive` 어댑터를 구현했다. 원본·취득·소스 검증은 실제 경로를 유지하고 native 명령·작업 폴더·PATH·TEMP/TMP·출력 root만 일관되게 별칭화한다. 동일 파일과 정규 경로의 동일성을 확인하며 기존 실행·trace 검사는 완화하지 않는다.

기존 드라이브는 사용하지 않고, 이번 실행이 만든 동일 대상 연결만 소유 자식 종료 확인 후 해제한다. 실패 시 최초 오류와 정리 오류를 따로 보존한다. 연결 조회와 생성은 원자적 예약이 아니므로 바뀐 연결을 관찰하면 삭제하지 않고 실패한다. 과거 연결을 계속 유지하지 않으며 이후 native 검증도 새 연결을 사용한다.

[가상 검사와 독립 소스 검토](../experiments/results/meetings-summary-native-drive-implementation-v1.json)를 마쳤다. 누적 고유81개이며 마지막 영향 검사31개가14.68초에 통과했다. 실제 Windows 연결·경로 해석·native 실행은 아직0이다. 기존 한 줄 수정과 자원·시간 한도는 유지한다.

## 문제와 관측

새 오프라인 취득 검증은 정상 종료했지만 첫 빌드가 구성 단계에서 Windows 오류 보고 프로세스를 감지해 중단됐다. 보호 규칙은 그대로 유지했고, 실패 원본·정리 오류·부분 파일을 보존했다. 처음에는 오류 대상 PID를 기록하지 못했으므로 특정 도구를 원인으로 단정하지 않았다.

| 별도 진단 | 실제 결과 | 알 수 있는 범위 |
| --- | --- | --- |
| 고정 Ninja 버전 | 자연 종료0, 0.109초 | 해당 명령 단독 실행 정상 |
| 고정 Ninja 코드페이지 | 자연 종료0, 0.093초 | 해당 명령 단독 실행 정상 |
| 기존 CMakeLists 첫11줄 최소 구성 | 0.391초 후 보호 종료 | 오류 보고 대상이 이번 CMake 자체임을 확인 |
| 동일 길이 ASCII·한글 경로 변환 | ASCII 완료, 한글 시작 뒤 오류, 0.281초 | 두124문자 문자열에서 한글6글자를 영문6글자로 바꾼 차이로 실패 구간을 분리 |
| 대체 변환으로 C/C++ 영문·한글 네 경로 | 기대 문자열과 모두 일치, 자연 종료0, 0.094초 | 이 네 canonical 경로에서 대체 연산 정상 |

각 진단은 새 디렉터리의 별도 단일 실행이다. 원래 빌드 재시도나 모델 생성은 아니다. 시간은 작은 진단의 실측이며 서비스 응답 시간이나 일반 성능 수치가 아니다. 보호 종료된 CMake의 자연 예외 코드는 관측하지 못했다. [기계 판독 결과](../experiments/results/meetings-summary-build-diagnostics-v1.json)에 범위와 실패를 남겼다.

## 선택한 수정

고정 CMake3.31.8의 [컴파일러 경로 변환](https://github.com/Kitware/CMake/blob/dbe9d4593f4b7a2b1eb87826949f09af0268240a/Modules/CMakeDetermineCompiler.cmake#L115-L127)은 `cmake_path(CONVERT … NORMALIZE)`를 사용한다. [해당 구현](https://github.com/Kitware/CMake/blob/dbe9d4593f4b7a2b1eb87826949f09af0268240a/Source/cmCMakePathCommand.cxx#L638-L653)은 경로 객체의 정규화를 거친다. 새 사본에서 이 한 줄만 `file(TO_CMAKE_PATH …)`로 바꾸는 제한된 우회를 선택했다. [대체 구현](https://github.com/Kitware/CMake/blob/dbe9d4593f4b7a2b1eb87826949f09af0268240a/Source/cmFileCommand.cxx#L1699-L1730)은 문자열 구분자를 변환한다.

대체 연산은 일반적인 경로 정규화와 동치가 아니다. 고정 C/C++ 컴파일러 값이 단일 절대 canonical 경로이며 `.`·`..`·경로 목록·확장 경로 접두어가 없다는 조건을 확인해야 한다. 다른 형태를 조용히 고치거나 허용 범위를 넓히지 않는다. 내부 라이브러리의 정확한 예외 원인이나 공식 upstream 수정까지 확인했다고 주장하지 않는다.

## 원본 보존과 검증 경계

새 전용 실행기는 기존 취득 수용을 읽기 전용으로 검증한다. 새 출력 위치에 CMake 패키지만 복사해 정확한 원본 해시·한 줄 치환·파생 목록을 기록한다. LLVM·Ninja·llama 소스와 기존 BUNDLE은 원본을 사용하고, 실패 디렉터리나 이전 실행 표시는 바꾸지 않는다. 전체 도구의 재다운로드나 프로젝트 폴더 이동은 필요하지 않다.

새 빌드 결과에는 원래 취득 근거와 새 실행기·파생 도구·새 실행 파일의 근거를 분리한다. 이를 새 취득 성공으로 표시하지 않는다. 원래900초 빌드·정리5초·병렬2와 메모리·실행 허용 규칙을 유지한다. 디스크4GiB 검사는 새 쓰기 가능한 출력 전체에 적용하며, 따로 보존하는 읽기 전용 원본의 바이트 수는 구분한다. 원본과 새 출력 합산 최고 사용량4GiB를 보장한다는 뜻이 아니다. 이후 별도 native 문법 검증도 원본 취득과 새 빌드 결과를 함께 확인하며 기존60초 조건을 사용한다.

이 연결의 [구현·가상 검사·독립 코드 검토](../experiments/results/meetings-summary-compat-implementation-v1.json)를 마쳤다. 고유56개 검사를 여러 실행에서 확인했으며 전체56개 재실행으로 합치지 않는다. 최종 성공 기록 자체가 용량 한도를 넘길 수 있다는 검토 지적은 수정 전4개 실패로 확인하고, 수정 후 관련8개 통과로 검증했다. 실제 CMake 복사·빌드는 아직 실행하지 않았다. 작은 대체 연산이나 가상 검사 통과가 실제 엔진 빌드 성공·모델의 올바른 요약을 보장하지 않는다. 설계·검토·실행은 AI 기여이며 사용자 검수는0이다.
