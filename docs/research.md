# DocTrail 조사 기록

확인일: 2026-10-12. 이 문서는 공개 자료를 바탕으로 프로젝트 방향을 정한 기록이다. 사용자 인터뷰, 시장 수요 검증, 경쟁 제품 실측 비교를 수행했다는 뜻은 아니다. 채용 공고의 조회일과 게시일, 현재 접수 여부는 구분한다.

## 결론

DocTrail은 작은 개발팀의 온보딩·운영 문서에서 질문에 맞는 원문 근거를 찾는 도구로 시작한다. 한국어 질문, 영어 기술 용어, 한국어·영어 문서가 섞인 검색을 핵심 실험 대상으로 삼는다. 차별화 목표는 새로운 검색 기능의 발명이 아니라 **공개 가능한 데이터, 동일 조건의 모델 비교, 권한·수정·삭제 실패 사례까지 재현할 수 있는 평가 과정**이다.

기능만으로 기업용 검색 제품을 대체한다고 주장하지 않는다. 포트폴리오에서는 문제를 데이터와 지표로 바꾸고, 약한 기준선부터 개선하며, 결과가 나빠진 경우도 설명하는 AI 엔지니어링 역량을 보여준다.

## 데이터 후보와 적용 범위

첫 공개 코퍼스 후보는 Kubernetes 공식 문서의 한국어·영어 페이지다. 기술 용어, 운영 절차, 오류 대응, 번역 대응 문서가 있어 혼합 언어 검색을 실험하기에 적합하다. 이는 공개 기술문서이므로 실제 회사의 비공개 장애 보고서 분포를 대표하지 않는다.

저장소의 [LICENSE](https://github.com/kubernetes/website/blob/main/LICENSE)는 CC BY 4.0이다. 수집은 특정 커밋의 문서 본문으로 제한하고 출처·저자 또는 프로젝트 귀속·라이선스 링크·변경 내역을 보존한다. 자료별 별도 표기가 있으면 먼저 확인한다. [공식 문서](https://kubernetes.io/docs/home/), [CC BY 4.0 안내](https://creativecommons.org/licenses/by/4.0/)를 기준으로 attribution 파일을 만든다. 자동으로 1,000개가 확보됐다고 쓰지 않고 수집·정제 후 실제 문서와 문서 계열 수를 센다.

가상 팀의 온보딩 문서·런북은 권한과 수정 시나리오를 재현하는 보조 자료로 직접 만들 수 있다. 반드시 `synthetic`으로 표시하며 실제 고객·실제 장애·사용자 인터뷰 결과처럼 소개하지 않는다. 유료 문서, 실제 사내 자료, 개인 GitHub 비공개 저장소는 기본 데이터 원천이 아니다.

## 모델과 평가 방향의 근거

[BEIR 논문](https://arxiv.org/abs/2104.08663)은 여러 영역에서 BM25가 유효한 기준선이며 재순위화 성능에는 계산 비용이 따른다는 점을 보여준다. 이 결과를 DocTrail의 성능으로 가져오지 않고, BM25→밀집 검색→혼합 검색→재순위화를 같은 데이터에서 비교할 이유로 사용한다.

초기 임베딩 후보는 [multilingual-e5-small 공식 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small)다. 한국어를 포함하는 다국어 모델이며 MIT로 배포된다. 384차원, 최대 512 토큰, 검색 질의와 문서에 서로 다른 접두사를 사용하는 규칙을 따른다. 한국어 기술문서 성능은 직접 평가해야 한다.

재순위화 후보인 [bge-reranker-v2-m3 공식 모델 카드](https://huggingface.co/BAAI/bge-reranker-v2-m3)는 다국어와 Apache-2.0을 명시한다. 후보일 뿐 채택·실행 완료가 아니다. RTX 4050 6GB에서 문서 길이와 배치 크기별 메모리·지연시간을 확인한 뒤 결정한다. 점수에 sigmoid를 적용해도 정답 확률로 보정된 것은 아니다.
