# 회의 항목 보정과 정확한 원문 근거 선택

2026-10-27. 회의의 AI 초안을 보존하면서 사용자가 누락된 작업을 추가하고 잘못된 항목·근거·담당자를 수정하는 화면을 구현했다. 실제 Java 저장과 브라우저 검증을 마쳤으며 게시 소스 CI는 별도로 확인한다. 실제 AI 요약·답변의 의미 품질 통과를 뜻하지 않는다.

## 사용 흐름

회의 상세의 **분석 편집**에서 항목을 추가하거나 삭제하고, 저장 전 삭제를 취소할 수 있다. 원문 근거는 읽기 전용 문장에서 구절을 선택하거나 정확한 문구를 붙여넣고 위치를 직접 고른다. 반복되는 문구의 첫 위치를 자동 채택하지 않는다. 담당자·기한·상태와 요약/제목의 근거도 수정한 뒤 전체 수정본을 저장한다.

새 항목은 확인 필요로 시작한다. 확정 결정의 내용·종류·근거를 바꾸면 재확인을 요구하고 기존 결정 연결에 미칠 영향을 안내한다. 저장한 항목은 작업 목록·필터·재조회·재로그인에 반영되며 AI 초안과 원문은 유지된다. 삭제 취소는 미저장 편집에만 적용하며, 저장된 삭제를 복구하는 휴지통 기능은 아니다.

저장 전 이동에는 초안 폐기 확인, 저장 중에는 중복 제출·이동 차단이 적용된다. 원문이 바뀌면 옛 근거를 그대로 저장하지 못한다. 권한 회수·세션 만료 때는 원문과 초안을 숨긴다. 충돌에서는 사용자 선택으로 최신 version을 채택하며 자동 병합·재저장하지 않는다. 초안은 현재 화면 메모리에만 있다.

## 구조와 선택 이유

기존 revision/version 확인을 포함한 전체 분석 PUT을 사용한다. 새 Java API·DB 테이블·상태관리 라이브러리는 추가하지 않았다. SourceSpanPicker는 Unicode codepoint 경계를 한 번 만들고 인용 위치를 검증한다. 원문을 매 일치마다 다시 순회하지 않으며 반복 일치 목록은 페이지마다20개만 표시한다. 구조적으로 맞는 인용을 의미적으로 올바른 결정이라고 표시하지 않는다.

## 발견한 결함과 수정

독립 코드 검토에서 새 작업공간 생성의 초안 보호 누락, 반복 구절마다 원문을 재순회하는 비용, 충돌 복구 뒤 옛 결정 연결 개수 안내를 발견해 보완했다. 키보드 초점 이동 경합도 화면 반영 뒤 처리하도록 수정했다. 최종 제품 코드 재검토는 blocker0/advisory0이었다.

실제 전체 검사에서 두 기존 테스트의 갱신 누락을 발견했다. readonly 제목 근거에 직접 fill하던 조작을 현재의 명시 위치 선택으로 바꾸고, 저장 실패 뒤 모든 status가 사라진다는 기대를 저장 중 안내 제거·미저장 안내 보존으로 구체화했다. 원래 저장/검색/초안/잠금/PUT1회 기대값은 유지했다. 새 값 확인의 label 선택자 오류는 같은 문자열을 검증하는 textbox role 선택자로 고쳤다.

## 재현과 남은 한계

기존 Java21·고정 의존성으로 새 복사본에서 web typecheck/build, server package, web의 `npm run test:e2e`를 실행한다. 관련 검사만 실행하려면 `npm run test:e2e -- meeting-ready.spec.ts meeting-save-pending.spec.ts`를 쓴다. 생성 transport는 runner가 명시 합성 fixture로 준비하며 개인 DB와 원래 JAR는 사용하지 않는다. 자세한 환경 준비는 실행 안내를 따른다.

입력100개를 봉인하고 마지막 테스트 수정2개 외98개·원래JAR·개인DB metadata가 유지됨을 확인했다. 최초 통합과 최종 표적에서 관측한 소유 프로세스는 종료됐고 원래 실패186개 증거도 보존했다. 이는 관측 범위의 확인이며 전체 OS 감사가 아니다.

1440px/390px 저장 화면과 키보드/긴 문구 화면을 AI가 확인했다. 물리 기기·사람 사용성·새 환경·부하·실제 생성 품질·공개 배포는 미검증이다. 300,000 codepoint 원문의 모형 성능 검사도 실제 운영 지연으로 일반화하지 않는다. 기계 판독 근거는 [결과 JSON](../experiments/results/meetings-manual-correction-v1.json)에 기록한다.

게시 준비에서 새 manual spec의 CRLF4개만 LF로 통일했다. 원래 검사 소스와 봉인본은 보존했고 TypeScript5.9.3이 생성한 JavaScript40,754바이트가 양쪽에서 같음을 확인했다. 제품 코드나 기대 문자열은 바뀌지 않았다. 최종 게시 바이트는 결과 JSON에 별도로 결속한다.

마지막 테스트 조작2개와 게시 줄바꿈1개에 대한 별도 독립 검토도 blocker0/advisory0이었다. 기존 기대값 보존과 저장된 변환 결과를 확인했으며 새로운 전체 실행이나 사용자 검수로 세지 않는다.
