# 한 번의 더 큰 로컬 모델 비교

4B의 원문 우선 정책과 JSON 구조 제한은 인용 대상 혼동·시간 표현 과장을 해결하지 못했다. 같은 질문에 예시나 후처리 규칙을 더 맞추지 않는다. 이 문서는 새 계열의 더 큰 무료 로컬 모델을 한 번 비교하는 사전 계획이며 성공·서비스 채택 증거가 아니다.

## 선택과 비용 경계

Qwen3-8B Q4는4.68GiB 가중치와 문맥 cache·buffer의 합이6GiB GPU에 빠듯하다. 14B Q5는9.79GiB라 CPU 계산 비중과 지연 위험이 더 크다. **Qwen3.5-9B/Unsloth Q5_K_M**는6.13GiB로 전체 GPU 적재가 불가능하지만32GB RAM에 일부를 적재할 수 있는 후보다. 32층 중24층을 GPU에 고정한다. 실제 메모리·속도는 측정 전이다.

원본은9B dense 모델이며24개 Gated DeltaNet·8개 attention 층을 가진다. 전체 계열 설명의 MoE 문구를 이 모델의 속성으로 옮기지 않는다. 공식 지시 수행·다국어 자료는 후보 선정의 참고이며, 양자화·비사고·greedy의 DocTrail 성능을 증명하지 않는다. 원본 Apache-2.0, 제3자 Unsloth 양자화, 기존 MIT llama.cpp b11429를 사용한다. 원본·양자화 revision, 가중치·license hash는 별도 manifest로 고정한다. 약6.58GB를 로컬에 내려받고 유료 API/GPU/클라우드는 사용하지 않는다.

## 동결 조건

4B에서 사용한 evidence-first v2 프롬프트·고정 GBNF·엄격한 원문 검사·샘플링과 입력4096/출력768/요청120초 상한을 유지한다. 바뀌는 것은 모델 계열·크기·양자화·chat template와 GPU24층 분할 배치다. 차이를 모델 크기의 단독 효과라고 해석하지 않는다. 모델은 동시에 한 개만 적재하고 검색은CPU를 유지한다. vision projector·MTP·음성·도구 실행은 추가하지 않는다.

새 template는 기본 사고형이므로 `--reasoning off`와 `enable_thinking=false`를 지정하고, 실제 적용된 마지막 assistant preamble이 공식 비사고형 suffix와 같은지 검사한다. 문서 안에 있는 문자열을 사고 과정으로 오인해 지우지 않는다. API 입력·출력 원문은 운영 로그에서 제외한다. 별도 개발 보고서에는 공개/합성 입력·raw 출력을 재현 근거로 보존한다.

## 순서와 호출 상한

1. 새 소스·정책·모델 manifest·계획을 먼저 커밋으로 동결한다.
2. 중립 영어 readiness 두 입력만 최대1회씩 생성한다. 하나는 짧은 인사, 하나는 사실 없는 반복 문장300줄이다. 구조적 보류 JSON만 요구한다. 실제 template·EOS·설정·시간·입력 token·post-load 표본 GPU 전체 사용량과 native RSS를 기록한다. 시작 중 최대 메모리나 실제 Java HTTP 수치로 기록하지 않는다. 실패하면 자동 재시도 없이 보존한다.
3. 기존 네 알려진 실패를 각1회 실행한다. 새 모델이4/4 정확한 인용·의미·완전성·언어/보류를 통과해야 다음 검증을 연다. 이 자료는 독립 평가가 아니다.
4. 후보 동결 뒤 격리된 custodian이 새 자료12건을 만든다. 공개 출처6건·별도AI합성6건, 답변 가능8건·근거 부족4건, 한국어/영어/교차언어·단일/다중 문서를 포함한다. Jupyter/community/2025 및 기존 출시/로그보관 사례, M5-B family·validation은 사용하지 않는다. 원문 license/revision/hash·질문·필수 사실·원문 인용·보류 이유를 고정하고 부모·prompt 작성자는 실행 전 문항·정답을 보지 않는다.
5. 기존 네 사례를 통과한 경우에만 새12건을 고정4B와9B 각각 한 번 비교한다. 모델을 가린 별도 AI 검토가 인용·주장 지지·시간 표현·완전성·언어·보류를 판정한다. 이 작은 제품 검증의 통합 gate는 후보12/12이며 인간 검수나 일반 정확도가 아니다. 실패한 항목을 빼거나 새 모델/프롬프트로 같은 자료를 반복하지 않는다.
6. 통과 후9B의 회의 분석과 실제 Java/React 전 흐름을 별도로 확인한다.4B의 분석 성공을9B로 옮기지 않는다. 자연어 답변 실패를 발췌 표시로 대체해 완료 처리하지 않는다.

생성 상한은 readiness2 + 알려진 실패4 + 새 비교24 =30회, 자동 재시도0이다. 실제 Java 통합 호출은 이 비교가 통과한 뒤 별도 사전 범위로 기록한다. 실패하면 독립적으로 가능한 기존 분석·작업·권한 기능의 검증과 문서화를 유지하며, 유료 대안을 사용할 경우 모델·전송 자료·실제 가격 근거·호출 수·비용 상한을 제시한 뒤 승인받는다.

현재 사용자 검수0, paid calls0, 외부 서비스 배포0이다. 이 비교는 기존 동결M2/M3/M4/M5와 별개이며 최종 test를 열지 않는다.
