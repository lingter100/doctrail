# 회의 검증 자료 일부 노출 기록

기록일: 2026-10-13. 상태: **노출 사고 기록과 후속 평가 선택 제안**. 이 문서는 기존 C0 설계·알고리즘·실패 게이트를 수정하거나 봉인 자료 실행을 허용하지 않는다.

## 확인 범위와 시점

부모 에이전트가 `git diff --cached --check`를 실행했을 때 후행 공백 진단에 봉인 12항목 pool의 공개 출처 일부 원문이 함께 출력됐다고 보고했다. 이 문서는 그 보고를 기록한다. 작성자는 출력 원본이나 봉인 자료를 열어 노출 문구를 다시 확인하지 않았다.

- 노출된 내용: 정기 일정, 문서 준비 안내, 회의 목록 제목과 관련된 공개 출처의 일부 줄 및 후행 공백 진단. 실제 문구는 이 문서에 복사하지 않는다.
- 노출되지 않았다고 보고된 내용: 검증 질문, oracle, 모델 출력. 해당 pool의 모델 호출은 0으로 보고됐다.
- 부모는 위 출처 일부를 보았으므로 더 이상 원문 전체에 대해 완전히 blind였다고 주장할 수 없다. 구현자와 설계자에게는 해당 문구가 전달되지 않았다. 사고 범주를 전달받은 사실과 실제 문구 접근을 구분한다.
- 부모 보고에 따르면 C0의 480 code points 분할, 최대 160구간·10청크, 입력 4,096 tokens·출력 768 tokens 정책 채택 및 구현 지시는 노출 전에 완료됐다. 노출 이후 그 내용을 이용한 추가 정책 선택은 하지 않는다.
- 정확한 노출 시각·출력 전문·영향받은 자료별 목록은 이 작성자가 확인하지 않았다. 부모의 사고 보고와 기존 정책 결정 기록의 순서를 보존하며 확인하지 않은 시각이나 범위를 만들어 적지 않는다.

공개 문서라는 사실은 평가의 접근 격리를 대신하지 않는다. 동시에 일부 출처 줄을 본 일을 검증 질문·정답 유출, 모델 학습 또는 전체 pool 열람과 같다고 단정하지 않는다. 이번 사고만으로 그런 일이 있었다는 증거는 없다.

## 원래 조건과 현재 제한

[C0 인용 구조 제안](MEETINGS-CITATION-ARCHITECTURE-PROPOSAL.md)은 기존 봉인 12항목을 사용할 조건으로 부모·구현자·정책 설계자가 봉인 항목의 내용을 읽지 않았는지 확인하도록 정했다. 이 엄격한 조건은 부모의 일부 출처 접근으로 충족되지 않는다. 질문과 oracle가 계속 비공개라는 사실만으로 원래 조건을 충족했다고 바꾸어 해석하지 않는다.

원래 설계 파일과 알고리즘은 변경하지 않는다. 사고 이전 설계 문서 SHA256은 `16e7044e05e60cae76de4c1e6091295c5010fa6269db45067ea79fa4f64a8e6c`다. 이 사고 문서는 그 조건을 완화하는 개정안이 아니다. 기존 9B 실패 결과와 원래 검증 계획의 blocked 상태도 보존한다.

현재 준비 범위는 기존 C0 전체 상한 18회 가운데 **중립 control 최대 2회와 알려진 개발 사례 4회까지만**이다. 호출 예산이 남았다는 이유로 기존 12항목 실행이 허용되는 것은 아니다. 알려진 네 사례는 일반 개발 회귀이며 이번 사고가 이를 독립 검증으로 만들거나 그 목적을 바꾸지 않는다. 이 문서 작성 중 실제 모델 호출은 없다.

알려진 네 사례가 모두 통과하기 전에는 새 pool을 작성하지 않고 기존 12항목도 실행하지 않는다. C0 첫 실패 뒤 known 사례를 반복 튜닝하지 않는 중단 규칙, 재시도 0, 기존 자원 상한은 유지한다.

## known4 통과 뒤에만 검토할 평가 선택

먼저 격리된 custodian이 기존 manifest와 접근 기록으로 영향 범위를 확인하되 원문·질문·oracle를 부모나 구현자에게 추가로 노출하지 않는다. 그 확인은 이미 발생한 노출을 없애는 조치가 아니다. 누가 어떤 종류의 자료에 언제 접근했는지와 정책 동결 전후 관계를 내용 없는 감사 기록으로 남긴다.

후속 선택은 별도 계획으로 명시해야 한다.

1. 기존 12항목을 사용한다면 일부 출처 노출을 공개한 제한적 평가로만 다룬다. 질문·oracle 비공개 상태와 출처 일부 노출 상태를 각각 기록하고, 엄격한 blind 검증 또는 원래 조건을 충족한 평가라고 부르지 않는다. 그런 결과만으로 원래 품질 게이트 통과나 Phase 1 완료를 선언하지 않는다. 현재는 실행을 준비하거나 승인한 상태가 아니다.
2. 원래 수준의 엄격한 독립 검증이 필요하다면 후보 코드·정책·판정 기준을 먼저 고정하고, 격리된 역할이 새로운 평가 가족과 질문·oracle를 준비하는 별도 계획을 검토한다. 원문 미노출까지 요구하는 조건에서는 이미 노출된 출처에 새 질문만 붙여도 그 조건이 복원되지 않는다. 출처를 포함한 접근 경계를 다시 설계해야 한다. 단순히 노출 항목을 조용히 제외하거나 pool 이름을 바꾸는 것은 허용하지 않는다.

어느 쪽을 택할지, 새로운 자료가 실제로 필요한지와 필요한 범위는 known4 통과 및 영향 감사 후 결정한다. 지금 자료 수를 늘리거나 새 정책을 선택하지 않는다. 노출 이전에 C0 정책이 정해졌다는 점은 기록할 가치가 있지만, 그것만으로 엄격한 미열람 조건을 대체하지 않는다. 후보 출력에 접근한 검토자의 역할과 AI 작성·검토의 한계도 후속 평가 기록에 공개한다.

## 재발 방지

- 봉인 디렉터리가 포함된 staged 전체에 대해 내용이 출력될 수 있는 diff·whitespace 검사를 부모나 구현자의 화면으로 직접 반환하지 않는다. 문서·코드 확인은 명시한 비봉인 파일 경로로 제한한다.
- 전체 staged 검사가 필요하면 stdout과 stderr를 모두 버전 관리에서 제외된 로컬 감사 파일로 보내고, 부모에게는 종료 코드와 민감 내용을 포함하지 않는 상태만 반환한다. 파일 경로·진단 메시지에도 질문이나 문구가 들어갈 수 있으므로 원시 오류를 그대로 요약에 붙이지 않는다.
- 격리된 custodian이 필요한 진단을 검토한다. 해당 파일을 다시 일반 도구 출력에 읽어 노출시키지 않으며, 사고 조사를 이유로 부모가 원문을 추가 열람하지 않는다.
- 봉인 자료의 내용을 바꾸는 수정이 필요하면 먼저 별도 감사 기록과 평가 유효성 판단을 남긴다. 후행 공백을 포함해 바인딩된 출처를 조용히 정리하지 않는다.

## 작성 상태

이 문서는 부모가 보고한 사고를 기록한 AI 작성 문서다. 원래 C0 설계 파일·코드·알고리즘·자료·oracle 변경 0, 이번 역할의 모델 호출 0, 봉인 문구 열람 0, 새 pool 작성 0, 유료 승인·호출 0, 인간 검수 0이다. 유료 API 비교나 외부 실행으로 이 제한을 우회하지 않는다.
