# 생성 형식 후보 실제 결과와 남은 품질 문제

2026-10-27 · 실제 무료 로컬 실행 · 기준 source4998 · 개발 자료 요약4/답변4 · 사용자 검수0

**JSON 생성 문법을 적용해 답변4개는 형식 검사를 통과했지만, 독립 AI 내용 평가에서는 수용0/4였다.** 요약4개는 여전히 형식·길이 조건에서 거부됐다. 후보를 서비스 기본값으로 채택하지 않는다. [실측·평가 집계](../experiments/results/meetings-local-format-actual-v1.json)를 원래 실패와 함께 보존한다.

## 무엇을 비교했는가

같은 무료 Ministral3 3B Q5_K_M, 원문4개·질문4개·기준·compact 입력·자원·시간 예산을 유지하고 schema3의 `claims-json-gbnf-v1`만 사용했다. 이전 v4와 같은 개발 입력에 대한 관측 비교이며 반복 노출된 자료다. 최종 평가나 일반적 모델 성능, 통계적 인과 효과로 해석하지 않는다.

| 측정 | 이전 v4 | 새 v5 |
| --- | --- | --- |
| 실제 생성 | 요약4 + 답변4 | 요약4 + 답변4 |
| 형식 검사 통과 | 요약0/4, 답변0/4 | 요약0/4, 답변4/4 |
| 독립 내용 평가 | 유효 출력이 없어 미평가 | 답변4개 평가, 수용0/4 |
| 요약 거부 | 출력상한3, JSON1 | 출력상한3, schema1 |
| 답변 거부 | 출력상한1, JSON3 | 형식 거부0, 내용 수용0/4 |
| CLI 전체 시간 | 100.969초 | 88.235초 |

각1회이고 완료 단계·실행 환경의 차이가 있어 시간 감소를 성능 향상으로 주장하지 않는다. v5의 내부 실행 시간은87.109초로 CLI 전체 시간과 다르다. 실제 summary review 호출은0회이며 요청 출력 토큰 합4096은 실제 생성된 토큰 합이 아니다.

## 요약 실패

3개는 실제768토큰 한도에서 JSON이 끝나지 않았다. 나머지1개는728토큰에서 EOS로 끝났지만 주장6개의 총1235자가 기존1200자 제한을35자 넘었다. 개별 문장은170~238자로 개별240자 한도 안에 있었다. 새 문법은 JSON 구조를 제어하지만 전체 문자 수·내용 충족·토큰 완결까지 보장하지 않는다.

원본을 자르거나 JSON을 고쳐 수용하지 않았다. 유효한 요약이 없어 의미 평가는 하지 않았으며 이를 의미 정확도0%로 표시하지 않는다. 지금 출력이 예산을 넘었다는 사실은 충분한 다른 요약도 예산 안에 들어갈 수 없다는 증거가 아니다.

## 답변 실패

출력 전에 고정한 [평가 대상 포함 규칙](../data/evaluation/meetings-local-format-review-protocol-v1.json)에 따라 형식을 통과한 답변4개를 모두 독립 판정자에게 전달했다. 판정자는 기존 원문·질문·잠긴 기준을 사용했고 개별 판단을 먼저 고정했다. 추가 실행 상태·모델 자체 검토·성능·정체 매핑은 판단 전에 전달하지 않았다. 과거 자동 문맥 노출이 있어 완전 맹검으로 주장하지 않는다.

- 4개 모두 질문의 필수 정보를 충분히 담지 못했다.
- 인용11개는 모두 실제 원문의 정확한 구간이었다.
- 선택한 인용만으로 주장 전체가 지지된 경우는0/4였다. 부분 지지3개, 미지지1개였다.
- 원문 전체를 기준으로는 완전 지지1개·부분 지지2개·미지지1개였다. 원문에 내용이 있어도 실제 선택 근거가 충분하지 않을 수 있다.
- 필수 정보13개는 충족1·부분7·누락4·오류1로 판정됐다. 이는 작은 개발 집합의 독립 AI 판단이며 사람 검수를 대신하지 않는다.

실패 유형은 필수 정보 누락/불완전4, 선택 근거 부족4, 추가 구체화/관계 모호성2, 자연스러움/지시 대상1, 시점/상태 모순1이다. 유형은 겹치며 새 수용 기준을 만든 것이 아니다. 원문 전체를 제공한 생성 실험이므로 검색·권한 적용까지 포함한 서비스 질의응답 품질로 해석하지 않는다.

## 운영과 보존

공식CLI는1회, exit1이며 바깥 관찰 도구의 exit0과 구분한다. 고정8개 생성 일정은 끝났지만 전체 기능 수용은 실패다. 샘플 native RSS 최대2,957,680,640B, 호스트 가용RAM 최소9,323,601,920B, 장치 전체 VRAM 최대3163MiB를 관측했다. 순간 최대치·메모리 예약·모델 독점 GPU 사용량은 아니다. 정리0.375초, 소유21신원의 부재와 lease 해제를 확인했다.

원본66파일을 봉인했다. 외부 관찰표의 request/response 순번 연결 오류는 원본을 유지하고 별도 정정표를 추가했다. 실제 실행·응답을 고친 것은 아니다. 소비된 실행은 재시도하지 않는다.

## 다음 작업과 완료 조건

[다음 요약 설계](MEETINGS-LOCAL-SUMMARY-CONTROL-NEXT.md)는 동일 예산 안에서 출력 전체의 분량을 먼저 배분하도록 지시한다. 개별160자·총960자는 작성 목표이며 기존240/1200·필수 내용 기준을 바꾸지 않는다. 아직 설계만 완료됐고 성공 가능성을 실측하지 않았다. 이 요약 전용 변경은 별도 답변 품질 실패를 해결한 것으로 세지 않는다.
