# C2-P0 근거 블록과 중립 자원 검사

2026-10-14. 기존 실패를 보존하는 새 후보의 **구현·자원 확인 계획**이다. 새 품질 질문, 기존 질문 재실행, 서비스 채택을 포함하지 않는다. [설계 제안](MEETINGS-C1-FAILURE-FOLLOWUP.md)의 단일 생성·문단 보존을 사용한다.

## 고정 조건

- 같은 무료 Qwen3.5-9B Q5_K_M, 고정 GGUF/runtime, 24 GPU layers, context6144, batch512/ubatch128, fit off, nonthinking, greedy/seed0, cache off, warmup0이다.
- 새 모듈만 추가한다. C0/C1의 파일·질문·oracle·보고서를 편집하거나 실행하지 않는다. 출력384 tokens·입력4096 tokens·어댑터90초다. 인용 단위1024 codepoints를 넘으면 자르지 않고 호출 전에 오류로 반환한다.
- 구조 설명 외의 질문별 prompt, 예시, 검색 설정, 모델을 추가하지 않는다. Java·React 기본 실행 경로는 바꾸지 않는다.
- 원문 인용 폭이 넓어지는 만큼 길이·중복과 의미 지지를 별도로 판단해야 한다. 정확한 좌표는 의미 정답의 증명이 아니다.

## 품질 자료보다 먼저 고정할 중립 2회

새 실행기의 `prepare`는 고정된 합성 문자열만 사용한다. 첫 입력은 색상 표식 하나의 정상 응답 계약 확인이다. 두 번째는 반복되는 무의미한 자원 확인 문단이다. 모델 출력 없이 공식 tokenizer로 문단 개수만 순차 결정해 전체 candidate prompt를 3800~3900 tokens에 맞춘다. 이 범위에 맞지 않으면 준비가 실패하며 원문을 잘라 넣지 않는다. tokenizer assets와 실제 입력 hash를 계획에 기록한다. 이 자료는 품질 평가 문항 수에 포함하지 않는다.

1. **normal**: 실제 블록 어댑터·문법·응답 복원으로 1회 실행한다. 정상 answered, EOS,384 tokens 이하,90초 이내여야 한다. 합성 표식의 의미 품질 일반화를 주장하지 않는다.
2. **stress**: 같은 블록 prompt 준비·native adapter·greedy를 사용하되 출력 문법만 `("x "){500}`로 고정한다. 무의미한 긴 출력을 강제하는 자원 전용 검사다. 서비스 답변으로 반환하지 않으며 모델 품질·인용·보류 성공으로 세지 않는다. 실제 native 입력3800~4096, 출력384, 종료length,90초 이내여야 **지연 준비**를 통과한다. 다른 tokenizer 길이를 공식 측정으로 대신하지 않는다.

모든 호출은 실행 전에 dispatch 영수증을 저장한다. 최대2회·재시도0·추출0·warmup0이며, normal 오류 시 stress를 실행하지 않는다. 이미 존재하는 출력 폴더는 재사용하지 않는다. 첫 실행 전에 코드·단위 검사·본 문서·실제 중립 입력·tokenizer receipt를 파일 hash와 커밋으로 고정한다.

## 취소·정리와 결과 판정

각 호출에 별도90초 native watchdog을 둔다. 기한에 도달하면 이 실행이 소유한 native 프로세스만 강제 종료하고 최대5초 이내 종료 여부를 확인한다. 타 프로젝트 프로세스는 조회나 종료 대상으로 삼지 않는다. 이때 통신 오류나 timeout은 정상 답변이나 stress 지연 성공이 아니다. 호출 시작부터 native 정리 완료까지120초를 넘으면 안전 경계도 실패다.

stress가 기한 때문에 중단되면 `readiness_passed=false`를 유지한다. watchdog이 정상 작동해도 최악 지연이나 출력 완전성까지 통과했다고 해석하지 않는다. 새 품질 자료 작성·실행으로 넘어가지 않고 자원 예산을 별도 후보로 검토한다. 제한을 같은 실행 중 늘리거나 stress의384 요구를 사후 낮추지 않는다.

종료 후 같은 local weights로 새 프로세스를 한 번 띄워 health·고정 모델 identity만 확인하고 내린다. **새 생성 호출은 없다.** 프로세스 재시작·잠금 복구의 증거이며 취소 후 다음 생성 품질이나 Java 운영 복구 검증은 아니다. 모든 정상·실패 경로에서 원본 report, source hash 확인, 소유 process 종료, native 로그 크기를 남긴다.

## 측정과 한계

입력·출력 tokens, EOS/length/오류, 전처리 포함 호출 시간, native prompt/decode 시간, HTTP dispatch 수, 설정 확인 결과, native RSS 주기 표본을 기록한다. RSS는 표본 최대이며 실제 peak나 GPU 사용량으로 부르지 않는다. raw messages/native output은 공개 합성 실험 report에만 저장한다. 운영 로그에는 원문·질문을 쓰지 않고 안전한 오류 코드만 사용한다.

이 두 검사는 모든384-token 답변의 시간 상한을 증명하지 않는다. 무의미한 강제 출력의 속도는 자연어·문법별 속도와 다를 수 있다. 통과해도 후속 새 자료의 각 응답에 동일한 제한을 적용하며 의미·완전성·권한·리비전·실제 Java/React 검증은 별도다. 실패해도 기존 회의 관리·검색 기능의 검증 결과를 삭제하지 않는다.

부모는 중립 검사 설계·실행기를 구현한다. 별도 기존 Astra high 역할은 새 블록 어댑터와 합성 검사를 맡는다. 설계 제안자의 Astra xhigh 수락 기록과 부모 채팅 설정을 구분한다. 유료 사용0·사용자 검수0이며 현재 PR14/회의1차는 미완료다.
