# 회의록 확장: 실제 실행과 실패 기록

2026-10-13. 이 기능은 기존 Java 문서 서비스를 확장한다. 회의 원문·권한·청크·리비전은 기존 저장을 재사용하고 React 화면과 로컬 Qwen worker를 연결한다. 공개 Jupyter 회의록과 별도의 AI 작성 한국어 사례를 사용한 **개발·운영 검증**이다. 독립 benchmark, 사용자 검수 또는 배포 완료를 뜻하지 않는다.

## 구현한 경계

- 텍스트·TXT/MD/텍스트 PDF 등록 후 실제 로컬 모델 분석을 요청한다. 실패해도 원문은 남고 실패 코드와 재시도를 제공한다.
- AI가 선택·분류한 구절에서 발췌 요약, 논의·제안·결정·미해결·작업을 만든다. 누락된 담당자·기한은 null이다. AI 항목은 확인 전 상태이며 AI 원본과 사용자 수정본을 분리한다.
- 회의와 일반 문서를 현재 권한·메타데이터로 먼저 거른 뒤 BM25 또는 선택적 E5/혼합/BGE로 검색한다. Q&A는 실제 생성 모델을 사용하고 정확한 원문 인용·리비전과 응답 직전 권한을 다시 검사한다.
- 결정 변경 연결은 양쪽 확정 결정과 명시적 원문 근거를 사용자가 선택하는 기능이다. 유사도나 날짜만으로 자동 폐기하지 않는다. 담당자·상태·기한 편집은 저장 충돌을 검사하며 원래 AI 결과를 보존한다.
- 원문 수정은 분석을 stale로 만들고 삭제는 관련 분석·작업·링크를 함께 제거한다. 기존 문서 검색 기록과 피드백을 보존한다. 새 전체 작업공간 Q&A의 영구 기록·피드백은 아직 추가하지 않았다.

보고서의 두 합성 `analysis` 스냅샷에는 테스트 클라이언트의 이후 결정 확정 수정이 반영되는 참조 공유 오류가 있었다. `ai_analysis`는 그대로이며 최초 모델 출력 판단은 이 필드를 사용했다. 원본을 수선하지 않고 [검토 영수증](../experiments/results/meetings-operations-v1.semantic-review.json)에 표시했다. 새 `SnapshotVerification`과 회귀 검사는 향후 실행의 초기 응답을 깊은 복사한다. 검사 조건이 실제로 수행됐다는 운영 증거와 보고서 스냅샷의 한계를 구분한다.

## 검증 구분

현재 서비스 재검증과 내용 검토를 진행 중이다. 최종 실행 파일·검사 수·원격 CI는 완료 후 아래에 기록한다.

기존 실제 HTTP 호환 검사에서 일반 문서 응답에 추가한 `document_kind`가 과거 Python DTO와의 정확한 비교를 깨뜨렸다. 기존 검사나 참조 구현을 완화하지 않고, 새 회의 문서에만 표식을 추가해 일반 문서 응답을 유지했다. 수정한 JAR를 패키징하기 전에 낡은 JAR로 한 번 더 실행한 절차 오류도 있었으며 성공으로 계산하지 않는다. 패키징 완료 뒤 기존 HTTP 11묶음과 Java 124개가 통과했다. 통합 knowledge 결과에는 회의/일반 구분을 별도로 제공한다.

- Java 검사는 실제 DB·세션·ACL·편집 충돌·revision·중간 권한 변경·재시도 보존과 제한된 worker 계약을 확인한다. 성공을 모델 정확도로 환산하지 않는다.
- 브라우저의 결정·작업·답변 성공 경로 일부는 이름에 `synthetic-browser-transport-fixture-NOT-LLM`을 명시한 전송 대역을 사용한다. 이는 실제 AI 품질 증거가 아니다. 실제 GPU HTTP 실행은 별도 파일로 남긴다.
- UI 스크린샷은 AI가 데스크톱·모바일 레이아웃과 원문 표시를 확인한 자료다. 사용자 검수·실사용자 만족도는 0이다.
- 공개 소스의 고정 revision, BSD-3-Clause 및 가공 hash는 [자료 안내](MEETINGS-DATA.md)를 따른다. 모델은 고정 Qwen3-1.7B이며 로컬 GPU를 사용한다. 유료 API·GPU 임대·클라우드·외부 서비스 배포는 없다. 전력과 개발 보조 비용은 측정하지 않았다.

## 남은 한계와 설명할 내용

1. 요약은 실제 모델이 분류한 원문을 선택한 발췌 요약이다. 추상적 회의 서술을 자유롭게 생성한 결과와 구분한다. 명시적 이름·날짜·우선순위는 규칙으로 읽으므로 표현이 다르면 놓칠 수 있다.
2. 정확한 인용은 주장 전체가 참이거나 질문의 모든 부분에 답했다는 증거가 아니다. 다중 문서·충돌·보류는 개별 내용을 검토해야 한다. 작은 개발 자료에서 수정했으므로 성능 일반화를 주장하지 않는다.
3. 분석 입력·출력·시간·메모리 상한이 있다. 초과 시 조용히 버리지 않고 오류와 재시도를 제공한다. OCR·DOCX·녹음·STT·실시간·외부 회의 도구 연동은 지원하지 않는다.
4. 작업 담당자는 텍스트 값이며 실제 조직 계정 자동 연결·알림·외부 업무 도구 동기화는 없다. 결정 변경은 사용자 확인이 필요하다.
5. 이번 확장은 동결 M5-B 품질 비교를 대신하지 않는다. 기존 18개 파일과 final test 잠금을 보존한다. 후속 품질 실험과 사용자 검수는 별도 작업이다.
