# 고정 CMake 모듈의 줄 위치 불일치

2026-10-30 · 실제 v7 취득 실패의 원인을 수정하고 집중 검사·실제 모듈 메타데이터 검사를 통과했다. 독립 변경 검토는 차단0·권고0으로 끝났고 게시·필수 CI를 진행한다. 전체 취득·컴파일·문법 검사·AI 품질 성공을 뜻하지 않는다.

v7은 도구 준비, 소스 1,687개·33,232,611바이트, 라이선스 취득을 마친 뒤 최종 명세 작성에서 `BoundaryError/optional_probe_source`로 실패했다. CLI는 1,555.922초에 자연 종료1을 반환했다. [원본에 근거한 실패·보존 기록](../experiments/results/meetings-summary-engine-v7-acquisition-v1.json)은 시간 초과와 이 소스 검증 오류를 구분한다.

고정 CMake 3.31.8 Windows 배포물의 `Modules/Platform/Windows-GNU.cmake`는 11,218바이트이며 SHA-256은 `edc2abe122ba69089d9ff23a15916e474e3309bc64d3ccf5f7c04451abe1b7ab`다. 실제 파일과 실행자가 보존한 목록의 해시가 일치했다. 55행은 빈 줄이고, 검사 대상인 `execute_process(COMMAND ld -v OUTPUT_VARIABLE _help ERROR_VARIABLE _help)`는 61행에 한 번 존재했다. 코드가 55행으로 고정한 위치만 잘못됐다. CRLF나 공백을 완화할 문제는 아니다.

수정은 기존 준비 스크립트의 위치 검사·기록·검증을 61행으로 일치시키는 범위다. 임의 위치 탐색이나 두 위치 동시 허용을 추가하지 않는다. 정확한 명령과 인수, 유일성, 모듈 해시·경로, 실행 파일 부재 조건은 유지한다. 이는 실행되지 않는 선택적 조회를 trace에서 식별하는 규칙이며 `ld` 실행 권한을 부여하지 않는다. 도구·소스 pin, 전송·저장·시간 한도와 실패한 실행 기록도 유지한다.

기존 가상 모듈은 구현과 똑같이 55행에 명령을 만들어 잘못된 가정을 놓쳤다. 공개 회귀 검사에는 실제 55행 빈 줄·61행 명령 배치를 독립된 리터럴로 넣고, 과거 위치·이동·중복·인수·해시·trace 변조 거절을 확인한다. 추가 로컬 확인은 보존된 실제 11KB 모듈만 새 가상 binding 환경에 복사해 수행한다. 다른 도구는 실행되지 않는 가상 파일이며 원본 실패 폴더는 변경하지 않는다. 이 확인도 컴파일이나 새 취득 실행은 아니다.

과거 [ENGINEv3 계획](MEETINGS-SUMMARY-ENGINE-V3-PLAN.md)의 55행 가정은 당시 기록으로 보존한다. 현재 관측 위치는 61행이다. 통과한 무관한 검사나 전체 다운로드를 진단 목적으로 반복하지 않으며, 수정의 집중 검사와 독립 변경 검토를 마친 뒤 해당 커밋의 CI를 확인한다.

관련40개 검사는88.47초에 통과했다. 실제11,218바이트 모듈을 새 가상 환경에 복사한 binding→guard→trace 확인도1회 통과했다. 초기 Ruff의 import 뒤 빈 줄 지적은 원본과 함께 보존했고, 빈 줄1개만 제거해 AST 동일성을 확인한 뒤 Ruff를 통과했다. [검사 결과와 한계](../experiments/results/meetings-summary-optional-probe-repair-v1.json). 공개 CI의 가상 자료 검사와 실제 작은 파일을 사용한 로컬 메타데이터 검사는 구분한다.

독립 검토에서 실제 모듈의55–64행과 공개 리터럴 fixture를 직접 비교했고, 제품 코드의 세 숫자 위치 밖 바이트가 유지됨을 확인했다. 그 검토도 새 검사·컴파일·취득을 실행하지 않았다. 이 수정은 새 실제 실행이나 자동 재시도를 허용하는 결과가 아니다.
