# 실제 Java 검색을 거치는 공개 개발 QA

2026-10-31. 실행기 구현·가상 검사·독립 AI 소스 검토를 마쳤다. 실제 서비스·모델 답변은 아직 실행 전이며 품질 수용 문서가 아니다.

## 문제와 선택

전체 원문을 직접 제공한 [표현 길이 진단](MEETINGS-FREE-QA-REPRESENTATION-DEVELOPMENT.md)은 검색을 검증하지 못한다. 같은 공개 원문3개·한국어 질문2개를 실제 Java 서비스에 넣고 기본 BM25 검색 결과와 답변을 함께 관찰한다. 전체 원문과 충분한 참고 답변은 근거 누락과 생성 오류를 구분하는 기준으로 유지한다.

기존 일반 GGUFGenerator와 MeetingRuntime을 명시적 Ministral 명세로 연결한다. 기존 예시4개·입력4,096·출력768·요청120초 정책을 유지하며, 이전 compact/256 비교와 합치지 않는다. 기본 모델 채택이나 기존 닫힌6개 비교 재실행이 아니다.

## 실행 범위

새 DB와 작업공간에서 원문3개를 일반 문서로 등록한다. 회의 생성의 자동 분석을 피하므로 이번에는 회의 날짜·참석자 필터와 전체 회의 분석 흐름을 검증하지 않는다. 질문마다 기본 BM25·10개 문맥으로 검색1회와 답변1회만 요청한다. 입력 초과·HTTP 실패·생성/인용 오류를 보존하며 재시도하지 않는다. HTTP 실패 후 작업자가 남아 있을 수 있으면 다음 사례를 미시도로 남긴다.

실험용 관찰기는 기존 토큰 계산·생성 함수에 각각 한 번씩 위임한다. 요청별 실제 토큰, 반환된 원문 출력, 시간, 오류와 Java 검색 결과·개정·원문 구간을 별도로 기록한다. 반환 전 실패한 생성의 계측은 null이며 이전 요청 값을 재사용하지 않는다. 공개 원문·질문·출력은 실험 파일에만 저장하고 운영 로그에는 넣지 않는다.

최대 생성 시도2회·요청 토큰 합계1,536, 시작120초·공유 작업240초·정리5초다. 별도 외부 관찰은 전체 CLI400초 중 마지막5초를 정리에 남기고 시작 가용 RAM8GiB·작업 중2GiB·소유 프로세스 합계 RSS6GiB를 확인한다. 시간·자원은 관찰과 중단 기준이며 OS 수준 최고값 보장은 아니다. Java 직접 경로·모델 명세·소스·자료·새 실행 파일을 고정한 직전 점검 후 실행한다.

## 재현과 현재 검증

[공개 입력 묶음](../data/meeting-qa-development/opensearch-v1/README.md)은 개인 경로 없이 Python 표준 라이브러리로 검증·복원한다. 새 관찰 실행기는 다음 명령 형태를 사용한다. `<새 출력 경로>`는 아직 없는 경로여야 한다.

```powershell
python -B -m scripts.run_meeting_qa_service_development --jar server/target/doctrail-server-0.1.0.jar --jar-sha256 <실제 JAR SHA256> --output <새 출력 경로>
```

위 명령만으로 외부 프로세스·자원 관찰이 제공되지는 않는다. 실제 실행에는 해당 관찰을 함께 적용한다. 모델 준비는 명시된 고정 자료를 사용하고 실행 중 다운로드하지 않는다. Python 기본/dev 의존성, psutil7.2.2, Java21이 필요하다.

독립 검토에서 늦게 끝난 이전 요청이 다음 사례에 기록될 수 있는 문제와 같은 코드의 서로 다른 오류를 삭제하는 문제를 발견해 수정했다. 새 Python3.11 환경의 가상18개와 Ruff가 통과했고 잔여 검토 지적은0이다. [구현 결과](../experiments/results/meetings-qa-service-development-implementation-v1.json). 이는 실제 검색·생성 품질이나 사람 검수의 증거가 아니다.
