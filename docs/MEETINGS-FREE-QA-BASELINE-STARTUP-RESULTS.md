## 확인된 원인과 수정 범위

독립 진단에서 저장된 설정 응답은 정확히 `/props`, `case_id:null`임을 먼저 확인했다. 승인된 원본 Ministral template는7,753바이트다. 고정 서버의 [조건문 치환](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/common/chat.cpp#L749-L757)이198바이트를 줄이고 [lexer](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/common/jinja/lexer.cpp#L39-L53)가 마지막 LF1개를 제거한다. 계산한7,554바이트는 저장된 실제 응답과 바이트 단위로 같았다. 원문에는 CR이 없으며 단순한 줄바꿈 보정만으로는 맞지 않는다.

현재 어댑터는 Qwen의 정확한 변환만 등록해 Ministral에는 원본 해시를 기대했다. 실제 응답을 넣은 순수 재현에서 같은 오류가 발생했고, 정확한 Ministral 모델·런타임·원본 해시/크기 조합1개만 추가한 메모리상 비교는 전체 설정 검증을 통과했다. 기존 Qwen 매핑은 정확했다. 이는 실행 실패 원인의 증거이며 수정된 서비스나 답변 품질 성공은 아니다.

어댑터의 정확한 매핑1개와 기존 QA 테스트를 수정했다. 공개 Apache-2.0 template를 포함한 집중27개가 통과했고 관련 검사는310통과·기존 hardlink 생성 권한 오류1개였다. 동일 소스의 해당 검사만 권한 있는 환경에서 다시 확인해1개 통과했으며 최초 실패와 구분한다. 전체 검사 재실행은 없다. 기존 Ruff CLI의 F 검사는 통과했고 지정 Python에 Ruff 모듈이 없던 최초 오류도 보존했다.

독립 변경 검토는 차단0·권고0이었다. 부모는 구현34참조·Git 원본2개와 검토 참조를 대조했다. [소스 검증 기록](../experiments/results/meetings-free-qa-baseline-template-repair-v1.json)은 실제 생성이나 의미 품질 성공과 구분한다. 입력 질문·모델·생성 설정·시간 한도·이전 통제 파일은 변경하지 않았다. 게시 후 필수 CI와 새로운 실제 품질 비교는 남아 있다.

설치 전 Python 별칭 접근 오류, 공식 메타데이터 확인 및 엄격한 종료 확인 뒤의 오케스트레이션 JavaScript `.then` 오류도 원본과 함께 보존했다. 실제 도구 종료 결과는 각각 확보됐고 같은 명령을 다시 실행하지 않았다. 이 보조 호출 오류와 실제 모델의 대화 형식 검사 실패는 구분한다.

이 결과는 로컬 실행에 대한 AI 자동 확인이다. 실제 답변의 독립 품질 평가, 사용자 검수와 공개 서비스 배포는 아직 아니다.
