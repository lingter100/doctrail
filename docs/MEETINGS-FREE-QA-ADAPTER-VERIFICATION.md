# 무료 로컬 QA 비교 구현과 검증

2026-10-28. 같은 질문·원문·생성 한도로 기존3B와 새7B 후보를 비교하는 실행기를 구현했다. **코드·합성 회귀·독립 코드 검토까지 완료했으며, 새 가중치의 실제 비교와 품질 통과는 아직 없다.**

## 문제와 선택

기존 후보의 정확한 인용만으로 충분한 자연어 답변이 보장되지 않았다. [비교 계획](MEETINGS-FREE-QA-NEXT-DECISION.md)에 따라 기존 실패 질문을 반복 조정하지 않고 새6개를 양쪽 모델에 동일하게 제공한다. 프롬프트·원문·출력 상한을 유지하되 모델별 template/tokenizer 이후 토큰 수 차이는 관측한다. 더 큰 모델의 우위를 가정하지 않는다.

## 실제 연결된 코드

- `tools/free_qa/policy.py`: 두 모델 정책, 같은6개·호출/시간/토큰 한도, 정확한 파일·사전 검토 결속을 검사한다.
- `tools/free_qa/adapter.py`: 기존 GGUF HTTP transport와 원문 복원을 재사용하고 QA 요청만 허용한다. 원문을 줄여 입력 초과를 숨기지 않는다.
- `tools/free_qa/runner.py`: 모델 준비·순차 시작·한번 실행·소유 프로세스 정리·전후 원본 확인을 연결한다.
- `scripts/probe_meeting_free_qa.py`: `verify`와 명시적 `run`만 제공한다. 합성 응답을 실제 경로로 자동 대체하지 않는다.

개별 질문의 정답 가능/불가능 유형은 실행 계약에서 거부한다. 원문을 사전 검토한 별도 역할의 안전 집계만 고정된 신뢰 파일에 결속한다. 실행자는 비공개 기준을 의미로 파싱하지 않고 바이트 해시만 확인한다. 실제 사전 검토·자료·신뢰 파일·실행 등록은 후속 작성 대상이며 코드가 의미 검수를 대신하지 않는다.

## 재현과 남은 순서

기존 Python 환경에서 `python -m pytest -q tests/test_meeting_free_qa.py`로 합성 검사를 실행한다. 실제 모델 실행은 [구현 계약](MEETINGS-FREE-QA-ADAPTER-PLAN.md)과 [취득 gate](MEETINGS-FREE-QA-ACQUISITION-GATE.md)에 결속된 별도 등록이 있어야 하며, 임의 JSON 예제로 대체하지 않는다.

다음은 정확 소스 CI → 새 폴더의 자산 취득 → 내장 metadata 검토 → 새 자료·기준 사전등록 → 중립/양쪽 실제 비교다. 중립1+모델별6씩 최대13회·출력 요청 합3328토큰·질문당60초를 유지한다. 비교가 통과해도 독립 격리 평가와 실제 Java/React 권한·수정·삭제 흐름, 사용자 검수가 남는다. 사용자 직접 검수0·유료 사용0·새 모델 실행0이며 기본 서비스 모델은 변경하지 않았다.
