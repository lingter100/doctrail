# 실제 서비스 검색의 근거 회수 비교

2026-10-31. **계획이며 실제 실행 전이다.** 기존 Java/Python 검색 기능을 사용하는 공개 개발 진단이다. 기본 모델 채택이나 잠긴 최종 평가가 아니다.

## 해결할 문제

[실제 서비스 QA](../experiments/results/meetings-qa-service-development-v1.json)는 세 문서를 모두 찾았지만 출범 규정 대신 멤버 제명 구절을 가져왔다. 독립 AI 검토는 제안의 확정 오인, 잘못된 인용, 한국어 질문에 대한 영어 출력도 확인했다. 문서를 찾았는지와 필요한 사실을 찾았는지를 구분해야 한다.

## 고정 비교

공개 `data/meeting-qa-development/opensearch-v1`의 원문3개·질문2개·참고 답변을 변경하지 않는다. 새 DB에 일반 문서로 등록해 자동 회의 분석을 피한다. 각 질문에 기존 `bm25`, `dense`, `hybrid`를 고정 순서로 한 번씩 요청한다. profile은 `base`, limit는10이다. 총 검색6회·답변 생성0회이며 실패 뒤 남은 요청은 미시도로 보존한다. 자동 재시도나 키워드 대체는 없다.

Java의 권한 검사·청크·검색 API와 Python `doctrail.inference`를 그대로 사용한다. 검색 모델은 기존 고정 E5와 BGE이며 현재 로더가 둘 다 CPU에 적재한다. BGE 재정렬은 이번 비교에 사용하지 않는다. 모델은 기존 검증 함수가 현재 파일 해시를 확인한 뒤 적재한다. 새 격리 환경은 uv.lock의 retrieval/dev 의존성을 사용하며 기존 환경을 수정하지 않는다. 생성 URL/token은 비우고 `/answer`와 `/analyze`를 호출하지 않는다.

## 실행 한도

시작 단계240초·검색 전체360초·정리5초로 내부 전체605초다. Java 요청별120초와 남은 전체 시간을 함께 적용한다. 외부 관찰은650초 중 마지막5초를 정리에 남기며 내부 시간 연장에 사용하지 않는다. CPU2스레드, 소유 프로세스 RSS6GiB, 시작 가용 RAM8GiB·실행 중2GiB를 고정한다. 자원 한도는 관측/중단 기준이며 OS 수준 보장이 아니다. 초과 시 실패를 기록하며 자동으로 늘리지 않는다.

독립 Astra xhigh가 이 최초 실행 한도를 검토했다. 실제 적재·완주 가능성은 아직 미확인이다. 소스 검사와 집중 테스트, 게시/필수 CI, 직전 중복 프로세스 점검을 마친 뒤 한 번 실행한다. 엔진 빌드와 동시에 실행하지 않는다.

## 해석과 다음 단계

각 결과의 문서·개정·청크·원문 오프셋·순위·시간을 보존한다. 독립 AI 검토는 6월 제안/담당 작업, 11월 미결 범위, 출범 투표/헌장 반영, 초기 구성원 근거가 들어 있는지 판단한다. 근거 없는 두 번째 질문은 최종 범위/명단이 확정되지 않았음을 보여 주는 근거와 아예 검색되지 않은 상태를 구분한다. 사람 검수는0이다.

고정 순서의 후속 요청은 기존 캐시를 사용할 수 있어 냉간 지연 비교가 아니다. 512토큰 모델 입력 절단과 작은 개발 자료라는 한계를 남긴다. 두 질문의 회수 개선을 일반 검색 품질로 확대하지 않는다. 이후 별도 답변 후보에서 출력 구조·언어·근거 충분성을 확인하며, 형식 성공을 의미 정확도로 계산하지 않는다.
