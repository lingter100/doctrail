# 회의 편집 충돌에서 초안 보존

2026-10-15. 다른 창에서 같은 회의를 수정하면 서버는 revision/version을 비교해 이전 편집의 저장을 거절한다. 기존 화면은 이때 초안을 유지했지만, 오류의 ‘새로 불러오기’가 편집기를 제거해 작성 내용을 잃는 문제가 있었다.

## 변경한 사용 흐름

저장 충돌 뒤 **서버 버전 확인**을 누르면 서버에 저장된 분석을 별도 읽기 전용 영역에 보여준다. 제목·날짜·참석자·목적·요약·항목·담당 작업·근거를 확인할 수 있고, 원래 입력은 그대로 남는다. 조회가 실패해도 초안을 지우지 않는다.

- **내 초안 유지 · 저장은 나중에**: 원문과 분석 원문 revision이 같고 서버 분석이 준비 상태인 경우에만 선택할 수 있다. 확인한 version을 다음 저장의 기준으로 삼되 자동으로 저장하지 않는다. 사용자가 저장 버튼을 다시 눌러야 한다. 그 사이 다른 변경이 생기면 서버 CAS가 다시 거절한다.
- **내 초안 버리고 서버 버전 사용**: 사용자가 명시적으로 선택한 경우에만 로컬 초안을 버린다. 이 선택은 서버에 저장 요청을 보내지 않는다.
- 원문 revision이나 분석 상태가 달라졌다면 이전 근거와 항목을 그대로 저장하지 못한다. 초안은 복사할 수 있게 남기고 서버본에서 원문·재분석 상태를 확인하도록 안내한다.

자동 갱신이 편집 중인 상세를 교체하지 않으며, 작업공간·세션이 바뀐 뒤 도착한 응답은 화면을 복구하지 못한다. 이 기능은 현재 화면의 메모리에서 초안을 보존한다. 페이지 새로고침·다른 화면으로 이동한 뒤까지 보관하는 영구 초안 저장 기능은 아니다.

## 실제 검증과 한계

[검증 영수증](../experiments/results/meetings-conflict-recovery-v1.json)은 수정 파일 SHA와 원본 실행 기록을 연결한다.

- 새 브라우저 검사5개 통과: 로컬 유지 후 명시적 재저장, 서버본 선택과 추가 PUT 없음, 조회 실패 및 두 번째 편집 경합, 원문 변경의 오래된 근거 저장 차단, 지연된 응답의 작업공간 침범 차단.
- 기존 회의 브라우저 검사3개도 통과했다. 새5개는10.3초, 기존3개는14.6초의 별도 spec 실행이다. 실패한 첫 batch의 전체 결과를 통과로 바꾸지 않고, 그 안에서 통과한 기존3개의 원본 spec 결과만 연결했다.
- React/검사 TypeScript, production build, Java JAR `package -DskipTests`를 통과했다. 이 package 명령은 Java 전체 테스트 통과 주장이 아니다. 사용한 UI가 JAR에 포함됐고 각 검사 서버가 종료됐음을 실행기가 확인했다.
- 초기 새 테스트에는 합성 fixture 날짜 누락·label 선택자·작업공간 생성 시점 오류가 있었다. 원본 실패 batch3개를 보존한 뒤 테스트만 바로잡았으며 의도한 검증 조건을 완화하지 않았다.
- 390px 모바일에서 가로 넘침이 없음을 자동 확인했고 부모 AI가 실제 비교 화면 캡처를 확인했다. 사용자 검수는0이다.

인증·SQLite 저장·CAS·HTTP·브라우저는 실제 Java 서비스다. 모델 HTTP 경계는 명시적인 합성 전송 fixture이며, 조회 실패 한 건은 합성503 주입이다. LLM 호출0으로 UI 복구를 검증했으며 모델 정확성이나 Phase1 전체 완료의 증거가 아니다.

## 실행 방법

Java21과 저장소의 고정 wrapper, 설치된 Playwright Chromium을 사용한다.

```powershell
npm --prefix web run typecheck
npm --prefix web run build
./server/mvnw.cmd -B -q -f server/pom.xml package -DskipTests
npm --prefix web run test:e2e -- meeting-conflict-recovery.spec.ts meeting-ready.spec.ts
```

모델을 시작하거나 유료 서비스를 연결할 필요가 없다. 새 브라우저 검사도 다른 spec과 별도 서비스·DB를 사용한다. 원래 CAS·권한 검사는 완화하지 않았다. 전체 Java/브라우저 원격 CI 결과는 해당 커밋의 실행 기록으로 별도 확인한다.
