# 회의 확장을 설명할 때

이 문서는 현재 구현과 실패를 설명하는 학습 자료다. 자연어 답변은 아직 품질 기준을 통과하지 못했고 1차 전체 완료나 외부 배포를 주장하지 않는다. 최신 실측은 STATUS와 MEETINGS-RESULTS를 기준으로 한다.

## 해결하려는 문제

회의록에는 아이디어, 확정한 결정, 해야 할 작업이 섞여 있다. 다음 회의에서 결정이 바뀌면 원래 결정이 무엇이었는지와 변경 근거를 찾아야 한다. 일반 운영 문서도 함께 검색해야 답을 완성할 수 있다. DocTrail은 회의 원문에서 분류한 AI 초안을 사람이 확인하고, 원문과 변경 관계를 따라갈 수 있도록 확장했다.

## 왜 기존 문서 구조를 재사용했나

회의도 권한과 버전이 있는 문서다. 별도 저장소나 검색 인덱스를 추가하면 같은 본문의 수정·삭제·권한 상태가 어긋날 수 있다. 기존 문서 ID에 회의 메타데이터를 연결하고 기존 청크·권한·리비전을 재사용했다. Java가 세션, 저장, 접근 권한과 상태 변경을 맡고 Python은 모델 계산만 맡는다.

대안은 회의 전용 DB와 별도 인덱스를 만드는 것이었다. 규모가 작은 개인 프로젝트에서는 데이터 동기화 책임을 늘리는 비용이 더 커서 선택하지 않았다.

## AI가 요약하고 작업을 추출한다는 뜻

현재 요약은 실제 로컬 모델이 원문 단위를 분류한 뒤 결정·작업 등을 우선 표시하는 **발췌 요약**이다. 원문에 없는 설명을 자유롭게 생성한 서술 요약은 아니다. 원문 위치와 인용을 검증하고, 담당자와 날짜가 없으면 비워 둔다. 제안은 확정 결정으로 자동 승격하지 않는다.

AI 결과와 사용자의 수정본은 분리한다. 사용자가 담당자·기한·상태를 바꾸더라도 최초 AI 결과와 원문은 남는다. 동시에 수정한 내용을 덮어쓰지 않도록 원문 revision과 편집 version을 함께 검사한다.

## 결정 변경은 왜 자동 연결하지 않았나

두 문장이 비슷하거나 더 최근에 작성됐다고 이전 결정이 폐기된 것은 아니다. 양쪽의 확정 결정과 변경을 설명하는 원문 근거를 선택해 연결한다. 원문이 바뀌면 낡은 관계를 현재 결정 이력으로 보여주지 않는다. 자동 유사도 연결은 후보 추천에는 쓸 수 있지만 사실상의 폐기 판정으로 쓰기에는 오탐 비용이 크다.

## 인용이 정확하면 답변도 정확한가

아니다. 실제 개발 비교에서 원문 구절을 정확히 가져왔어도 출시 예정과 완료를 섞거나, 회의 날짜를 사건 발생 날짜로 확대하는 오류가 있었다. 출력 JSON 검사와 인용 문자열 검사는 구조·출처를 확인할 뿐, 주장 전체가 원문으로 뒷받침되는지까지 증명하지 않는다.

그래서 JSON, 정확한 인용, 의미 지지, 질문의 모든 요구에 대한 응답, 언어, 근거 부족 시 보류를 따로 확인한다. JSON 문법 제한을 추가한 뒤 형식은 회복됐지만 내용 오류가 남았다는 실패도 보존했다. 작은 개발 사례를 반복 수정한 결과를 독립 평가 정확도로 발표하지 않는다.

## 실제로 확인한 범위

공개 회의 2건과 별도 합성 회의 2건을 실제 모델로 분석하고 Java의 저장·편집·결정 연결·작업 관리·권한·문서 수정과 삭제를 검사했다. 실제 브라우저로 원문과 저장된 작업, 모바일 화면도 확인했다. 자연어 답변은 이 운영 검사에서 제외했고 이전 품질 실패를 취소하지 않았다.

보고서에서도 이후 테스트 편집이 초기 객체에 반영되는 기록 오류를 발견했다. 최초 AI 결과는 별도 필드에 보존되어 있었으며, 원본 보고서를 수정하지 않고 한계를 표시했다. 후속 검증에서는 초기 응답을 깊은 복사해 같은 오류를 막는다.

## 직접 판단해야 하는 부분

사용자는 회의의 제안·결정·작업 구분이 실제 의도와 맞는지, 담당자와 기한이 맞는지, 변경 연결의 근거가 충분한지를 확인해야 한다. 현재 사용자 검수는 0이며 자동 테스트나 AI 검토를 사람 확인으로 바꾸어 기록하지 않는다.

구현·실험·문서의 작성과 검증에는 AI가 크게 기여했다. 사용자는 프로젝트 목표, Java 백엔드, 공개 소스와 본인 Git 작성자, 1차·2차 기능 경계와 비용 승인 조건을 정했다. 세부 기여와 도구가 실제 수락한 개발 모델 설정은 CONTRIBUTIONS에 기록한다.
