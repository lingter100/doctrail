# 회의·후속 작업 목록의 조회 실패 복구

2026-10-15. 실제 검증 결과는 아래 검증 기록을 따른다. 브라우저 검사는 Java API와 저장소를 사용하고, 분석 모델 전송만 명시적인 합성 fixture로 대체한다. 이 수정은 자연어 답변 모델의 정확도 평가가 아니다.

## 해결하려는 문제

기존 화면은 첫 목록 요청이 실패해도 초기 빈 배열을 렌더링했다. 사용자는 오류 배너 아래에서 ‘첫 회의 등록’이나 ‘후속 작업 없음’을 동시에 보게 됐다. 회의 조회가 실패하면 별도 API인 작업 조회도 건너뛰었고, 상세 화면의 성공이 공용 오류 상태를 지울 수도 있었다.

회의 목록과 작업 목록에 각각 성공 여부와 조회 오류를 둔다. 현재 요청을 소유한 화면만 결과를 적용하며, 다른 작업공간이나 세션으로 이동한 뒤 도착한 응답은 적용하지 않는다. 새 상태 관리 라이브러리나 저장소를 추가하지 않는다.

| 상태 | 표시 원칙 |
|---|---|
| 최초 요청 진행 | 불러오는 중이며 개수·빈 결과를 확정하지 않음 |
| 최초 요청 실패 | 목록 미확인과 명시적인 재시도 제공 |
| 성공한 빈 목록 | 해당 목록의 실제 빈 결과 표시 |
| 성공 뒤 일시적 조회 실패 | 이전 조회 결과임을 표시하고 재시도 제공 |
| 두 API 중 하나 실패 | 각 결과를 따로 표시하며 성공한 API로 다른 목록의 성공을 추정하지 않음 |
| 명시적인 접근 거절 | 해당 접근 범위의 이전 결과를 현재 허용 데이터로 유지하지 않음 |

상세 열기·편집·폴링의 성공으로 목록 오류를 지우지 않는다. 해당 목록의 후속 GET 성공이 오류를 해제한다. 네트워크 장애 때 보존되는 목록은 이 화면의 메모리 범위이며 오프라인 저장 기능이 아니다.

부모 코드 검토에서 추가한 경합 검사에서는 실제 Java 등록201을 보류하고 목록의 접근 거절403을 먼저 전달하자, 늦은201이 상세 화면을 다시 열었다. 이 실패 원본도 보존한다. 접근 거절 뒤에는 상세뿐 아니라 진행 중 변경 요청과 연결 대상 조회의 응답 소유권도 무효화해야 한다. 브라우저 요청을 취소해도 서버의 저장이 되돌아갔다는 뜻은 아니므로 자동으로 등록을 반복하지 않는다.

## 검증 기록

최종 소스에서 실제 Java 브라우저 **17/17**이 통과했다. 새 목록 검사9개15.6초, 기존 충돌 복구5개11.3초, 기존 회의3개14.3초다. 각 spec의 별도 서비스·DB와 packaged React를 사용했고 소유 서버 종료를 확인했다. TypeScript/production build와 JAR `package -DskipTests`도 통과했다. 패키징을 Java 전체 테스트로 기록하지 않는다.

[로컬 검증 영수증](../experiments/results/meetings-list-recovery-v1.json)은 최종5소스, 실제 run/report, 화면 이미지와 앞선 실패의 SHA를 연결한다. 영수증 SHA256은 `1295cc012eb43622c764ce5d7b8866d01e96f3798799f6658cddb949f327bec3`이다. 첫 새 검사7/8의 작업공간 이동 가정 오류, 보정 뒤8/8, 추가 권한 경합의 실제 실패, 최종17/17을 구분해 보존했다. 부모 AI가 최종390px 최초 실패 화면을 확인했으며 가로 넘침 검사를 통과했다.

모델 전송은 명시적 합성 fixture이고 실제 LLM0·사용자검수0이다. 권한403/404와 응답 지연 주입은 브라우저 복구 검증이며 실제 권한 취소 요청을 발생시킨 서버 평가로 표현하지 않는다. 원격 CI는 push 이후 STATUS에 별도로 기록한다.

## 설명할 수 있어야 할 점

- 빈 배열만으로 ‘데이터가 없다’를 판단하면 통신 실패를 제품 상태로 오인한다. 데이터와 조회 상태를 함께 관리해야 한다.
- 회의 목록과 작업 목록은 별도 권한 검사·조회 API다. 한쪽 성공이나 실패가 다른 쪽 결과를 대신하지 않는다.
- 일시적인 장애에서 이전 결과를 보존하는 편의성과, 접근 거절 뒤 데이터를 숨기는 보안 처리를 구분한다.
- 합성 장애 주입은 복구 동작을 검증한다. 실제 모델 정확도나 운영 장애 빈도, 사용자 만족도를 측정한 결과는 아니다.

사용자 직접 검수는 아직 없다. 기존 회의 편집 충돌 복구와 C3 실패 기록, 미개방 validation은 보존한다.
