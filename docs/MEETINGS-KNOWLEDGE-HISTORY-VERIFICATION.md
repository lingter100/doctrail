# 통합 질문 기록과 결과 피드백 검증

2026-10-27. 일반 문서·회의를 함께 검색하거나 질문한 뒤, 당시 조건을 다시 불러오고 개별 근거의 관련성을 평가할 수 있도록 구현했다. 기존 워크스페이스 문서 기록은 유지한다. 이 문서는 실제 서버 동작, 모형 검사, 실제 AI 품질을 구분한다.

## 사용 흐름과 저장 경계

검색 기록의 `통합 검색·질문` 탭에서 본인 기록을 고른다. 전체 작업공간 또는 특정 작업공간, 자료 종류, 회의·날짜·담당자 등의 조건을 복원하고 사용자가 명시적으로 다시 실행한다. 과거 답변이나 원문을 다시 표시하지 않는다. 모델 설정 차이는 안내하고 접근 불가능한 범위를 현재 작업공간으로 임의 변경하지 않는다.

결과마다 관련 있음/없음을 남기며 같은 결과의 평가를 바꿀 수 있다. 저장된 질문·조건·완료 상태와 근거 식별자만 유지하고 원문·제목·생성 답변은 복사하지 않는다. 현재 권한과 문서 revision·청크·offset·해시를 확인해 삭제/비공개/변경된 근거 평가는 거부한다. 현재 접근 가능하고 변하지 않은 근거 수를 기록 목록에서 다시 계산한다.

모델 호출 중 DB 쓰기 잠금을 유지하지 않는다. 호출 뒤 세션·멤버십·검색 대상 전체와 회의 조건을 다시 확인하고 같은 쓰기 트랜잭션에서 기록한다. 응답 전달이 끊기더라도 이미 commit된 기록은 남을 수 있으므로 클라이언트 수신 증명으로 쓰지 않는다. [API 계약](API-CONTRACT.md#unified-meetingdocument-knowledge-and-personal-history)과 [설계](MEETINGS-KNOWLEDGE-HISTORY-PLAN.md)를 참고한다.

## 발견한 실패와 수정

1. 기록을 불러오는 동안 상단 검색 방식을 바꾸면 응답과 로딩 종료를 함께 무효화했다. 화면 문맥과 검색 요청 토큰을 분리했고 수정 전 지연 성공/실패 두 경우를 실제로 재현해 보존했다.
2. 근거 없는 질문을 시험하려던 문자열의 synthetic/evidence 단어가 업로드 문서와 겹쳤다. 실제 서버가 근거를 찾아 비활성 생성기 오류를 반환한 것은 테스트 전제 문제다. 비중복 질의로 바꾸고 실제 검색의 빈 결과를 먼저 확인한다.
3. 답변 실패 후 원문 검색으로 전환할 때 답변의 limit5를 유지해 기존 기본값10 계약을 깨뜨렸다. 명시 전환의 화면·요청을10으로 맞췄으며 사용자 입력·기록 복원 limit은 보존했다. 기존 회귀의 기대값10을 바꾸지 않았다.

처음 JAR와 소스·실패 로그·화면을 보존했다. 준비 스크립트 문법 오류로 이전 dist의 복사본 JAR가 만들어진 경우도 별도 보존했고 그 JAR로 검사를 실행하지 않았다. 정확한 dist 복사 확인 후 패키징했다.

## 재현과 운영 범위

새 작업용 복사본에서 Java21과 기존 잠금 의존성을 사용한다. `web`에서 `npm ci`, `npm run typecheck`, `npm run build`, `server`에서 기존 Maven wrapper로 `package`, 다시 `web`에서 Chromium이 없다면 `npx playwright install chromium`으로 준비한 뒤 `npm run test:e2e` 순서다. 저장된 로컬 실행은 캐시된 Maven의 offline package를 썼다. Windows에서는 Java21의 bin을 해당 실행 환경 PATH 앞에 명시해 다른 launcher를 피한다. 일반 설치는 [실행 문서](MEETINGS-RUNBOOK.md)와 [화면 문서](FRONTEND.md)를 따른다.

기존 test-java.mjs를 수정 없이 사용해 spec마다 별도 임시 DB·포트·서버를 만들고 패키징된 UI와 dist가 같은지 확인했다. 개인 DB나 원래 server/target JAR를 재사용하지 않았다. 현재 소스/복사본97개와 원래 JAR 해시를 대조했다. 검사 서버21개는 종료·로그 flush를 확인했고 실제 모델 호출0이다.

1440px 실제 Java 기록복원 화면과390px API모형 복원 화면을 별도로 시각 확인했다. 기존 회의 화면의390/1440px 검사는 실제 Java와 합성 모델 transport다. 사용자 사용성 검수, 실제 모델 정확성, 새 환경·부하 검증과 공개 배포는 아직 아니다. 개인 이력 전체를 읽는 목록 방식의 확장 비용도 미측정이다. 최종 두 파일 변경의 독립 검토는 blocker0/advisory0으로 수용했다. 게시 후 필수 CI는 아직 남아 있다.

게시 과정에서 새 브라우저 검사 파일의 CRLF만 Git 규칙에 맞는 LF로 통일했다. 실제 검사에 쓴 원본/복사본을 보존하고 TypeScript5.9.3의 변환 JavaScript가 바이트 단위로 같음을 확인했다. 제품 코드는 이 게시 변환에서 바뀌지 않았으며, 게시 파일 SHA는 결과 JSON에 따로 기록한다.
