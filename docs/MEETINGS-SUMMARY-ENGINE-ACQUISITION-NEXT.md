# 요약 엔진 도구 취득 실패와 최소 수정 계획

2026-10-27. 저장된 실제 실패와 일반 코드에 근거한 후속 설계다. 새 취득·빌드·엔진 성공을 뜻하지 않는다.

## 실제 결과와 해석

[첫 취득](../experiments/results/meetings-summary-engine-acquisition-v1.json)은 공유 시간 한도로 실패했다. supervisor595.75초, wrapper596.890초, official exit1이다. LLVM ZIP171,028,561B의 공식 해시는 일치했다. 부분335파일 중 실제 추출 파일은329개/7,254,979B이고 나머지는 ZIP과 metadata다. CMake·Ninja·선택 엔진 소스와 완전한 취득 manifest는 없다. 원래 폴더와 실패는 보존하고 재시도하지 않았다.

코드에는 다음 문제가 있다. 시간 초과의 지배 원인을 계측한 결과와 구분한다.

- 작업자가 각 다운로드/출력 청크마다 전체 폴더를 반복 탐색한다. 소스와 저장 바이트로 유도한 최소 호출은 다운로드7,832회, 현재 추출분1,093회다. 실제 단계 시간·파일 시스템/백신/네트워크별 기여는 미측정이다.
- 압축의 누적 선언 크기에 이미 출력된 파일을 포함한 현재 디스크를 다시 더해, 실제 한도 안에서도 거절할 수 있다. 이번 오류명이 시간 한도였으므로 이 결함을 이번 종료 원인으로 단정하지 않는다.
- 상속한 urllib 리다이렉트 처리기가 본문을 무제한으로 읽는다. 외부 시간/RSS 관측은 있지만 다운로드 바이트 장부 밖이다. 이번 응답의 redirect 횟수/크기는 모른다.

## 최소 구현 범위

1. `scripts/prepare_summary_grammar_engine.py`: 작업자 쓰기 전 바이트 장부로 청크별 전체 탐색을 대체한다. 시작 기준 크기·모든 archive/source/metadata 쓰기·직접 stat하는 supervisor 로그 증가를 포함한다. 부분/짧은 쓰기는 실패로 보존하고 바이트를 환급하거나 기존 부분 파일을 재사용하지 않는다.
2. 같은 파일: ZIP 선언 크기를 시작 기준에 한 번만 합산한다. 경로·case 중복·타입·암호화·항목 수·CRC·선언/실제 길이 검사는 유지한다. 단계 전후 전체 탐색과 장부/실제 크기를 대조하고 불일치·관측 오류를 거부한다.
3. 같은 파일: 자동 redirect 본문 소비를 끄고 제한된 GET hop을 직접 처리한다. 301/302/303/307/308, 상대 Location, 기존 HTTPS/host/credentials/port 제한과 loop/hop 상한을 지킨다. 매 hop은 같은 남은 deadline을 사용하고 버릴 response/error body는 읽지 않고 닫는다. 다운로드 상한은 소비한 body 바이트이며 TLS/header까지 포함한 총 wire 바이트로 표현하지 않는다.
4. `tools/summary_grammar/runtime.py`: supervisor의 매 loop 전체 디스크·경로 검사를 유지한다. 탐색 항목 전후·완료에 optional checkpoint로 같은 시간/RSS/host/log 한도를 검사하되 재귀 탐색하지 않는다. 기존 기본 반환/오류, 자식 식별·정리, build/validator 경계는 보존한다.
5. `tests/test_summary_grammar_engine.py`: 위 수정의 합성 회귀만 추가한다. 기존 원본·기대 기준을 보존하고 fake API 정합 변경은 기록한다. 부모가 공개 문서/결과를 맡는다.

총 제품 도구 소스 범위는 기존3파일이다. 고정 모델·질문·평가 기준·기존 후보·Python 서비스·Java·React는 이 수정에 포함하지 않는다.

## 검증과 한계

- 여러 작은 파일/다청크 쓰기의 바이트·hash와 worker 전체 탐색 횟수를 검사한다. 호출 횟수의 개선을 실제 속도 향상률로 쓰지 않는다.
- DISK 정확 경계/1바이트 초과, 다파일 이중 합산, 빈 파일, 선언과 다른 stream, 부분 쓰기, 알려지지 않은 파일/임시파일·metadata·로그 증가와 stat 오류를 검사한다.
- 실제 redirect dispatch를 통과하는 fake 응답으로 무인자 read 금지, body 미소비/close, origin·relative·loop·deadline과 누적 다운로드 경계를 검사한다.
- 느린 fake 탐색 중 deadline/RSS/host/log 초과를 전달하고, 정리5초와 PID reuse/미허용 자식/cleanup 오류·다른 프로세스 보존을 검사한다.
- 합성 suite·Ruff와 별도 코드 검토 뒤 정확 소스 CI를 확인한다. 테스트 통과는 실제 다운로드·Windows 압축 해제·엔진 호환성을 대신하지 않는다.

supervisor의 전체 탐색 비용은 남는다. 단일 OS 호출의 blocking도 강제 시간 제한으로 바뀌지 않는다. 한도/검사 주기를 느슨하게 하거나 watcher·새 의존성을 넣는 것은 이번 최소 수정에 포함하지 않는다. 실제600초 적합성은 후속 실행으로만 확인할 수 있다.

## 실제 후속 실행 조건

실패·계획 게시 → 별도3파일 구현 → 합성/독립 검토/정확 소스 CI → 새 폴더/별도1회 배정 순서다. 기존 work-v1·부분 ZIP·소비한 실행은 재사용하지 않는다. 취득600초(정리5초 포함), 다운로드512MiB, 전체디스크4GiB, 소유RSS2GiB, host여유2GiB, 시작4GiB를 유지한다.

다음 실행에는 단계 시작·끝, 누적 다운로드/출력 바이트와 탐색 횟수·항목 수·시간을 작은 제한된 metadata로 남긴다. 원래 실행의 없는 수치를 만들어 채우지 않는다. 취득 성공 후에도 실행파일 hash·목록 검토, build, 모델 없는 문법 검증은 별도이며 새 모델 실행을 허용하지 않는다.
