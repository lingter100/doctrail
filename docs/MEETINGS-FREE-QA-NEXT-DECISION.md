v7 QA는 모두 EOS이고 실제 출력83/63/111/92토큰, 입력2456/2490/3333/2979토큰이었다. 256 상한에서 잘린 실패가 아니며, 숫자를512로 바꾸면 누락이 해소된다는 근거가 약하다.
전체 원문과 인용10/10 일치가 있어도 의미 선택·연결·완전성은 실패했다. 이것만으로 모델 용량, 학습, 한국어 전환, 짧은 답변 경향 중 어느 하나를 원인으로 확정할 수 없다.
현재 결과는 검색기가 근거를 못 찾았다는 실험도 아니다. 검색·ACL·revision·UI를 묶은 최종 서비스 평가와 계속 구분한다.

새 후보는 [공식 Qwen2.5-7B-Instruct-GGUF](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF/blob/bb5d59e06d9551d752d08b292a50eb208b07ab1f/README.md), revision bb5d59e06d9551d752d08b292a50eb208b07ab1f의 Q4_K_M 두 shard로 한정한다.
공식 card의 Apache-2.0·7.61B·한국어 포함 다국어 지원과 약4.68GB 배포를 후보 선정 근거로 쓴다. 더 크거나 새로 시험한다는 사실은 DocTrail 우위의 증거가 아니다.
이미 실패한 Qwen3-4B-Instruct-2507 및 Qwen3.5-9B의 닫힌 실행을 재개하지 않는다. 별도 학습 checkpoint의 동일 운영 예산 적합성과 내용 수용을 한 번 확인하는 제한된 선택이다.
두 shard SHA는 receipt에 결속했다. 정확 바이트 크기·원본 revision·license/template·분할 로딩 경로·실제 적합성은 후속 준비에서 고정해야 하며, 지금 가중치를 읽거나 내려받지 않았다.
새 모델 취득은 해당 두 shard/metadata만, 전송5GiB·새 소유 디스크6GiB·30분 상한의 별도 무료 로컬 준비로 제안한다. 기존 cache를 지우거나 런타임을 업그레이드하지 않는다.
6GB GPU에 들어간다고 보장하지 않는다. weights·KV·buffer·드라이버/다른 앱 사용량은 다르며, 기존 RSS6GiB/시작여유8GiB/활성여유2GiB에서 실패하면 자동 offload 변경·양자화 변경·메모리 한도 인하는 없다.

대안인 모델2×출력예산2의24호출은 이번에 제외한다. 미사용 출력 여유가 큰 EOS 실패에서 호출을 두 배로 늘릴 근거가 부족하고,512 지침 숫자까지 바꾸면 순수 hardcap 비교도 아니다.
C1 검토·C3 계획의 반복, 번역 왕복·다수 샘플 투표·새 학습·근거 발췌만 반환하는 방식도 이번 범위에 넣지 않는다. 각각 별도 오류·지연 또는 목표 축소를 추가하며 현재 우위 근거가 없다.

두 모델은 같은 원문·문서 경계·제목·질문·단위ID/좌표·compact payload·QA 지침·grammar·parser·언어/근거/내용 기준을 받는다. 현재256 안내 문구까지 그대로다.

바뀌는 것은 모델 가중치·양자화·tokenizer·공식 chat template의 묶음이다. 같은 토큰 상한은 같은 문자량을 뜻하지 않으며 실제 입력/출력 토큰과 문자·시간을 함께 기록한다.
양쪽의 모델별 입력 한도를 넘으면 원문을 자르거나 항목을 빼지 않고 그 조건의 실패로 남긴다. 모델 크기만의 효과나 v7 대비 인과 개선률을 주장하지 않는다.

최소 구현은 새 QA 비교 policy/adapter·runner와 대응 테스트, 새 모델 profile/비교 계약이다. 현재 candidate/test·schema1–5·소모된v7·동결 parser/grammar·서비스 기본값은 보존한다.
현재 adapter의 PROFILE_SHA/MODEL_SHA 하드코딩을 전역 교체하거나 monkeypatch하지 않는다. 기존3B 경로를 기준선으로 재사용하고 새 adapter에 불변 모델 정책을 명시 주입한다.

합성 검사는 legacy 요청 바이트·정확 정책/자산 선택·분할 누락/혼합/추가 파일·원문/ID 불변·Unicode·EOS/초과·deadline/자원 STOP·cleanup을 다룬다. 새 모델의 정답률 증거가 아니다.

짧게 답하기 쉬운 사례만 고르거나256에 맞춰 요구를 줄이지 않는다. 작성자·사전 검토자·실행자·판정자의 노출을 기록하고 부모/구현자는 비공개 본문, 보호/기존validation/finaltest를 열지 않는다.
