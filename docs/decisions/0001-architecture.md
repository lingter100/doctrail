# ADR-0001 · 로컬 검색 기준선을 중심으로 시작한다

- 결정일: 2026-10-12
- 상태: M1 구조로 채택; 실제 구현·검증 완료 여부는 [STATUS.md](../STATUS.md) 참고
- 범위: 실행 구조, 초기 검색 방식, 이후 실험의 분리

## 맥락

DocTrail은 신입 AI Engineer 포트폴리오다. 핵심은 데이터 준비, 모델 실험, 평가와 서비스 연결을 설명할 수 있는 증거다. 공개 기술문서의 한국어·영어 혼합 검색을 대상으로 하며, 사용자 장비는 RAM 32GB와 RTX 4050 6GB다. 외부 유료 서비스나 공개 서비스 배포는 승인 없이 사용하지 않는다.

현재 출발점에는 확정된 대규모 데이터셋, 정답 라벨, 검색 성능 수치가 없다. 벡터 검색·생성 모델·복잡한 분산 인프라를 한 번에 넣으면 무엇이 작동하고 무엇이 개선됐는지 구분하기 어렵다.

## 결정

1. Python 3.11/FastAPI, SQLite, Vite/TypeScript로 실제 업로드→키워드 검색→원문 근거 흐름을 먼저 만든다.
2. 서버 세션에서 사용자 신원을 정하고, 소속·문서 권한을 검색 후보 생성과 직접 접근에서 검사한다.
3. 초기 검색은 자체 BM25와 영어 단어·한국어 bigram 토큰화를 사용한다. 이는 비교를 시작하는 기준선이다.
4. 문서 버전, 근거 문자열, 원문 오프셋과 PDF 페이지를 연결한다. 수정·삭제는 오래된 청크를 남기지 않아야 한다.
5. 데이터·질문·근거 라벨과 평가 도구를 만든 후 밀집·혼합·재순위화·학습을 단계적으로 비교한다.
6. PostgreSQL+pgvector와 생성 모델은 후속 단계의 후보로 둔다. 기술 이름을 채우기 위해 미리 채택하지 않는다.

## 검토한 대안

| 대안 | 장점 | 이번에 미룬 이유 |
|---|---|---|
| 처음부터 PostgreSQL+pgvector | 관계 데이터와 벡터 저장을 함께 관리하고 이후 확장에 유리 | 초기 문서·라벨·모델 비교 없이 인프라 변수를 늘린다. |
| 처음부터 외부 LLM API 기반 RAG | 생성 답변 데모를 빠르게 만들 수 있음 | 승인되지 않은 비용·외부 전송이 생기고 검색 실패를 생성 답변이 가릴 수 있다. |
| Onyx 같은 기존 도구를 설치해 기능 구성 | 성숙한 검색·연결·화면을 활용 | 사용법 시연만으로 개인의 데이터·모델 개선 역량을 충분히 설명하기 어렵다. 향후 비교 대상으로는 유효하다. |
| Elasticsearch/OpenSearch 중심 시작 | 기존 검색 엔진 기능을 활용 | 단일 로컬 기준선에서 필요한 운영 복잡도가 커진다. 규모·분석기 필요가 확인되면 검토한다. |
| SQLite FTS 또는 BM25 라이브러리만 사용 | 검증된 구성요소를 활용하고 자체 코드가 줄어듦 | M1의 토큰화·ACL 통계 범위를 명시적으로 통제하는 작은 구현을 먼저 선택한다. 자체 구현 검증 비용은 수용한다. |

SQLite의 쓰기 동시성 한계는 [공식 사용 안내](https://www.sqlite.org/whentouse.html)를 참고했다. pgvector의 정확 검색과 근사 검색·필터 특성은 [공식 문서](https://github.com/pgvector/pgvector)를 기준으로 이후 전환 시 검토한다. 경쟁 제품의 상세 근거는 [research.md](../research.md)에 있다.

## 얻는 것과 감수하는 것

설치·실행 비용이 작고 개인정보를 외부 모델로 보내지 않는 로컬 흐름을 확인할 수 있다. 권한·문서 버전·원문 일치가 모델 도입 전에 검증 가능하다. 반면 초기 검색은 동의어와 언어 교차에 약하며, 한국어 bigram이 형태소 분석을 대체하지 못한다. SQLite와 요청 시 점수 계산은 규모가 커지면 병목이 될 수 있다.

직접 BM25를 구현하므로 수식·토큰화·정렬 검증 책임이 있다. 같은 토큰과 설정의 작은 수동 계산 예제 및 기준 구현 비교를 통해 오류를 점검한다. 단순한 구현을 선택했다는 사실을 검색 정확도나 운영 안전성의 증명으로 쓰지 않는다.

## 재검토 조건

- 1,000문서 규모 실측에서 지연시간·메모리 목표를 충족하지 못한다.
- 동시 업로드·편집·모델 인덱싱으로 SQLite 쓰기 충돌 또는 운영 제약이 확인된다.
- 밀집 검색의 개선 근거가 확보되어 벡터 인덱스의 지속적인 운영이 필요하다.
- 형태소·코드 식별자 처리에서 반복 실패가 확인되어 검증된 분석기·검색 엔진이 이점을 보인다.
- 실제 사용자의 요구와 승인을 바탕으로 공개 서비스 운영을 준비한다.

변경할 때는 이 ADR을 지우지 않고 후속 ADR에서 성능 근거, 전환 비용, 데이터·권한 이전 검증을 기록한다.

## M1 검증 조건

파일 업로드와 재시작 후 검색, 원문 근거 일치, 사용자 간 접근 차단, 수정·삭제·재처리 일관성을 테스트한다. 실제 실행한 결과를 상태 문서에 연결하고, 아직 실행하지 않은 시험을 완료 표시하지 않는다. 세부 조건은 [architecture.md](../architecture.md)와 [roadmap.md](../roadmap.md)를 따른다.
