# ADR-0002 · 사용자 서비스는 Java로 옮기고 Python 연구 코드를 보존한다

- 결정일: 2026-10-12
- 상태: 사용자 요청에 따라 전환 구조 채택. 구현·검증·로컬 전환 여부는 [STATUS](../STATUS.md) 참고
- 범위: 서비스 언어와 저장소·HTTP·연구 코드의 경계
- 이전 결정: [ADR-0001](0001-architecture.md)의 M1 기록은 유지하며, 현재 사용자 서비스 언어 선택만 이 결정으로 대체한다.

## 맥락

기존 M1 서비스는 Python/FastAPI·SQLite·TypeScript로 업로드·권한·BM25·원문 근거를 구현했다. M2 데이터와 M3 첫 오프라인 비교도 이미 별도 결과를 보존하고 있다. 사용자가 이제 서비스 개발 언어를 Java로 바꾸도록 요청했다. 이 요청을 기존 평가와 운영 검증을 지우거나 모델 품질 개선으로 표현하지 않으면서 수행해야 한다.

## 결정

1. Java 21 + Spring Boot MVC 서비스와 명시적 JDBC·SQLite를 사용한다. TypeScript 화면과 `/api` 계약을 유지한다.
2. 기존 SQLite 스키마 v1, scrypt 비밀번호·서버 세션 저장 형식, ACL·리비전·원문 근거 계약을 보존한다. 언어 전환과 DB·검색 알고리즘 변경을 한 번에 수행하지 않는다.
3. Java 기본 DB를 `var/doctrail-java.sqlite3`로 분리한다. 기존 DB를 자동으로 초기화하거나 가져오지 않는다. 실제 이전은 복사본 검사 이후 별도로 기록한다.
4. 문서 추출·청크·BM25를 Java 서비스 내부에서 수행한다. 코드포인트 오프셋·정렬과 Python 기준선의 차이를 실제 비교한다. PDF 파서 출력은 동일하다고 가정하지 않으며 기존 저장 결과를 자동 재처리하지 않는다.
5. Python 3.11·uv 연구 코드와 동결 입력·보고서는 유지한다. 기존 FastAPI 구현도 회귀 비교·되돌리기의 참조로 보존한다.
6. Java 서비스 호환 검증 후 M3 모델 연결을 이어간다. Python 추론과 Java 서비스의 구체적 연결 방식은 그 단계의 별도 결정이다.

세부 계약, 확인할 경계 사례와 전환 절차는 [JAVA-MIGRATION](../JAVA-MIGRATION.md)에 있다.

## 검토한 대안

| 대안 | 이번에 선택하지 않은 이유 |
|---|---|
| 모든 연구·실험까지 Java로 재작성 | 사용자 서비스 언어를 바꾸는 데 필요하지 않고 동결 비교의 재현 변수를 늘린다. |
| Java 앞단에서 기존 Python 서비스로 모든 요청 전달 | 계정·권한·검색 핵심을 Java로 옮겼다는 목적을 충족하기 어렵고 운영 프로세스만 늘어난다. |
| PostgreSQL·벡터 검색·생성을 함께 도입 | 언어·데이터·검색 결과가 동시에 변해 회귀 원인을 나누기 어렵다. 기존 M3 측정·권한 검증 순서를 유지한다. |
| 같은 실사용 SQLite를 두 서비스가 동시에 변경 | 복사본 검증 전에 기존 작업을 손상시킬 수 있고 어느 런타임의 동작인지 구분하기 어렵다. |

## 결과와 한계

서비스의 Java 구현과 AI 연구의 Python 구현을 각각 설명할 수 있다. 기존 계약과 결과를 보존하므로 전환 실패를 추적할 수 있다. 반면 두 언어의 의존성·테스트를 관리해야 하며 문자열·해시·파서·수치 동작의 호환 검증 비용이 생긴다.

SQLite 쓰기 동시성·동기 PDF 파싱·요청별 BM25 계산의 기존 한계는 남는다. 이 결정은 검색 품질 개선, 완전한 Unicode 수학적 동등성, 사용자 검수, M3 서비스 연결, 학습 또는 공개 배포를 입증하지 않는다. 실제 검증 범위와 실패는 상태·기여 기록에 추가한다.
