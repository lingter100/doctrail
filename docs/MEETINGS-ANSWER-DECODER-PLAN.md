# 출력 구조만 제한하는 한 번의 비교

Evidence-first v2의 원본과 별도 의미 검토를 보존한다. 한국어 날짜·로그 금지와 beta 예정 표현은 회복됐지만 공개 답변의 출시 시점 합성과 진행자 답변의 JSON·근거 오류가 남았다. 형식 문제만 고치면 의미도 옳아진다는 가정을 하지 않는다.

같은 v2 프롬프트·질문 네 개·문서 후보·4B 모델·양자화·런타임·greedy 설정·입출력 상한을 유지한다. 새 생성기에서 JSON 키·타입·순서·개수만 제한하는 고정 GBNF를 적용한다. 정답 문장·날짜·특정 근거 ID·인용 문자열을 문법에 넣지 않는다. 근거를 먼저 쓰고 주장 텍스트를 쓴다는 기존 순서는 그대로다. 문법의 실제 적용 문자열과 SHA를 출력 설정에서 검사한다.

네 답변을 각각 한 번만 실행한다. 분석0회, 재시도0회이며 이전 출력은 수선하지 않는다. 원문 인용 검증기·언어 검사·별도 의미 검토도 그대로다. 이 비교는 알려진 실패를 사용한 구조적 개발 검사이며 독립 평가가 아니다. 사용자 검수0이다.

통과 조건은 JSON 구조와 정확한 인용에 더해 네 사례 모두의 의미 지지·질문 완전성·언어다. 특히 February의 beta 예정과 June 당시 사용 가능 상태를 구별해야 한다. 진행자 답변은 실제 calendar 설명과 회의 채팅의 agenda 링크를 정확히 인용해야 한다. 한국어 복합 질문은 변경 날짜·30일→7일·원문 질문 로그 금지를 모두 포함해야 한다. 없는 예산에는 실제 모델이 보류해야 한다.

실패하면 같은 사례를 보며 추가 프롬프트 버전을 반복하지 않는다. 통과한 분석·작업·권한·수정/삭제 검증을 따로 진행할 수 있지만 자연어 RAG 완료를 주장하지 않는다. 원문 발췌로 요구사항을 바꾸거나 paid 모델 사용을 승인 없이 실행하지 않는다. 모델·서비스 설계와 필요한 검증 자료를 다시 판단한다.
