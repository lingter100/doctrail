# M4 train-only 질문 작성 지침 v1

작성일: 2026-10-12. 이 파일은 AI 작성 지침이며 사용자 검수 영수증이 아니다.

1. 배정받은 `fit` 또는 `calibration` author pack만 읽는다. M2 dev/test 질문, 해당 정답·평가 결과, 다른 partition의 질문은 열지 않는다. Pack의 모든 문서는 원래 train 계열이다.
2. 목표는 fit 64개/16계열, calibration 16개/4계열이며 한 코퍼스 계열당 최대 4개다. 목표 수량보다 독립된 질문 의도와 근거 품질을 우선한다. 본문에 충분한 사실이 없으면 부족한 수를 보고하고 멈춘다. 같은 의도의 한국어·영어 번역이나 말바꾸기를 서로 다른 학습 사례로 늘리지 않는다.
3. 실제 엔지니어가 단일 사실·조건·명령 옵션을 찾는 질문을 쓴다. 질문 자체에 정답을 넣거나 제목을 그대로 의문문으로 바꾸는 패턴은 피한다. 막연한 질문, 문서 밖의 최신 사실, 답변에 추측이 필요한 질문, 링크 대상 내용을 읽어야만 답할 수 있는 질문을 제외한다.
4. `semantic`, `exact_term`, `cross_lingual` 유형을 구분한다. Cross-lingual은 질문 언어와 주석 근거 언어가 다른 경우이며, 의미 동등한 번역본 전체를 검색했다는 뜻이 아니다. 전체 목표는 한국어 질문/영어 근거 16개 이상, 영어 질문 8개 이상이다. 개별 pack에 배정한 수를 따르고 수량을 맞추려고 사실을 지어내지 않는다.
5. 한 질문에 한 필수 사실만 요청한다. 원문 전체 문맥을 확인하고 이를 직접 지지하는 연속된 짧은 구절을 정확히 복사한다. 다중 문서 결합 질문은 이번 pilot 범위 밖이다. 여러 `evidence`를 쓰면 같은 사실을 독립적으로 지지하는 대안 OR이며, 번역이라는 이유만으로 양성을 추가하지 않는다.
6. `quote`는 정제 본문의 실제 문자열이어야 한다. 공백·줄바꿈·Unicode를 바꾸지 않는다. `occurrence`는 0부터 세는 동일 구절의 등장 순서다. Compiler가 정확한 문자 위치와 포함 청크를 계산한다. 구절이 기존 청크 하나에 온전히 들어가지 않으면 독립적으로 충분한 다른 구절을 찾거나 부족 사유를 남긴다. 정답에 유리하게 기존 청크를 바꾸지 않는다.
7. 출력은 UTF-8 JSONL 한 줄에 한 질문이다. 필드는 `id`, `partition`, `question`, `language`, `query_type`, `question_family_id`, `evidence`, `expected_answer`, `rationale`, `author_pack_sha256`, `provenance`, `semantic_review`다. `id`는 `m4-fit-001` 또는 `m4-cal-001` 형식이다. `question_family_id`는 질문의 독립 의도 식별자이며 코퍼스의 `family_id`와 다르다. 번역·말바꾸기는 동일한 question family를 사용한다.
8. `evidence` 각 항목은 `document_id`, `quote`, `occurrence`를 갖는다. `expected_answer`는 인용한 근거로만 작성한 짧은 참고 답안이다. `rationale`에는 질문의 구체성과 근거가 요청 사실을 충분히 지지하는 이유를 기록한다. 참고 답안은 서비스의 생성 답변·확정 정답이 아니다.
9. `provenance`는 `authorship: ai_authored`, `source_kind: public_real`, 실제 도구 수락 값인 `author_model`, `author_reasoning`, `human_review: pending`을 기록한다. 이 작업의 수락된 작성 모델은 gpt-6-astra / xhigh다. 사람이 확인한 것처럼 표시하지 않는다. `semantic_review.status`는 작성자가 `pending`으로 남긴다. 별도 AI 검토가 정확한 문맥을 대조한 후에만 `ai_checked`로 기록하며 사용자 검수로 바꾸지 않는다.
10. 음성 예시는 작성하지 않는다. BM25가 돌려준 미주석 후보는 아직 `unknown`이다. 이후 별도 검토에서 질문·양성 근거·음성 후보 전체 청크를 함께 읽고 요청한 사실을 지지하지 않는 구체적 이유를 남겨야 한다. 같은 계열·양성 겹침·정확/유사 중복·모호한 후보를 학습 음성으로 쓰지 않는다.
11. Author pack의 SHA-256을 모든 행에 기록한다. 생성 영수증에는 본 지침·pack·draft의 실제 SHA-256, 작업 역할, 수락된 모델 설정을 기록한다. 개인 절대 경로나 모델 가중치·전체 캐시 본문은 Git에 추가하지 않는다. 저장 초안의 재컴파일은 재현 가능하지만 AI 생성 호출 자체의 재현을 주장하지 않는다.

검토는 질문의 답변 가능성, 원문 일치, 독립된 의도, 요구 사실의 범위, 언어, 출처, split을 확인한다. 자동 검사가 통과해도 의미 라벨의 정확성을 증명하지 않는다. 부족한 수·부적격 사유와 미검수 상태를 그대로 보고한다.
